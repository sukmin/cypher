1. 전체 구성

Cypher는 실행 파일 두 개입니다. 창을 띄우는 cypher.exe와, Claude Code가 불러 주는 작은 심부름꾼 cypher-bridge.exe(전달 프로그램)입니다. 전달 프로그램은 claude.exe라는 이름의 사본으로 불리면 끼움 프로그램으로 동작합니다(4절).

  • 화면은 빌드 단계 없는 자바스크립트입니다. 사이드바의 항목과 워크스페이스를 알고 있는 것은 화면뿐입니다.
  • 본체는 화면이 못 하는 일(프로세스 띄우기, 파일, 네트워크)을 합니다. 워크스페이스에 관한 판단이 필요하면 화면에 물어봅니다.
  • 웹 페이지를 보여 주는 사이트 항목의 웹뷰에는 앱 명령 권한을 주지 않습니다. 본창의 화면에는 보안 정책(CSP)이 걸려 있어 화면 코드가 바깥과 통신하지 못합니다.
  • 크레이트는 넷입니다: cypher-core(화면·창과 무관한 로직: 링크·설정·프로필·.http 형식·글자 파일·창 자석 계산), cypher-pty(ConPTY 세션), cypher-bridge(전달 프로그램), cypher-app(Tauri 앱).

2. 사이드바: 워크스페이스와 항목

사이드바에 놓이는 것을 항목이라 부릅니다. 터미널 세션(Claude, PowerShell 등 프로필)과 그 밖의 열한 가지 종류(메모, HTTP, 사이트, 이미지, 마인드맵, ERD, 문서, 할 일, 명령, 표, 코드)가 있습니다. 0.13부터 모든 세션과 항목은 이름 붙인 워크스페이스 안에만 놓입니다(업무 하나가 워크스페이스 하나).

  • 새 종류의 항목은 이름·아이콘과 화면을 만드는 함수(create(item, host, saved, onChange) → { ready, focus, title, state, close, dispose })를 ui/main.js의 KINDS에 올리면 사이드바·분할·워크스페이스·복원에 그대로 들어갑니다.
  • 항목은 아무것도 묻지 않고 만들어집니다. 볼 파일이나 실행할 명령이 필요한 종류(문서·명령·표)는 빈 영역으로 뜨고, 거기서 파일을 끌어다 놓거나 고르거나 경로를 적어 대상을 정합니다(ui/empty.js).
  • 워크스페이스를 정할 수 없으면 만들지 않습니다(groupFor): 주어진 워크스페이스 → 지금 보는 항목의 워크스페이스 → 워크스페이스가 하나뿐이면 그것. 그 밖에는 알림만 띄웁니다.
  • 워크스페이스 폴더(cypher.groupFolders)는 그 워크스페이스에서 여는 세션의 시작 폴더입니다. 정하지 않았으면 그 워크스페이스에 이미 있는 항목의 폴더, 그것도 없으면 사용자 폴더를 씁니다.
  • 워크스페이스의 순서 0.17부터: 사이드바에는 만든 차례(cypher.groups의 차례)대로 보입니다. 워크스페이스의 머리를 끌어 다른 워크스페이스의 위·아래에 놓으면 그 목록에서의 자리를 옮깁니다(moveGroup). 놓을 자리는 머리부터 그 워크스페이스의 마지막 줄까지를 한 덩이로 보고 위쪽 절반이면 앞, 아래쪽 절반이면 뒤입니다(groupUnder). 항목을 끄는 것과 같은 마우스 처리를 함께 씁니다(파일 끌어다 놓기와 겹치지 않게 브라우저의 끌어다 놓기는 쓰지 않음).
  • 스테이지 표시줄(renderWhere): 지금 보는 항목의 워크스페이스 › 이름 · 폴더를 스테이지 맨 위에 적습니다. 터미널 세션을 보고 있을 때는 워크스페이스 이름을 크게 적고 0.17부터, 나란히 볼 때는 창마다 제목 줄에 그 세션의 워크스페이스 이름을 붙입니다(여러 워크스페이스의 세션을 오가다 엉뚱한 세션에 입력하지 않게).
  • 북마크는 항목에 붙이는 숫자(0~9) 하나입니다. 숫자 하나에 항목 하나이고, 항목의 기록(mark)에 함께 저장됩니다.
  • 코드 안의 이름(group, createGroup, 저장 키 cypher.groups)은 "그룹"이던 때의 것을 그대로 씁니다(저장된 자료를 옮기지 않으려는 것).

3. Claude 세션과 이야기하는 길

Cypher는 Claude 세션을 띄울 때 claude --mcp-config <파일> --settings <파일>로 설정을 끼워 넣습니다(도구 연결인 --mcp-config는 설정에서 [browser] enabled = false로 끄면 붙이지 않습니다). 사용자의 settings.json은 건드리지 않습니다. 그 설정이 전달 프로그램을 세 가지 자리에 걸어 둡니다.

  • 통로에 접속하면 첫 줄에 확인값(실행할 때마다 운영체제의 난수로 새로 만드는 128비트 값), 둘째 줄에 세션 번호(도구 연결은 mcp <세션 번호>)를 적습니다. 전달 프로그램은 이 값들을 환경 변수(CYPHER_PORT, CYPHER_TOKEN, CYPHER_SESSION)로 받습니다.
  • 전달 프로그램은 신호를 보낸 뒤 본체가 처리를 마치고 연결을 닫을 때까지(길어야 1.5초) 기다립니다. 그래서 "쓰기 직전" 신호는 Claude가 실제로 파일을 쓰기 전에 처리됩니다(본체가 1.5초 안에 처리하는 보통의 경우).
  • 훅: 늘 거는 것은 요청 시작(UserPromptSubmit), 응답 완료(Stop), 입력·승인 대기(Notification), 서브에이전트 시작·종료(SubagentStart·SubagentStop), Claude Code 종료(SessionEnd)입니다. 도구 훅(PreToolUse·PostToolUse)은 설정에 따라 다릅니다: [session] activity가 켜져 있으면 모든 도구에 걸고 실패 신호(PostToolUseFailure)도 받으며, 꺼져 있고 show_created만 켜져 있으면 파일을 쓰는 도구에만 겁니다(Write의 직전과 Write·Edit·MultiEdit의 직후). 둘 다 꺼져 있으면 걸지 않습니다.
  • 본체는 도구 신호를 화면에 그대로 넘기지 않습니다. 도구 이름과 짧은 설명만 뽑아 session-tool 이벤트로 알리고(9절), Write 도구의 신호에서는 새로 만든 파일을 가려 session-file로, 있던 파일을 고쳐 쓴 것(Write·Edit)은 session-edit로 알립니다(8절). 상태줄은 session-status, 그 밖의 훅은 session-hook입니다.
  • 도구는 26개입니다: 브라우저 13개(browser_*), HTTP 2개(http_list·http_run), 항목 11개(cypher_items, memo_write, mindmap_write, erd_write, todo_write, todo_check, run_output, image_add, doc_show, table_show, notify_user).
  • 워크스페이스를 알아야 하는 도구는 본체가 화면에 물어서(mcp-request 이벤트) 답을 받습니다(20초 안에). 화면이 그 시각을 넘겨 받은 요청은 실행하지 않습니다(Claude가 다시 시도한 것과 겹치지 않게).
  • 상태줄 자리는 하나뿐이라, 사용자가 원래 쓰던 상태줄(HUD)이 있으면 전달 프로그램이 정보를 넘긴 뒤 그 명령을 이어서 실행해 출력을 그대로 내보냅니다(CYPHER_STATUSLINE).
  • 설정 → "Claude 실행 명령…"에 적어 둔 명령이 있으면 claude 대신 그 명령으로 띄우고, 위 인자는 그 뒤에 붙입니다.

4. 셸에서 띄운 Claude에 붙기 0.12부터

PowerShell 같은 셸 세션에서 사용자가 직접 친 claude에도 Cypher가 붙습니다. 셸 세션의 PATH 맨 앞에 claude.exe라는 이름의 작은 끼움 프로그램을 두는 방식입니다.

  • 끼움 프로그램은 본체가 시작할 때 전달 프로그램을 %LOCALAPPDATA%\cypher\shim\claude.exe로 복사해 만듭니다. 전달 프로그램이 바뀌었으면(새 버전) 사본도 바꿉니다.
  • 끼움 프로그램은 진짜 claude(claude.exe·.cmd·.bat)를 PATH에서 자기 폴더를 건너뛰고 찾습니다. 그 Claude Code가 다시 띄우는 claude는 끼움 프로그램을 거치지 않게, 자식의 PATH에서 자기 폴더를 빼고 붙일 파일의 경로도 넘기지 않습니다(같은 세션 번호로 신호가 겹치지 않게).
  • 그 Claude가 끝나면 SessionEnd 훅이 와서 그 줄의 모델·상태 표시를 지우고 평범한 셸로 돌아갑니다(/clear·/resume으로 온 것은 끝난 것으로 치지 않음). 다시 시작한 뒤에는 셸만 되살립니다.
  • 설정의 [session] claude_in_shell = false로 끕니다. 끄면 셸 세션에는 통로의 값도 넣지 않고 PATH도 건드리지 않습니다.

5. 누가 보냈는지 확인하기

통로로 오는 신호에 적힌 세션 번호는 보낸 쪽이 스스로 적은 값입니다. 확인값은 Cypher가 띄운 모든 세션의 프로세스가 알고 있으니, 번호만 믿으면 한 세션이 다른 세션인 척할 수 있습니다. 그래서 Cypher는 번호를 믿지 않고 접속한 프로세스가 누구의 자손인지를 직접 봅니다.

  • 순서: 확인값이 맞는지 본다 → 접속한 프로세스를 찾는다 → 조상을 따라 올라간다 → 적힌 번호와 같은 세션인지 본다.
  • 부모가 이미 끝났거나 번호가 다른 프로세스에 다시 쓰인 경우는 "만든 시각"을 비교해 걸러 냅니다(부모는 자식보다 먼저 만들어졌어야 합니다).
  • 셸 세션에서 띄운 Claude(4절)는 그 셸의 자손이므로 그 셸 세션의 번호로 받아들여집니다.

6. 다룰 수 있는 범위

Claude 세션이 Cypher 도구로 다룰 수 있는 것은 자기와 같은 워크스페이스에 있는 항목뿐입니다. 규칙은 한 줄짜리 판정(canControl)에 모여 있습니다: 둘이 같은 워크스페이스에 있고, 대상이 자기 자신이나 터미널 세션이 아닐 것.

상황결과
같은 워크스페이스의 메모·마인드맵·ERD·할 일·사이트·HTTP·문서·표·이미지다룰 수 있음(만들기, 고치기, 놓기, 조작)
같은 워크스페이스의 명령 항목상태와 출력 읽기만(run_output). 만들기·실행·멈춤은 사용자만
다른 워크스페이스의 항목거절. 목록에도 나오지 않음
다른 세션(Claude든 PowerShell이든)거절. 다루는 도구 자체가 없음(같은 워크스페이스의 세션은 목록에 이름·폴더·상태만 보임)
항목이나 세션을 다른 워크스페이스로 옮김그 순간부터 옛 워크스페이스는 거절, 새 워크스페이스는 허용(판정을 매번 새로 함)
부른 세션을 알 수 없는 요청거절

HTTP 도구는 폴더 기준입니다: 같은 워크스페이스 HTTP 항목의 요청 폴더와 그 세션을 시작한 폴더의 요청 파일(폴더 바로 아래, http, .cypher\http)에만 씁니다.

명령 항목이 돌리는 프로그램은 세션과 같은 가상 터미널에서 돌지만, 통로의 값(CYPHER_*)과 끼움 프로그램은 넣지 않습니다. 그래서 명령 항목으로 돌린 프로그램은 Cypher 도구에 붙지 못합니다.

판정에는 "워크스페이스에 들지 않은 세션은 새 항목 놓기와 알림만 된다"는 갈래가 남아 있지만, 0.13부터 모든 세션이 워크스페이스 안에 있으므로(옛 것은 root로 모임) 실제로는 생기지 않습니다.

사용자가 직접 하는 일(변경 내용에서 고른 줄을 세션에 넣기, 이미지 경로를 세션에 넣기, 할 일을 세션에 넣기)은 이 제한과 무관합니다. 제한은 "Claude가 도구로 하는 일"에만 겁니다.

7. 워크스페이스마다 다른 브라우저

조작할 수 있는 탭만 나누면 로그인 상태가 샙니다(A 워크스페이스에서 로그인한 사이트에 B 워크스페이스의 Claude가 자기 브라우저로 가면 로그인돼 있음). 그래서 브라우저 프로필(쿠키·저장소가 담기는 폴더)을 워크스페이스마다 따로 씁니다.

  • 어느 워크스페이스가 어느 프로필 번호를 쓰는지는 화면이 기억합니다(cypher.profiles). 번호는 그 워크스페이스에서 브라우저를 처음 띄울 때 만듭니다. 워크스페이스 이름을 바꿔도 번호는 그대로라 로그인 상태가 유지됩니다.
  • 이미 있는 워크스페이스에 합치면 합쳐진 쪽 항목은 그 워크스페이스의 프로필을 씁니다.
  • 워크스페이스를 없앴다가 같은 이름으로 다시 만들면 예전 프로필을 다시 씁니다.
  • 프로필마다 브라우저 엔진 프로세스가 따로 뜹니다(사이트 항목을 실제로 띄운 워크스페이스만).
  • 어느 항목이 어느 프로필을 써야 하는지는 화면이 정해 본체에 알립니다. Claude의 도구 호출이 그와 다른 프로필을 들고 오거나(도구가 도는 사이에 항목이 옮겨짐) 그사이 항목이 닫혔으면 본체는 웹뷰를 만들지 않고 거절합니다.
  • 사이트 웹뷰가 여는 것은 웹 주소(http, https)와 이 컴퓨터의 HTML 파일(.html, .htm)뿐입니다. 다른 로컬 파일과 네트워크 경로의 파일(file://서버/…)은 열지 않습니다. Claude의 browser_navigate도 같은 규칙을 따릅니다.
  • 사이트 웹뷰는 본창에 붙인 별도의 웹뷰를 그 항목의 창 자리에 겹쳐 놓은 것입니다(많은 사이트가 iframe을 막아 두었기 때문). 조작은 디버깅 포트를 열지 않고 WebView2의 개발자 도구 프로토콜을 앱 안에서 직접 부릅니다.
  • 워크스페이스를 없애도 프로필 폴더는 지우지 않습니다. 지우려면 Cypher를 끄고 site-profiles(chrome 엔진은 chrome-profiles) 아래의 폴더를 지웁니다. 폴더 이름은 번호라 어느 워크스페이스의 것인지 드러나지 않으니, 가리기 어렵다면 모두 지우고 워크스페이스마다 다시 로그인합니다.

8. 만든 파일을 사이드바에 놓기

Claude가 Write 도구로 새 파일을 만들면 종류에 맞는 항목으로 그 세션의 워크스페이스에 놓고 알림으로 알려 줍니다. 보던 화면은 바꾸지 않습니다. "새 파일인지"는 쓰기 직전에 그 파일이 없었는지로 가립니다.

  • 최종 파일만 놓기 0.17부터: ④에서 바로 놓지 않고 그 세션에 적어 두었다가(heldFiles) 그 요청의 응답이 끝났을 때(완료 신호, 중단된 요청의 정리, 세션 종료) 한꺼번에 놓습니다(placeHeld). 놓기 전에 앱이 최종 파일을 가려 줍니다(created_final): 지금은 없는 파일(만들었다가 지웠거나 옮겼다)과 빈 파일, 이름으로 보아 잠깐 쓰는 파일(tmp·temp·scratch·임시로 시작하거나 _tmp·.bak·-old·-wip 등으로 끝나는 이름 — 낱말의 일부인 temperature·template은 아님), 같은 요청에서 만든 문서·HTML 안에 이름이 적힌 그림(그 문서의 부품)은 놓지 않습니다. 아직 빈 파일은 버리지 않고 다음 응답이 끝날 때 다시 봅니다(빈 파일로 만들어 두고 다음 요청에서 채우는 경우. 다섯 번까지). 요청 중이 아닐 때 온 파일은 4초 동안 더 오지 않으면 놓고, 응답 도중에 닫은 세션의 파일은 놓지 않습니다.
  • HTML 파일은 그 파일을 여는 사이트 항목이 됩니다. 웹뷰는 사용자가 그 항목을 처음 볼 때 뜹니다. .json은 설정 파일인 경우가 많아 놓지 않습니다(table_show로 놓을 수 있음).
  • 요청 파일(.http)은 그 폴더를 보는 HTTP 항목이 이미 있으면 새로 만들지 않고 그 항목의 파일 목록을 다시 읽게 합니다.
  • 한 세션에서 같은 파일은 한 번만 놓고, 그 워크스페이스의 문서·표·메모·HTTP·사이트 항목이 이미 보여 주는 파일은 놓지 않습니다. 한 요청에 8개까지 놓고, 넘치면 한 번 알립니다.
  • 숨김 폴더·빌드 폴더(.git, node_modules, target 등)인지를 볼 때, 세션이 일하는 폴더 안의 파일은 그 폴더 아래 부분만 보고(프로젝트 자체가 D:\build 같은 곳에 있어도 놓임) 밖의 파일은 경로 전체를 봅니다. 요청 파일 자리인 .cypher\http는 예외로 놓습니다.
  • 임시 폴더와 Claude·Cypher의 설정·데이터 폴더, 네트워크 경로에 만든 파일은 놓지 않습니다.

고쳐 쓴 파일은 보여 주던 항목이 새로 읽는다

있던 파일을 고친 것(Edit·MultiEdit 도구의 직후 신호, 새 파일이 아닌 Write의 직후 신호)은 항목을 놓지 않고 session-edit 이벤트로 화면에 알립니다. 화면(onEditedFile)은 그 세션과 같은 워크스페이스(워크스페이스가 없으면 같은 폴더 묶음)에서 그 파일을 보여 주는 항목을 찾아 바로 새로 읽게 합니다. 다른 워크스페이스의 항목은 같은 파일을 보고 있어도 건드리지 않습니다.

  • 도구 신호로 아는 것이라 명령(Bash 등)으로 고친 파일은 알 수 없습니다. 문서·표는 스스로 살피므로 그래도 반영되고, 사이트는 ⟳로 다시 읽습니다.

10. 터미널 화면 맞추기 0.16부터

세션의 출력은 프로그램 → Windows의 가상 터미널(conhost) → 화면(xterm.js) 순으로 옵니다. conhost는 자기 화면을 따로 갖고 있다가 바뀐 칸만 다시 보내는데, 이때 줄바꿈과 커서 이동을 생략합니다. 그래서 둘이 글자의 칸 수를 다르게 세면 줄이 밀려 화면이 어긋납니다.

  • 칸 수 표(ui/widths.js): xterm.js의 기본 표(유니코드 11)와 conhost가 다르게 세는 글자(변형 선택자가 붙은 이모지 ✔️·⚠️, 유니코드 12 이후의 이모지, 국기, 결합 글자)를 conhost 쪽에 맞춥니다. 화면을 실제로 배치하는 쪽이 conhost이기 때문입니다.
  • 이 표는 세션이 Windows에 내장된 conhost(실제로 재어 본 빌드 27000 미만)에 붙을 때만 씁니다. 빌드가 그 이상이거나 실행 파일 옆에 따로 둔 conpty.dll을 쓰면 유니코드 11 표를 그대로 두고, 아래의 자동 다시 맞추기도 돌지 않습니다(오른쪽 클릭 메뉴로 직접 하는 것은 됩니다). 어느 쪽인지는 본체가 시작할 때 알려 줍니다(Windows 빌드 번호와 conpty.dll이 있는지).
  • xterm.js에는 Windows 가상 터미널에 붙는다는 것도 알려 줍니다(windowsPty). 줄 수가 늘 때 지난 출력을 화면으로 끌어내리지 않고 아래에 빈 줄을 더하게 해서, conhost가 다시 그린 화면과 어긋나지 않게 합니다.
  • 다시 맞추기(realign): Claude Code와 conhost가 다르게 세는 글자가 찍혔으면 그 세션에 표시해 두었다가, 응답이 끝났을 때(Stop) 터미널을 한 줄 줄였다가 0.45초 뒤 되돌립니다. 크기가 바뀌면 프로그램이 화면을 처음부터 다시 그리고, 다시 그리지 않는 프로그램이라도 conhost가 자기 화면을 통째로 다시 보냅니다.
  • 지난 출력을 올려 보는 중이면 건드리지 않습니다(보던 자리를 잃지 않게). 사용자는 세션 오른쪽 클릭 → "화면 다시 맞추기"로 직접 할 수 있습니다.
  • 아래 빈 공간 메우기(closeGap): Claude Code는 화면 아래쪽의 움직이는 부분(승인 창, 메뉴, 진행 목록)이 길어지면 그만큼 지난 출력을 위로 밀어 올리고, 그 부분이 접히면 줄들을 지우기만 합니다. 터미널은 위로 올라간 줄을 도로 끌어내릴 수 없으므로 입력창 아래가 다음 출력이 채울 때까지 빈 채로 남습니다. 그때 화면이 맨 아래를 따라가지 않고 있었으면(조금이라도 올려 본 뒤) 입력창은 바닥에 보이는데 스크롤은 빈 줄만큼 더 내려갑니다. Claude Code는 터미널의 줄 수가 줄면 화면을 맨 위부터 대화의 끝부분으로 다시 채워 그리므로, 같은 방법(다시 맞추기)으로 메웁니다.
    • 살피는 때: 응답 완료(Stop), 출력이 조용해졌을 때, 중단된 요청을 정리했을 때, 스크롤이 움직였을 때. 0.8초 뒤에 한 번 살핍니다.
    • 메우는 조건: 돌고 있는 Claude 세션이고, 일하는 중·승인 대기 중이 아니고, 출력이 조용하고, 보통 화면(대체 화면이 아님)에 지난 출력이 있고, 글자를 골라 두지 않았고, 커서가 있는 줄이 보이고, 커서와 마지막 글자 아래의 빈 줄이 10줄 이상이면서 화면 줄 수의 1/5 이상일 때.
    • 메워지지 않는 빈 공간(대화를 비운 직후처럼 대화가 한 화면보다 짧을 때)은 한 번만 해 보고, 빈 공간이 더 커지거나 그 뒤의 출력이 화면의 줄을 위로 더 밀어 올리기 전에는 다시 하지 않습니다(gapStuck: 빈 줄 수와 커서 줄의 마커).
    • 다시 맞추느라 나온 출력으로는 사이드바의 "새 출력" 표시를 켜지 않습니다.
  • 프롬프트 편집기의 높이를 바꿀 때(settleResize) 0.17부터: 편집기의 위쪽 테두리를 끄는 동안에는 터미널의 줄 수를 그대로 둡니다(fitHeld). 끄는 내내 따라 바꾸면 Claude Code가 그때마다 화면을 다시 그려 지난 출력에 같은 줄이 겹쳐 쌓이기 때문입니다. 끌던 손이 0.22초 멈추면(그리고 놓으면) 한 번에 새 크기로 맞춥니다.
    • 줄 수만 줄었으면 Claude Code가 스스로 다시 그리므로 그 뒤의 정리(겹친 줄 지우기, 보던 자리 지키기)만 합니다.
    • 줄 수가 늘었으면 새 크기를 알리고 0.3초 뒤에 다시 맞춥니다(한 줄 줄였다 되돌리기). 바로 이어서 줄이면 프로그램은 두 번의 변경을 "조금 늘어난 것" 한 번으로 보고 다시 그리지 않아, 늘어난 만큼 아래가 빈 채로 남습니다.
    • 앞선 다시 맞추기가 끝나지 않았으면 끝난 뒤에 합니다(겹치면 어느 줄이 겹친 줄인지 가려낼 수 없음). 그사이 높이가 또 바뀌었어도 다시 맞추던 것은 원래 줄 수로만 되돌리고, 새 높이는 그 뒤에 맞춥니다. 접기·펴기와 두 번 눌러 기본 높이로 돌릴 때도 같은 길을 탑니다(resizeComposer).
    • 겹친 줄을 지울 때, 다시 그린 쪽에만 몇 줄(6줄까지)이 더 있는 경우도 받아 줍니다: 프로그램은 줄 수가 줄 때마다 화면의 끝부분만 다시 그려서 그때 화면 맨 위의 줄이 지난 출력에서 빠지는데, 나중에 넓어져 다시 그리면 그 줄이 되살아나 위아래 덩이가 글자까지 똑같지는 않게 됩니다. 맞은 줄이 세 줄 이상이고 글자가 있는 줄이 있을 때만 지웁니다.
  • 겹친 줄 지우기(dropRepeated): 다시 맞추면 내용이 아래로 내려오면서, 이미 위로 올라가 있던 줄이 화면 위쪽에 한 번 더 그려집니다. 다시 맞추기 전에 화면의 윗줄 세 개와 맨 윗줄의 자리(xterm.js 마커), 아래 빈 줄 수를 적어 두고, 프로그램이 다 그린 뒤(줄 수를 되돌리고 0.5초 뒤부터 0.3초 조용할 때까지, 길어도 3초) 그 윗줄이 마커 자리에서 몇 줄 아래로 내려와 있는지로 겹친 줄 수를 구합니다(빈 공간이 줄어든 만큼을 먼저 보고, 아니면 가까운 데부터 찾습니다). 겹친 두 덩이는 다시 그릴 때 화면이 시작되던 줄을 사이에 두고 붙어 있으므로, 그 줄 수만큼의 위아래 덩이가 글자까지 똑같은 곳을 찾아 위쪽(지난 출력 쪽)을 지우고, 없으면 지우지 않습니다. 자리를 마커로 잡으므로 다시 그리는 사이에 새 출력이 와도 맞습니다. Claude가 도는 세션에서만 하고(셸은 화면을 다시 채워 그리지 않습니다), 글자를 골라 둔 동안에는 하지 않습니다. xterm.js에는 지난 출력의 가운데 줄을 지우는 공개 기능이 없어 안쪽 버퍼(_core.buffers.normal)를 직접 고칩니다 — xterm.js를 바꿀 때 다시 확인할 곳입니다. 내용의 끝을 보고 있었으면 끝난 뒤 맨 아래를 보게 합니다(기다리는 사이에 사용자가 스크롤을 움직였으면 그대로 둡니다).

11. 다시 시작과 쉬는 세션 0.12부터

화면은 열린 항목과 분할 모양을 바뀔 때마다 cypher.state에 적어 둡니다. 다시 시작하면 그 기록으로 되살립니다.

  • 터미널 세션은 바로 띄우지 않습니다. 사이드바에 "쉬는 중"으로만 되살려 두고(프로세스 없음), 사용자가 누른 세션만 띄웁니다(wake). 워크스페이스 머리의 ▶는 그 워크스페이스의 쉬는 세션을 한꺼번에 띄웁니다. 설정의 [session] restore_on_click = false이면 예전처럼 모두 바로 띄웁니다.
  • Claude 세션은 하던 대화의 번호를 적어 두었다가 --resume <번호>로 이어 엽니다. 셸에서 띄운 Claude의 대화는 잇지 않습니다(셸만 되살림).

  • 명령 항목은 명령만 되살리고 스스로 실행하지 않습니다.
  • 창을 닫을 때는 본체가 닫기 요청을 한 번 미루고, 화면이 쓰던 것을 저장했다고 알려 오면(길어야 3초) 닫습니다.
  • 닫은 항목은 같은 기록 모양으로 30일 동안, 30개까지 기억해(cypher.closed) 다시 열 수 있습니다. 메모·마인드맵·ERD·할 일·이미지의 내용은 저장 폴더의 closed에 보관합니다.

12. 업데이트 0.16부터

Cypher는 설치 프로그램 없이 실행 파일 두 개로 배포됩니다. 업데이트는 GitHub 릴리즈의 묶음(zip)을 받아 실행 파일이 있는 폴더의 파일을 바꾸는 것입니다. 사용자가 도움말 → "Cypher 업데이트…"에서 단추를 눌렀을 때만 돌고, Cypher가 스스로 확인하러 나가지 않습니다. 저장소와 릴리즈가 공개라서 로그인이나 토큰이 필요 없고, 보내는 정보도 없습니다.

① 업데이트 확인

  • https://api.github.com/repos/sukmin/cypher/releases/latest를 읽습니다(연결 10초, 전체 15초 안에).
  • 릴리즈의 태그(v0.16.0)에서 v를 떼고 점으로 나눈 숫자들을 지금 버전과 숫자로 견줍니다(0.100.0 > 0.99.9). 태그가 숫자와 점만으로 된 버전이 아니면(0.16.0-beta 등) 확인이 "릴리즈의 버전을 읽지 못했습니다"라는 오류로 끝나고, 설치 단추는 나오지 않습니다.
  • 묶음은 릴리즈의 자산 가운데 이름이 -windows-x64.zip으로 끝나고, 주소가 https://github.com/sukmin/cypher/releases/download/로 시작하는 것만 받습니다. 이름에 경로(/, \, ..)가 섞여 있으면 받지 않습니다. 확인값은 GitHub가 자산마다 붙여 주는 digest(sha256:…)에서 읽습니다.
  • 새 버전이 있어도 다음 경우에는 설치 단추를 내놓지 않고 까닭과 릴리즈 페이지를 안내합니다: 개발용 빌드, Windows 64비트 묶음이 없음, 확인값이 없음, 크기가 0이거나 300MB를 넘음, 실행 파일이 있는 폴더에 쓸 수 없음(Program Files 등 — 그 폴더에 시험 파일을 만들어 봄).

② ~ ④ 내려받아 설치

  • 설치를 누르면 본체는 최신 릴리즈를 다시 읽습니다. 받을 주소를 화면에서 넘겨받지 않고, 새 버전인지와 설치할 수 있는지도 다시 확인합니다.
  • 묶음을 %LOCALAPPDATA%\cypher\update에 받으면서 SHA-256을 구합니다. 받은 크기가 릴리즈에 적힌 크기와 다르거나 확인값이 다르면 설치하지 않습니다.
  • 풀 때는 Windows에 든 tar(%SystemRoot%\System32\tar.exe)를 씁니다(PATH의 다른 tar는 zip을 풀지 못함). tar에는 전체 경로를 주지 않고 내려받은 폴더에서 띄워 상대 경로만 줍니다(tar는 인자를 시스템 코드 페이지로 읽어서, 사용자 폴더 이름에 그 코드 페이지에 없는 글자가 있으면 전체 경로로는 폴더를 찾지 못함). 푼 곳에서 cypher.exe와 cypher-bridge.exe가 함께 든 폴더(푼 폴더 자체, 또는 그 안의 폴더 하나)를 찾고, 없으면 설치하지 않습니다.
  • 그 폴더의 파일을 하나씩 실행 파일이 있는 폴더에 놓습니다. 같은 이름의 파일이 이미 있으면 <이름>.old-<시각>으로 이름을 바꿔 두고 새 파일을 복사합니다. 도중에 하나라도 실패하면 놓은 것을 치우고 옛 파일의 이름을 되돌립니다(반쯤 바뀐 상태로 남지 않게).
  • 놓는 것은 그 폴더 바로 아래의 파일들입니다(실행 파일 둘과 묶음에 함께 든 README 등). 하위 폴더는 놓지 않고, 새 버전에서 없어진 파일을 지우지도 않습니다.
  • 내려받기의 시간 제한은 연결 10초, 전체 300초입니다. 받는 곳은 그 안의 프로세스별 폴더(update\<프로세스 번호>)라서, 다른 Cypher 창이 떠도 받고 있는 묶음을 건드리지 않습니다. 도중에 실패하면 그 폴더에 받다 만 것이 남는데, 같은 창에서 다음 설치를 시작할 때 지우고, 그러지 못한 것은 한 시간이 지난 뒤 Cypher를 켤 때 지웁니다.
  • 끝나면 내려받은 것을 지우고 cypher.log에 "업데이트: 0.15.0 → 0.16.0 설치"처럼 남깁니다. 이때까지 돌고 있는 것은 옛 버전입니다.
  • 설치는 한 번에 하나만 합니다. 설치하는 중에 창을 닫았다 다시 열어 또 눌러도 겹쳐 돌지 않고, 이번 실행에서 이미 설치한 버전은 다시 설치하지 않습니다.
  • 설치는 창 스레드가 아닌 곳에서 돌고(spawn_blocking), 어디까지 왔는지를 update-progress로 화면에 알립니다: check(릴리즈 확인) → download(받은 바이트와 전체 바이트, 1%가 바뀔 때마다) → unpack(확인값 견주기·풀기) → replace(파일 바꾸기). 화면은 진행 막대와 "설치가 끝날 때까지 Cypher를 끄지 말고 기다려 주세요"라는 안내를 보여 줍니다. 그동안 세션은 그대로 쓸 수 있고, 업데이트 창을 닫아도 설치는 계속되며 다시 열면 이어서 보여 줍니다.

⑤ ~ ⑥ 다시 시작

  • "지금 다시 시작"을 누르면 화면이 "새 버전으로 다시 시작하는 중입니다"라는 안내 창으로 창을 덮고 쓰던 것을 저장한 뒤, 본체가 실행 파일 폴더의 새 cypher.exe를 띄웁니다. 본창의 저장소를 환경 변수(WEBVIEW2_USER_DATA_FOLDER)로 돌려 띄운 경우에는 그 값을 새 프로세스에도 넘깁니다. 누르지 않아도, 다음에 Cypher를 켜면 새 버전으로 뜹니다.
  • 새 실행 파일을 띄우는 일은 창 스레드가 아닌 곳에서 합니다. 새 실행 파일을 처음 띄울 때는 Windows(백신)가 그 파일을 검사하느라 띄우는 일 자체가 수십 초 걸릴 수 있는데, 창 스레드에서 하면 그동안 창이 답하지 않고 하얗게 됩니다(0.16.3까지 그랬습니다).
  • 앞선 창은 새 프로세스의 창이 화면에 보일 때까지(60초까지) 안내를 띄운 채 기다렸다가 닫힙니다. 새 프로세스가 창을 띄우지 못하고 끝나면 오류를 알리고 이 창을 계속 씁니다.
  • 새 창은 뜨자마자 저장된 창 위치·크기와 배치(cypher.state)를 읽는데, 앞선 창은 그 뒤에야 닫힙니다. 그래서 새 것을 띄우기 직전에 창 위치·크기를 먼저 저장하고, 새 프로세스가 만들어진 직후(restart-spawned)에 화면이 배치를 한 번 더 적습니다(새 실행 파일을 띄우는 데 오래 걸린 사이의 변화를 담으려는 것). 그 뒤로 앞선 창은 배치를 적지 않습니다.
  • 새 프로세스에는 환경 변수 CYPHER_RESTARTED를 넘깁니다. 그렇게 뜬 Cypher는 본창을 숨긴 채 만들고(창 위치를 되살리는 쪽도 창을 보여 주지 않게 함), 화면이 테마까지 입힌 뒤 app_ready로 알려 오면 보여 줍니다. 창이 먼저 뜨면 화면이 그려질 때까지 하얀 창이 보이기 때문입니다. 화면이 8초 안에 알려 오지 않아도 창은 보여 줍니다. 평소에 켤 때는 이 변수가 없어 전과 같이 뜹니다.
  • 열려 있던 세션은 끝납니다. 새 버전이 뜨면 11절대로 쉬는 세션으로 되살아나고, 누르면 Claude 세션은 하던 대화를 이어 갑니다.
  • 새 버전은 시작할 때 실행 파일 폴더에서 이름이 .old-<숫자>로 끝나는 파일(업데이트가 이름을 바꿔 둔 옛 파일)과 update 폴더에 남은 지 한 시간이 넘은 것을 지웁니다(다른 창이 지금 받고 있는 묶음은 두고, 이 창이 파일을 바꾸는 동안에는 옛 파일도 지우지 않습니다). 이름 가운데에 .old-가 든 다른 파일은 건드리지 않습니다(다시 시작으로 떴으면 앞선 창이 아직 떠 있어 옛 실행 파일이 지워지지 않으므로 30초 뒤에 한 번 더 치우고, 그래도 남으면 다음 시작 때 다시 시도). 끼움 프로그램(shim\claude.exe)도 새 전달 프로그램으로 다시 복사합니다.

릴리즈를 낼 때 지킬 것: 태그는 숫자와 점만으로 된 버전(v0.16.0처럼 앞의 v는 있어도 됨), 묶음의 이름은 …-windows-x64.zip으로 끝나고(지금까지는 cypher-<버전>-windows-x64.zip), 안에는 cypher.exe와 cypher-bridge.exe가 한 폴더에 함께 들어 있어야 합니다. 묶음은 이 저장소의 릴리즈 자산으로 올려야 하고(GitHub가 붙여 주는 확인값 digest가 있어야 함), 300MB를 넘으면 안 됩니다. 이 모양이 바뀌면 이전 버전의 업데이트 단추가 그 릴리즈를 설치하지 못합니다. 저장소 주소(sukmin/cypher)는 실행 파일 안에 적혀 있어서, 저장소의 이름이나 소유자가 바뀌어도 마찬가지입니다. 또 본창 웹뷰의 실행 옵션(tauri.conf.json의 additionalBrowserArgs)을 바꾼 버전은 "지금 다시 시작"으로는 뜨지 못합니다: 앞선 창이 떠 있는 동안 새 프로세스가 같은 저장소를 다른 옵션으로 열 수 없기 때문입니다. 그때는 "새 버전이 뜨지 못하고 끝났습니다"로 알리고 창을 그대로 두므로, Cypher를 껐다 켜면 새 버전으로 뜹니다(릴리즈 글에 적어 둘 것).

코드 그리기화면(ui/code.js). 줄을 150줄씩 덩이로 묶어, 처음에는 글자만 넣어 두고 화면 가까이 온 덩이만 강조해 그립니다. 화면 밖의 덩이는 브라우저가 그리기를 건너뜁니다(content-visibility). 줄 높이가 일정하므로 줄 번호로 스크롤 자리를 계산합니다. 찾은 곳·같은 이름 표시는 글자를 고치지 않고 브라우저의 강조 기능(CSS Highlight)으로 칠합니다. 파일의 글자는 모두 textContent로만 넣습니다.
정의 찾기앱(cypher-core/src/code.rs). 주석과 문자열을 가린 뒤 줄마다 언어별 모양(정규식)과 중괄호 깊이로 정의를 가려냅니다: 함수·메서드·생성자, 클래스·인터페이스·열거형·구조체·트레이트, 필드·상수·열거 값, CSS의 선택자·변수, HTML의 id. 메서드와 필드는 "자료형의 몸통 바로 안쪽 깊이"에 있을 때만 정의로 보아, 함수 몸통 안의 호출·지역 변수와 가립니다. Python은 들여쓰기로, Vue·HTML은 구역마다 그 언어로 읽습니다.
정의로 가기화면의 해석기(ui/code-nav.js)가 언어 서버 없이 받는 쪽의 자료형을 따라갑니다. ① 이름 앞에 받는 쪽이 있으면(a.b().c, Type::name) 그 식을 거꾸로 읽어 조각으로 나누고, 첫 조각의 자료형(지역 변수·인자·필드를 선언한 줄의 자료형, 없으면 넣는 값의 식, this·self는 감싼 자료형)에서 시작해 조각마다 그 멤버의 정의를 찾아(code_defs에 감싼 이름을 주어 거름) 서명에서 반환형·필드의 자료형을 읽어 이어 갑니다. 자료형은 이름의 묶음으로 다룹니다(Arc<Mutex<Config>> → Arc, Mutex, Config). 묶음은 보통 닫혀 있어 맨 바깥 자료형과 그 상위 자료형(서명의 extends·implements·상위 트레이트)에서만 그 이름을 찾고(Vec<Buffer>의 len은 Buffer의 것이 아니다), 안의 것을 꺼내는 일(get·unwrap·iter, [i], ?, for·람다의 원소)을 거치면 열려 안쪽 자료형에서도 찾습니다. Rust에서 Option·Vec·Mutex 같은 묶음이 아닌 밖의 자료형(Box·Arc, tauri의 State<T>)은 안의 것을 그대로 내놓는 감싸개로 보고 건너뜁니다. 멤버는 그 자리에서 그 이름이 가리키는 자료형의 파일(Java 등)이나 크레이트(Rust)에 든 것만 맞는 답으로 치고, 자료형 이름은 그 이름을 적은 파일의 import로 풉니다(Rust의 함수 안 use는 그 함수 안에서만). 확실할 때만 바로 가고, 받는 쪽의 자료형을 알 수 없으면 이름이 같은 정의가 하나뿐일 때만 바로 갑니다(흔한 이름은 그때도 고르게 합니다). 맨 바깥 자료형이 이 폴더에 없으면(또는 import가 밖을 가리키면) "이 폴더 밖의 것"이라 알리고, 자료형은 있는데 멤버가 없으면 접근자의 필드(Lombok·record) → 트레이트·인터페이스의 기본 메서드 → "정의가 없다"는 알림 순입니다. ② 받는 쪽이 없으면 지역 선언(여러 줄에 걸친 인자, 무늬에서 꺼낸 이름, 람다의 인자 포함) → 감싼 자료형과 상위 자료형의 멤버 → import·use가 가리키는 파일의 것(같은 패키지, * import 포함) → 이 파일에서 정의한 것 순입니다. ③ 어느 것으로도 가리지 못하면 예전처럼 이름이 같은 정의에 같은 파일·같은 폴더·가져다 쓰는 파일로 점수를 매겨 맨 앞이 뚜렷하면 바로 가고 아니면 고르게 합니다. 인자 수가 다른 같은 이름(오버로드)은 부르는 자리의 인자 수로 거릅니다. 누른 자리가 바로 정의면: 메서드는 그 구현(code_subtypes로 찾은 하위 자료형의 같은 이름)이나 짝(같은 자료형 이름 아래의 같은 이름 — MyBatis의 XML 구문 ↔ 인터페이스)으로, mod name;은 그 파일로, 그 밖에는 쓰는 곳을 보여 줍니다. 구현으로 가기(Ctrl+Alt+B)는 자료형이면 code_subtypes를 아래로 따라간 것들(클래스·인터페이스의 정의와 Rust의 impl 트레이트 for 자료형), 메서드면 그 자료형들의 같은 이름입니다. 앱은 정의마다 서명(정의한 줄부터 몸통 앞까지를 한 줄로 이은 것)과 상위 자료형을 함께 돌려줍니다(cypher-core의 Signer·supertypes·subtypes).
쓰는 곳 찾기·기호 찾기·글 찾기앱(cypher-app/src/code.rs). 코드 보기가 폴더를 열면(처음 화면에 보일 때) 그 아래의 파일을 한 번 훑어 색인을 만듭니다(code_index). 색인은 디스크에 둡니다(%LOCALAPPDATA%\cypher\code-index\<폴더 경로의 해시>\): blocks.bin(파일마다의 정의들 — 이름을 한 글에 모으고 정의마다 24바이트 기록으로 적음), words.bin(파일마다의 낱말 해시 — 영문·숫자·_·$가 이어진 것, 정렬해 둠), table.bin(파일 목록 — 경로, 고친 때, 크기, 두 파일에서의 자리, 정의 이름의 해시들). 메모리에는 파일 목록만 올리므로 파일이 수만 개여도 메모리를 조금만 쓰고(한도 30만 개), 앱을 다시 켜면 목록만 읽어 바로 씁니다(그사이 바뀐 파일만 다시 읽음). 두 덩이 파일은 뒤에 덧붙이기만 하고(바뀐 파일은 새 덩이를 덧붙임), 버려진 덩이가 16MB를 넘고 살아 있는 것보다 많아지면 새로 써서 줄입니다. 목록은 임시 파일에 쓴 뒤 이름을 바꿔 적고, 깨졌거나 다른 폴더의 것이거나 가리키는 자리가 파일 끝을 넘으면 버리고 다시 만듭니다. 30일 넘게 쓰지 않은 색인 폴더는 지웁니다(열려 있거나 만드는 중인 것은 둠).
찾을 때: 정의로 가기는 메모리의 이름 해시로 파일을 고르고, 쓰는 곳 찾기는 words.bin을 한 번 훑어 그 낱말이 든 파일을 고른 뒤, 고른 파일만 지금 내용으로 다시 읽어 답합니다(색인이 조금 묵어도 줄 번호는 맞음). 기호 찾기는 blocks.bin을 여러 스레드로 훑어 이름으로 순위를 매깁니다(고른 파일의 고친 때나 크기가 색인에 적은 것과 다르면 그 파일의 정의는 지금 내용에서 다시 읽음). 맞추기: Claude 세션이 파일을 쓰면(session-file·session-edit) 그 파일만 바로 다시 넣고(code_index_touch, 파일 목록을 다시 읽지 않음. 색인에 없던 파일은 git이 무시하지 않는 것만 넣음), 그 밖에는 화면이 git에서 바뀐 것을 볼 때·가끔씩(지난번에 걸린 시간에 따라 작은 프로젝트는 6초, 큰 프로젝트는 30초 넘게)·정의를 못 찾았을 때(3초 넘게 묵었으면) 파일 목록을 다시 읽어 고친 때나 크기가 달라진 파일만 다시 읽습니다. 처음 만드는 중에 찾으면 다 만들 때까지 기다립니다. 같은 폴더를 보는 코드 항목이 없어지면 돌던 맞추기를 읽은 데까지만 적고 멈춘 뒤 메모리에서 내립니다(디스크의 것은 남음. 처음 만들다 멈춘 색인은 “다 만들지 못함”으로 적어 두고 찾는 데 쓰지 않으며, 다음에 열 때 이어서 만듦). 색인 파일에 덧붙이는 일은 폴더마다 잠금 하나 안에서만 하고, 닫는 쪽도 그 잠금을 쥔 뒤에 자리를 치웁니다(닫았다 곧바로 다시 열어도 두 일이 같은 파일에 함께 덧붙지 않음). 디스크에 쓰지 못하면(자리가 없음, 파일이 잠김) 색인을 메모리에서 내려 파일을 모두 읽는 길로 물러나고 위쪽 줄에 “색인 없음”으로 알린 뒤 다음 차례에 다시 해 봅니다. 위쪽 줄의 [재색인](code_index_rebuild)은 색인 파일을 지우고 처음부터 다시 만듭니다. 한글이나 -가 든 이름의 쓰는 곳과 글 찾기는 지금도 모든 파일을 훑습니다(여러 스레드로 나눠 읽음). 대상 파일은 git이 아는 파일(추적하는 것과 무시하지 않는 새 파일)이고, git 저장소가 아니면 숨김·빌드 폴더를 빼고 돌아다니며 코드·글자 파일만 고릅니다. 파일은 4만 개, 파일 하나는 1MB, 결과는 2천 곳까지입니다. 쓰는 곳은 낱말 단위로 찾아 정의·쓰는 곳·주석 안·문자열 안으로 가려 줍니다.
바뀐 파일과 줄변경 내용 옆 창과 같은 git 명령을 씁니다(git_changes, git_diff). 나무와 탭에 고친 파일·새 파일을 색으로, 줄 번호 옆에 더한 줄·고친 줄·지운 자리를 표시합니다. 바뀐 곳 모아 보기: git_hunks가 git diff -U0 HEAD 한 번으로 저장소 전체의 바뀐 곳(시작 줄, 더한·지운 줄 수, 지운 줄의 글)을 읽어 주고(문맥 줄이 없어 갈래 하나가 바뀐 곳 하나. 갈래의 몸통은 머리에 적힌 줄 수만큼만 읽어, -- 로 시작하는 지운 줄을 파일 머리로 잘못 읽지 않음), 화면은 6초마다와 파일이 바뀔 때 이것을 다시 읽어 해시가 달라졌을 때만 목록을 다시 그립니다. [바뀐 파일] 보기의 나무는 파일 아래에 바뀐 곳을 늘어놓고, 누르면 그 줄로 가서 지운 줄을 "이전 내용" 창으로 띄웁니다(창은 줄 목록의 자식이 아니라 스크롤 영역 위에 띄워, 줄 번호 셈과 덩이 그리기를 건드리지 않음). 지워진 파일은 바뀐 곳에 담겨 온 지운 줄로 지우기 전의 내용을 보여 줍니다. 한도: 차이 8MB, 바뀐 곳 3천, 바뀐 곳 하나의 지운 줄 400줄. 이름의 글자색을 git 상태에 쓰므로, 파일의 종류는 이름 앞의 표식으로 가립니다(code-lex.js의 fileBadge: 확장자 → 한두 글자와 색 이름. 색은 IntelliJ의 아이콘 색을 따른 --fi-* 변수이고 테마마다 따로 둡니다). 같은 워크스페이스의 Claude 세션이 파일을 쓰면 앱이 알려 온 신호(8절)를 코드 항목에도 넘겨(fileChanged) 나무와 바뀐 파일을 곧 다시 읽고, 보고 있는 파일이면 바로 다시 읽습니다. 그 밖에는 보이는 동안 2초마다 고친 시각을 봅니다.
띄울 프로그램 찾기(코드 보기와는 별개) 세션의 프로그램은 PATH에서 실행 파일·배치 파일을 찾아 띄웁니다. 사용자가 적어 준 Claude 실행 명령은 더 너그럽게 찾습니다: PATH의 PowerShell 스크립트(이름.ps1), 그것도 없으면 PowerShell의 명령(프로필의 별칭·함수)으로 실행합니다. 스크립트의 실행 정책은 건드리지 않고, PowerShell에 넘기는 인자는 작은따옴표(굽은 따옴표 포함)를 겹쳐 적어 글자 그대로 넘깁니다(cypher-pty).
글꼴위쪽 글꼴 칸에서 코드의 글꼴과 글자 크기를 앱의 글꼴(설정 → 모양)과 따로 정합니다. 이 컴퓨터에 기억하고(cypher.code.font) 모든 코드 항목이 함께 씁니다.

한계: 자료형을 따져야 알 수 있는 것(같은 이름의 메서드 가운데 어느 것인지, 상속받은 멤버)은 가리지 못해 이름이 같은 정의를 모두 내놓습니다. 한 줄에 정의가 둘 이상이면 첫 정의만 찾습니다. TypeScript 인터페이스의 속성, C의 전역 변수처럼 모양만으로 가리기 어려운 것은 정의로 잡지 않습니다. 4만 줄이 넘는 파일과 5천 자가 넘는 줄은 강조하지 않고, 그런 줄에는 찾은 곳·같은 이름 표시도 걸지 않습니다(지금 자리 하나만 표시 — 한 줄로 줄인 CSS·JSON에서 화면이 멈추지 않게).

14. SSH 세션, 타이머·알람 0.17부터

  • SSH 세션은 터미널 세션의 한 프로필(ssh)입니다. Cypher가 SSH를 직접 구현하지 않고 Windows에 든 OpenSSH(ssh.exe)를 가상 터미널에 붙여 띄웁니다. 그래서 키·에이전트·~/.ssh/config·known_hosts는 명령줄과 똑같이 적용되고, 비밀번호는 Cypher를 지나가기만 할 뿐 저장되지 않습니다.
  • 접속할 곳({ target, port, identity, options, name })은 화면이 세션을 만들 때 넘기고, 앱이 ssh의 인자로 바꿉니다(cypher-core/src/ssh.rs). 대상 자리에 옵션이 끼어들지 못하게, -로 시작하거나 빈칸이 든 대상은 거절합니다. 접속할 곳은 항목의 기록에 함께 저장되어 다시 시작하면 쉬는 세션으로 되살아나고, 누르면 다시 접속합니다. 워크스페이스 틀에는 주소·포트·이름만 담고(키 파일 경로와 추가 옵션은 담지 않음 — 틀 파일은 남에게서 받을 수 있고, 옵션은 명령을 실행할 수 있음), 틀로 펼친 SSH 세션은 쉬는 세션으로 놓아 사용자가 누를 때 접속합니다.
  • 접속 창(ui/ssh.js)은 저장해 둔 서버(cypher.ssh.hosts)와 ~/.ssh/config의 Host(여러 호스트에 걸리는 *·?·!가 든 이름은 뺌)를 보여 줍니다. 연결 복제는 같은 접속할 곳으로 세션을 하나 더 여는 것입니다(연결을 함께 쓰는 것이 아니라 새로 접속함. Windows의 OpenSSH는 연결 함께 쓰기를 지원하지 않음).
  • 동시 입력은 두 가지입니다(broadcast): 나란히 보이는 모든 터미널 세션('all', Ctrl+Shift+B)과 나란히 보이는 SSH 세션끼리만('ssh', SSH 창 제목 줄의 [동시 입력]). 입력을 보낼 때 받는 세션을 다시 셉니다(castTargets): 끝났거나 쉬는 세션은 빠지고, 대상이 아닌 세션에 친 것은 그 세션에만 갑니다.
  • 타이머·알람(ui/timer.js)은 울릴 때를 벽시계 시각으로 적어 화면의 저장소에 둡니다(cypher.timers). 1초마다, 그리고 켠 직후에 지난 것을 찾아 알리고 지웁니다. 그래서 Cypher가 꺼져 있던 동안 지나간 것은 켠 직후에 "지난 알람"으로, 컴퓨터가 잠들어 늦어진 것은 깨어난 직후에 알립니다. 24시간을 넘는 것은 받지 않습니다. 저장된 목록이 기준이라(맞추고 지우고 살필 때마다 다시 읽음) Cypher 창이 둘이어도 서로의 것을 지우지 않습니다. 창이 가려지거나 내려가 있으면 브라우저가 화면의 타이머를 늦추므로(오래 가려져 있으면 1분에 한 번), 다음에 울릴 때까지 앱이 대신 기다렸다가(wake_after, 길면 30초씩 끊어) 화면을 깨웁니다.

16. 막지 못하는 것

울타리는 Cypher 도구에 세운 것입니다. 그 바깥은 Cypher가 막을 수 없습니다.

  • 파일 직접 접근: Claude Code는 자기 권한 설정 안에서 이 컴퓨터의 파일을 읽고 씁니다. 다른 워크스페이스의 메모가 저장된 파일도 파일로는 읽을 수 있습니다. 이것은 Claude Code의 권한 설정으로 다룹니다.
  • 프로세스 조작: 세션 안에서 통로에 직접 접속해 다른 세션의 번호를 적는 평범한 방법은 막지만, 같은 Windows 사용자 권한으로 다른 프로세스 자체를 조작하는 것(부모 프로세스 위조, 코드 주입)까지 막지는 못합니다.
  • 셸 세션에서 돌린 다른 프로그램: 셸 세션에도 통로의 주소와 확인값이 환경 변수로 들어가므로(4절), 그 셸에서 실행한 프로그램은 그 세션의 이름으로 통로에 접속해 그 워크스페이스의 Cypher 도구를 쓸 수 있습니다. 믿을 수 없는 프로그램을 돌린다면 claude_in_shell = false로 끕니다.
  • 같은 폴더를 보는 HTTP 항목: HTTP 규칙은 폴더 기준이라, 두 워크스페이스가 같은 폴더의 요청 파일을 보면 함께 다루게 됩니다.
  • 업데이트의 믿음: 확인값은 GitHub가 알려 주는 값입니다. 묶음이 올라온 뒤에 바뀌지 않았다는 것과 이 저장소의 릴리즈에서 받았다는 것은 확인하지만, 릴리즈를 올리는 계정 자체가 탈취된 경우까지 막지는 못합니다(업데이트는 실행 파일의 서명을 따로 확인하지 않습니다).
