1. 전체 구성

Cypher는 실행 파일 두 개입니다. 창을 띄우는 cypher.exe와, Claude Code가 불러 주는 작은 심부름꾼 cypher-bridge.exe(전달 프로그램)입니다. 전달 프로그램은 claude.exe라는 이름의 사본으로 불리면 끼움 프로그램으로 동작합니다(4절).

  • 화면은 빌드 단계 없는 자바스크립트입니다. 사이드바의 항목과 워크스페이스를 알고 있는 것은 화면뿐입니다.
  • 본체는 화면이 못 하는 일(프로세스 띄우기, 파일, 네트워크)을 합니다. 워크스페이스에 관한 판단이 필요하면 화면에 물어봅니다.
  • 웹 페이지를 보여 주는 사이트 항목의 웹뷰에는 앱 명령 권한을 주지 않습니다. 본창의 화면에는 보안 정책(CSP)이 걸려 있어 화면 코드가 바깥과 통신하지 못합니다.
  • 크레이트는 넷입니다: cypher-core(화면·창과 무관한 로직: 링크·설정·프로필·.http 형식·글자 파일·창 자석 계산), cypher-pty(ConPTY 세션), cypher-bridge(전달 프로그램), cypher-app(Tauri 앱).

2. 사이드바: 워크스페이스와 항목

사이드바에 놓이는 것을 항목이라 부릅니다. 터미널 세션(Claude, PowerShell 등 프로필)과 그 밖의 열 가지 종류(메모, HTTP, 사이트, 이미지, 마인드맵, ERD, 문서, 할 일, 명령, 표)가 있습니다. 0.13부터 모든 세션과 항목은 이름 붙인 워크스페이스 안에만 놓입니다(업무 하나가 워크스페이스 하나).

  • 새 종류의 항목은 이름·아이콘과 화면을 만드는 함수(create(item, host, saved, onChange) → { ready, focus, title, state, close, dispose })를 ui/main.js의 KINDS에 올리면 사이드바·분할·워크스페이스·복원에 그대로 들어갑니다.
  • 항목은 아무것도 묻지 않고 만들어집니다. 볼 파일이나 실행할 명령이 필요한 종류(문서·명령·표)는 빈 영역으로 뜨고, 거기서 파일을 끌어다 놓거나 고르거나 경로를 적어 대상을 정합니다(ui/empty.js).
  • 워크스페이스를 정할 수 없으면 만들지 않습니다(groupFor): 주어진 워크스페이스 → 지금 보는 항목의 워크스페이스 → 워크스페이스가 하나뿐이면 그것. 그 밖에는 알림만 띄웁니다.
  • 워크스페이스 폴더(cypher.groupFolders)는 그 워크스페이스에서 여는 세션의 시작 폴더입니다. 정하지 않았으면 그 워크스페이스에 이미 있는 항목의 폴더, 그것도 없으면 사용자 폴더를 씁니다.
  • 북마크는 항목에 붙이는 숫자(0~9) 하나입니다. 숫자 하나에 항목 하나이고, 항목의 기록(mark)에 함께 저장됩니다.
  • 코드 안의 이름(group, createGroup, 저장 키 cypher.groups)은 "그룹"이던 때의 것을 그대로 씁니다(저장된 자료를 옮기지 않으려는 것).

3. Claude 세션과 이야기하는 길

Cypher는 Claude 세션을 띄울 때 claude --mcp-config <파일> --settings <파일>로 설정을 끼워 넣습니다(도구 연결인 --mcp-config는 설정에서 [browser] enabled = false로 끄면 붙이지 않습니다). 사용자의 settings.json은 건드리지 않습니다. 그 설정이 전달 프로그램을 세 가지 자리에 걸어 둡니다.

  • 통로에 접속하면 첫 줄에 확인값(실행할 때마다 운영체제의 난수로 새로 만드는 128비트 값), 둘째 줄에 세션 번호(도구 연결은 mcp <세션 번호>)를 적습니다. 전달 프로그램은 이 값들을 환경 변수(CYPHER_PORT, CYPHER_TOKEN, CYPHER_SESSION)로 받습니다.
  • 전달 프로그램은 신호를 보낸 뒤 본체가 처리를 마치고 연결을 닫을 때까지(길어야 1.5초) 기다립니다. 그래서 "쓰기 직전" 신호는 Claude가 실제로 파일을 쓰기 전에 처리됩니다(본체가 1.5초 안에 처리하는 보통의 경우).
  • 훅: 늘 거는 것은 요청 시작(UserPromptSubmit), 응답 완료(Stop), 입력·승인 대기(Notification), 서브에이전트 시작·종료(SubagentStart·SubagentStop), Claude Code 종료(SessionEnd)입니다. 도구 훅(PreToolUse·PostToolUse)은 설정에 따라 다릅니다: [session] activity가 켜져 있으면 모든 도구에 걸고 실패 신호(PostToolUseFailure)도 받으며, 꺼져 있고 show_created만 켜져 있으면 파일을 쓰는 도구에만 겁니다(Write의 직전과 Write·Edit·MultiEdit의 직후). 둘 다 꺼져 있으면 걸지 않습니다.
  • 본체는 도구 신호를 화면에 그대로 넘기지 않습니다. 도구 이름과 짧은 설명만 뽑아 session-tool 이벤트로 알리고(9절), Write 도구의 신호에서는 새로 만든 파일을 가려 session-file로, 있던 파일을 고쳐 쓴 것(Write·Edit)은 session-edit로 알립니다(8절). 상태줄은 session-status, 그 밖의 훅은 session-hook입니다.
  • 도구는 26개입니다: 브라우저 13개(browser_*), HTTP 2개(http_list·http_run), 항목 11개(cypher_items, memo_write, mindmap_write, erd_write, todo_write, todo_check, run_output, image_add, doc_show, table_show, notify_user).
  • 워크스페이스를 알아야 하는 도구는 본체가 화면에 물어서(mcp-request 이벤트) 답을 받습니다(20초 안에). 화면이 그 시각을 넘겨 받은 요청은 실행하지 않습니다(Claude가 다시 시도한 것과 겹치지 않게).
  • 상태줄 자리는 하나뿐이라, 사용자가 원래 쓰던 상태줄(HUD)이 있으면 전달 프로그램이 정보를 넘긴 뒤 그 명령을 이어서 실행해 출력을 그대로 내보냅니다(CYPHER_STATUSLINE).
  • 설정 → "Claude 실행 명령…"에 적어 둔 명령이 있으면 claude 대신 그 명령으로 띄우고, 위 인자는 그 뒤에 붙입니다.

4. 셸에서 띄운 Claude에 붙기 0.12부터

PowerShell 같은 셸 세션에서 사용자가 직접 친 claude에도 Cypher가 붙습니다. 셸 세션의 PATH 맨 앞에 claude.exe라는 이름의 작은 끼움 프로그램을 두는 방식입니다.

  • 끼움 프로그램은 본체가 시작할 때 전달 프로그램을 %LOCALAPPDATA%\cypher\shim\claude.exe로 복사해 만듭니다. 전달 프로그램이 바뀌었으면(새 버전) 사본도 바꿉니다.
  • 끼움 프로그램은 진짜 claude(claude.exe·.cmd·.bat)를 PATH에서 자기 폴더를 건너뛰고 찾습니다. 그 Claude Code가 다시 띄우는 claude는 끼움 프로그램을 거치지 않게, 자식의 PATH에서 자기 폴더를 빼고 붙일 파일의 경로도 넘기지 않습니다(같은 세션 번호로 신호가 겹치지 않게).
  • 그 Claude가 끝나면 SessionEnd 훅이 와서 그 줄의 모델·상태 표시를 지우고 평범한 셸로 돌아갑니다(/clear·/resume으로 온 것은 끝난 것으로 치지 않음). 다시 시작한 뒤에는 셸만 되살립니다.
  • 설정의 [session] claude_in_shell = false로 끕니다. 끄면 셸 세션에는 통로의 값도 넣지 않고 PATH도 건드리지 않습니다.

5. 누가 보냈는지 확인하기

통로로 오는 신호에 적힌 세션 번호는 보낸 쪽이 스스로 적은 값입니다. 확인값은 Cypher가 띄운 모든 세션의 프로세스가 알고 있으니, 번호만 믿으면 한 세션이 다른 세션인 척할 수 있습니다. 그래서 Cypher는 번호를 믿지 않고 접속한 프로세스가 누구의 자손인지를 직접 봅니다.

  • 순서: 확인값이 맞는지 본다 → 접속한 프로세스를 찾는다 → 조상을 따라 올라간다 → 적힌 번호와 같은 세션인지 본다.
  • 부모가 이미 끝났거나 번호가 다른 프로세스에 다시 쓰인 경우는 "만든 시각"을 비교해 걸러 냅니다(부모는 자식보다 먼저 만들어졌어야 합니다).
  • 셸 세션에서 띄운 Claude(4절)는 그 셸의 자손이므로 그 셸 세션의 번호로 받아들여집니다.

6. 다룰 수 있는 범위

Claude 세션이 Cypher 도구로 다룰 수 있는 것은 자기와 같은 워크스페이스에 있는 항목뿐입니다. 규칙은 한 줄짜리 판정(canControl)에 모여 있습니다: 둘이 같은 워크스페이스에 있고, 대상이 자기 자신이나 터미널 세션이 아닐 것.

상황결과
같은 워크스페이스의 메모·마인드맵·ERD·할 일·사이트·HTTP·문서·표·이미지다룰 수 있음(만들기, 고치기, 놓기, 조작)
같은 워크스페이스의 명령 항목상태와 출력 읽기만(run_output). 만들기·실행·멈춤은 사용자만
다른 워크스페이스의 항목거절. 목록에도 나오지 않음
다른 세션(Claude든 PowerShell이든)거절. 다루는 도구 자체가 없음(같은 워크스페이스의 세션은 목록에 이름·폴더·상태만 보임)
항목이나 세션을 다른 워크스페이스로 옮김그 순간부터 옛 워크스페이스는 거절, 새 워크스페이스는 허용(판정을 매번 새로 함)
부른 세션을 알 수 없는 요청거절

HTTP 도구는 폴더 기준입니다: 같은 워크스페이스 HTTP 항목의 요청 폴더와 그 세션을 시작한 폴더의 요청 파일(폴더 바로 아래, http, .cypher\http)에만 씁니다.

명령 항목이 돌리는 프로그램은 세션과 같은 가상 터미널에서 돌지만, 통로의 값(CYPHER_*)과 끼움 프로그램은 넣지 않습니다. 그래서 명령 항목으로 돌린 프로그램은 Cypher 도구에 붙지 못합니다.

판정에는 "워크스페이스에 들지 않은 세션은 새 항목 놓기와 알림만 된다"는 갈래가 남아 있지만, 0.13부터 모든 세션이 워크스페이스 안에 있으므로(옛 것은 root로 모임) 실제로는 생기지 않습니다.

사용자가 직접 하는 일(변경 내용에서 고른 줄을 세션에 넣기, 이미지 경로를 세션에 넣기, 할 일을 세션에 넣기)은 이 제한과 무관합니다. 제한은 "Claude가 도구로 하는 일"에만 겁니다.

7. 워크스페이스마다 다른 브라우저

조작할 수 있는 탭만 나누면 로그인 상태가 샙니다(A 워크스페이스에서 로그인한 사이트에 B 워크스페이스의 Claude가 자기 브라우저로 가면 로그인돼 있음). 그래서 브라우저 프로필(쿠키·저장소가 담기는 폴더)을 워크스페이스마다 따로 씁니다.

  • 어느 워크스페이스가 어느 프로필 번호를 쓰는지는 화면이 기억합니다(cypher.profiles). 번호는 그 워크스페이스에서 브라우저를 처음 띄울 때 만듭니다. 워크스페이스 이름을 바꿔도 번호는 그대로라 로그인 상태가 유지됩니다.
  • 이미 있는 워크스페이스에 합치면 합쳐진 쪽 항목은 그 워크스페이스의 프로필을 씁니다.
  • 워크스페이스를 없앴다가 같은 이름으로 다시 만들면 예전 프로필을 다시 씁니다.
  • 프로필마다 브라우저 엔진 프로세스가 따로 뜹니다(사이트 항목을 실제로 띄운 워크스페이스만).
  • 어느 항목이 어느 프로필을 써야 하는지는 화면이 정해 본체에 알립니다. Claude의 도구 호출이 그와 다른 프로필을 들고 오거나(도구가 도는 사이에 항목이 옮겨짐) 그사이 항목이 닫혔으면 본체는 웹뷰를 만들지 않고 거절합니다.
  • 사이트 웹뷰가 여는 것은 웹 주소(http, https)와 이 컴퓨터의 HTML 파일(.html, .htm)뿐입니다. 다른 로컬 파일과 네트워크 경로의 파일(file://서버/…)은 열지 않습니다. Claude의 browser_navigate도 같은 규칙을 따릅니다.
  • 사이트 웹뷰는 본창에 붙인 별도의 웹뷰를 그 항목의 창 자리에 겹쳐 놓은 것입니다(많은 사이트가 iframe을 막아 두었기 때문). 조작은 디버깅 포트를 열지 않고 WebView2의 개발자 도구 프로토콜을 앱 안에서 직접 부릅니다.
  • 워크스페이스를 없애도 프로필 폴더는 지우지 않습니다. 지우려면 Cypher를 끄고 site-profiles(chrome 엔진은 chrome-profiles) 아래의 폴더를 지웁니다. 폴더 이름은 번호라 어느 워크스페이스의 것인지 드러나지 않으니, 가리기 어렵다면 모두 지우고 워크스페이스마다 다시 로그인합니다.

8. 만든 파일을 사이드바에 놓기

Claude가 Write 도구로 새 파일을 만들면 종류에 맞는 항목으로 그 세션의 워크스페이스에 놓고 알림으로 알려 줍니다. 보던 화면은 바꾸지 않습니다. "새 파일인지"는 쓰기 직전에 그 파일이 없었는지로 가립니다.

  • HTML 파일은 그 파일을 여는 사이트 항목이 됩니다. 웹뷰는 사용자가 그 항목을 처음 볼 때 뜹니다. .json은 설정 파일인 경우가 많아 놓지 않습니다(table_show로 놓을 수 있음).
  • 요청 파일(.http)은 그 폴더를 보는 HTTP 항목이 이미 있으면 새로 만들지 않고 그 항목의 파일 목록을 다시 읽게 합니다.
  • 한 세션에서 같은 파일은 한 번만 놓고, 그 워크스페이스의 문서·표·메모·HTTP·사이트 항목이 이미 보여 주는 파일은 놓지 않습니다. 한 요청에 8개까지 놓고, 넘치면 한 번 알립니다.
  • 숨김 폴더·빌드 폴더(.git, node_modules, target 등)인지를 볼 때, 세션이 일하는 폴더 안의 파일은 그 폴더 아래 부분만 보고(프로젝트 자체가 D:\build 같은 곳에 있어도 놓임) 밖의 파일은 경로 전체를 봅니다. 요청 파일 자리인 .cypher\http는 예외로 놓습니다.
  • 임시 폴더와 Claude·Cypher의 설정·데이터 폴더, 네트워크 경로에 만든 파일은 놓지 않습니다.

고쳐 쓴 파일은 보여 주던 항목이 새로 읽는다

있던 파일을 고친 것(Edit·MultiEdit 도구의 직후 신호, 새 파일이 아닌 Write의 직후 신호)은 항목을 놓지 않고 session-edit 이벤트로 화면에 알립니다. 화면(onEditedFile)은 그 세션과 같은 워크스페이스(워크스페이스가 없으면 같은 폴더 묶음)에서 그 파일을 보여 주는 항목을 찾아 바로 새로 읽게 합니다. 다른 워크스페이스의 항목은 같은 파일을 보고 있어도 건드리지 않습니다.

그 파일을 보여 주는 항목하는 일
문서, 표고친 시각을 견주어 보던 자리를 지킨 채 다시 읽습니다. 이 둘은 화면에 보이는 동안 1.5초마다 스스로도 살피지만, 신호가 오면 가려져 있어도 바로 읽습니다.
사이트 (주소가 그 파일의 file:/// 주소인 것)웹뷰를 새로 고칩니다. 주소 뒤의 #자리·?값은 빼고 견줍니다. 웹뷰가 아직 뜨지 않았으면 할 일이 없습니다(처음 볼 때 새 내용으로 뜹니다).
이미지 (그 파일에서 가져온 그림)이미지 항목은 저장소에 복사해 둔 그림을 보여 주므로, 파일을 다시 가져와 그림을 바꿉니다. 옛 그림은 닫은 이미지처럼 보관 폴더로 옮깁니다(30일).
파일에 연결된 메모, HTTP 항목고치던 글이 없을 때만 디스크의 내용으로 맞춥니다. 고치던 글이 있으면 표시만 해 두고, 저장할 때 "다시 읽기 / 덮어쓰기"를 묻습니다.
  • 도구 신호로 아는 것이라 명령(Bash 등)으로 고친 파일은 알 수 없습니다. 문서·표는 스스로 살피므로 그래도 반영되고, 사이트는 ⟳로 다시 읽습니다.
  • [session] activity와 show_created를 둘 다 꺼 두면 도구 훅을 걸지 않으므로 이 신호도 오지 않습니다.

10. 터미널 화면 맞추기 0.16부터

세션의 출력은 프로그램 → Windows의 가상 터미널(conhost) → 화면(xterm.js) 순으로 옵니다. conhost는 자기 화면을 따로 갖고 있다가 바뀐 칸만 다시 보내는데, 이때 줄바꿈과 커서 이동을 생략합니다. 그래서 둘이 글자의 칸 수를 다르게 세면 줄이 밀려 화면이 어긋납니다.

  • 칸 수 표(ui/widths.js): xterm.js의 기본 표(유니코드 11)와 conhost가 다르게 세는 글자(변형 선택자가 붙은 이모지 ✔️·⚠️, 유니코드 12 이후의 이모지, 국기, 결합 글자)를 conhost 쪽에 맞춥니다. 화면을 실제로 배치하는 쪽이 conhost이기 때문입니다.
  • 이 표는 세션이 Windows에 내장된 conhost(실제로 재어 본 빌드 27000 미만)에 붙을 때만 씁니다. 빌드가 그 이상이거나 실행 파일 옆에 따로 둔 conpty.dll을 쓰면 유니코드 11 표를 그대로 두고, 아래의 자동 다시 맞추기도 돌지 않습니다(오른쪽 클릭 메뉴로 직접 하는 것은 됩니다). 어느 쪽인지는 본체가 시작할 때 알려 줍니다(Windows 빌드 번호와 conpty.dll이 있는지).
  • xterm.js에는 Windows 가상 터미널에 붙는다는 것도 알려 줍니다(windowsPty). 줄 수가 늘 때 지난 출력을 화면으로 끌어내리지 않고 아래에 빈 줄을 더하게 해서, conhost가 다시 그린 화면과 어긋나지 않게 합니다.
  • 다시 맞추기(realign): Claude Code와 conhost가 다르게 세는 글자가 찍혔으면 그 세션에 표시해 두었다가, 응답이 끝났을 때(Stop) 터미널을 한 줄 줄였다가 0.45초 뒤 되돌립니다. 크기가 바뀌면 프로그램이 화면을 처음부터 다시 그리고, 다시 그리지 않는 프로그램이라도 conhost가 자기 화면을 통째로 다시 보냅니다.
  • 지난 출력을 올려 보는 중이면 건드리지 않습니다(보던 자리를 잃지 않게). 사용자는 세션 오른쪽 클릭 → "화면 다시 맞추기"로 직접 할 수 있습니다.

11. 다시 시작과 쉬는 세션 0.12부터

화면은 열린 항목과 분할 모양을 바뀔 때마다 cypher.state에 적어 둡니다. 다시 시작하면 그 기록으로 되살립니다.

  • 터미널 세션은 바로 띄우지 않습니다. 사이드바에 "쉬는 중"으로만 되살려 두고(프로세스 없음), 사용자가 누른 세션만 띄웁니다(wake). 워크스페이스 머리의 ▶는 그 워크스페이스의 쉬는 세션을 한꺼번에 띄웁니다. 설정의 [session] restore_on_click = false이면 예전처럼 모두 바로 띄웁니다.
  • Claude 세션은 하던 대화의 번호를 적어 두었다가 --resume <번호>로 이어 엽니다. 셸에서 띄운 Claude의 대화는 잇지 않습니다(셸만 되살림).
  • 메모·마인드맵·ERD 같은 다른 항목은 바로 되살립니다. 항목마다 화면이 내놓은 상태(state(): 메모 번호, 보던 파일, 주소 …)를 그대로 돌려줍니다. 세션 복원을 꺼 두어도(restore = false) 이 항목들은 사이드바에 되살립니다(사용자가 쓴 글이 목록에서 사라지지 않게).
  • 명령 항목은 명령만 되살리고 스스로 실행하지 않습니다.
  • 창을 닫을 때는 본체가 닫기 요청을 한 번 미루고, 화면이 쓰던 것을 저장했다고 알려 오면(길어야 3초) 닫습니다.
  • 닫은 항목은 같은 기록 모양으로 30일 동안, 30개까지 기억해(cypher.closed) 다시 열 수 있습니다. 메모·마인드맵·ERD·할 일·이미지의 내용은 저장 폴더의 closed에 보관합니다.

12. 업데이트 0.16부터

Cypher는 설치 프로그램 없이 실행 파일 두 개로 배포됩니다. 업데이트는 GitHub 릴리즈의 묶음(zip)을 받아 실행 파일이 있는 폴더의 파일을 바꾸는 것입니다. 사용자가 도움말 → "Cypher 업데이트…"에서 단추를 눌렀을 때만 돌고, Cypher가 스스로 확인하러 나가지 않습니다. 저장소와 릴리즈가 공개라서 로그인이나 토큰이 필요 없고, 보내는 정보도 없습니다.

① 업데이트 확인

  • https://api.github.com/repos/sukmin/cypher/releases/latest를 읽습니다(연결 10초, 전체 15초 안에).
  • 릴리즈의 태그(v0.16.0)에서 v를 떼고 점으로 나눈 숫자들을 지금 버전과 숫자로 견줍니다(0.100.0 > 0.99.9). 태그가 숫자와 점만으로 된 버전이 아니면(0.16.0-beta 등) 확인이 "릴리즈의 버전을 읽지 못했습니다"라는 오류로 끝나고, 설치 단추는 나오지 않습니다.
  • 묶음은 릴리즈의 자산 가운데 이름이 -windows-x64.zip으로 끝나고, 주소가 https://github.com/sukmin/cypher/releases/download/로 시작하는 것만 받습니다. 이름에 경로(/, \, ..)가 섞여 있으면 받지 않습니다. 확인값은 GitHub가 자산마다 붙여 주는 digest(sha256:…)에서 읽습니다.
  • 새 버전이 있어도 다음 경우에는 설치 단추를 내놓지 않고 까닭과 릴리즈 페이지를 안내합니다: 개발용 빌드, Windows 64비트 묶음이 없음, 확인값이 없음, 크기가 0이거나 300MB를 넘음, 실행 파일이 있는 폴더에 쓸 수 없음(Program Files 등 — 그 폴더에 시험 파일을 만들어 봄).

② ~ ④ 내려받아 설치

  • 설치를 누르면 본체는 최신 릴리즈를 다시 읽습니다. 받을 주소를 화면에서 넘겨받지 않고, 새 버전인지와 설치할 수 있는지도 다시 확인합니다.
  • 묶음을 %LOCALAPPDATA%\cypher\update에 받으면서 SHA-256을 구합니다. 받은 크기가 릴리즈에 적힌 크기와 다르거나 확인값이 다르면 설치하지 않습니다.
  • 풀 때는 Windows에 든 tar(%SystemRoot%\System32\tar.exe)를 씁니다(PATH의 다른 tar는 zip을 풀지 못함). 푼 곳에서 cypher.exe와 cypher-bridge.exe가 함께 든 폴더(푼 폴더 자체, 또는 그 안의 폴더 하나)를 찾고, 없으면 설치하지 않습니다.
  • 그 폴더의 파일을 하나씩 실행 파일이 있는 폴더에 놓습니다. 같은 이름의 파일이 이미 있으면 <이름>.old-<시각>으로 이름을 바꿔 두고 새 파일을 복사합니다. 도중에 하나라도 실패하면 놓은 것을 치우고 옛 파일의 이름을 되돌립니다(반쯤 바뀐 상태로 남지 않게).
  • 놓는 것은 그 폴더 바로 아래의 파일들입니다(실행 파일 둘과 묶음에 함께 든 README 등). 하위 폴더는 놓지 않고, 새 버전에서 없어진 파일을 지우지도 않습니다.
  • 내려받기의 시간 제한은 연결 10초, 전체 300초입니다. 도중에 실패하면 update 폴더에 받다 만 것이 남는데, 다음 설치를 시작할 때나 다음에 Cypher를 켤 때 지웁니다.
  • 끝나면 내려받은 것을 지우고 cypher.log에 "업데이트: 0.15.0 → 0.16.0 설치"처럼 남깁니다. 이때까지 돌고 있는 것은 옛 버전입니다.

⑤ ~ ⑥ 다시 시작

  • "지금 다시 시작"을 누르면 화면이 쓰던 것을 저장한 뒤, 본체가 실행 파일 폴더의 새 cypher.exe를 띄우고 이 창을 닫습니다. 새 것을 띄우지 못하면 이 창은 계속 씁니다. 누르지 않아도, 다음에 Cypher를 켜면 새 버전으로 뜹니다.
  • 열려 있던 세션은 끝납니다. 새 버전이 뜨면 11절대로 쉬는 세션으로 되살아나고, 누르면 Claude 세션은 하던 대화를 이어 갑니다.
  • 새 버전은 시작할 때 실행 파일 폴더에서 이름에 .old-가 든 파일과 update 폴더를 지웁니다(아직 쓰이고 있어 지워지지 않으면 다음 시작 때 다시 시도). 끼움 프로그램(shim\claude.exe)도 새 전달 프로그램으로 다시 복사합니다.

릴리즈를 낼 때 지킬 것: 태그는 숫자와 점만으로 된 버전(v0.16.0처럼 앞의 v는 있어도 됨), 묶음의 이름은 …-windows-x64.zip으로 끝나고(지금까지는 cypher-<버전>-windows-x64.zip), 안에는 cypher.exe와 cypher-bridge.exe가 한 폴더에 함께 들어 있어야 합니다. 묶음은 이 저장소의 릴리즈 자산으로 올려야 하고(GitHub가 붙여 주는 확인값 digest가 있어야 함), 300MB를 넘으면 안 됩니다. 이 모양이 바뀌면 이전 버전의 업데이트 단추가 그 릴리즈를 설치하지 못합니다. 저장소 주소(sukmin/cypher)는 실행 파일 안에 적혀 있어서, 저장소의 이름이나 소유자가 바뀌어도 마찬가지입니다.

13. 어디에 무엇을 저장하나

곳담는 것
%APPDATA%\cypher사용자의 것: 설정(config.toml, 예시 config.example.toml), 메모(memos), 마인드맵(mindmaps), ERD(erds), 할 일(todos), 이미지(images), 워크스페이스 틀(templates). 닫은 것은 각 폴더의 closed에 30일
%LOCALAPPDATA%\cypher내부 상태: 세션에 넘기는 설정 파일(claude-settings-*.json, mcp-*.json — 이틀 넘은 것은 시작할 때 지움), 끼움 프로그램(shim), 기록(cypher.log), 되돌리기 전 차이(reverted), 업데이트 내려받기(update), 붙여넣은 그림(paste, 사흘 뒤 지움), 워크스페이스별 브라우저 프로필(site-profiles, chrome-profiles. 워크스페이스 없이 띄운 chrome 엔진의 것은 chrome-profile)
%LOCALAPPDATA%\dev.cypher.terminal본창의 브라우저 저장소(공용 프로필). 화면의 저장소도 이 안에 있음
화면의 저장소(localStorage)열린 항목과 분할 배치(cypher.state), 워크스페이스 목록(cypher.groups)과 폴더(cypher.groupFolders), 워크스페이스 → 프로필 번호(cypher.profiles), 닫은 항목(cypher.closed), 알림 기록(cypher.notices), 모양(cypher.look), 브라우저 시작 페이지(cypher.home), Claude 실행 명령(cypher.claudeCommand), 보낸 프롬프트·최근 폴더·자주 쓰는 지시, 접어 둔 워크스페이스·사이드바 너비·찾기 방식, 브라우저 즐겨찾기(cypher.bookmarks)
%APPDATA%\dev.cypher.terminal창의 위치와 크기
실행 파일이 있는 폴더cypher.exe, cypher-bridge.exe와 묶음에 함께 든 파일(README 등). 업데이트 직후에는 이름을 바꿔 둔 옛 파일(*.old-*)이 다음 시작 때까지 남음

Cypher는 사용자의 설정 파일을 고치거나 덮어쓰지 않고(없을 때만 기본 파일을 만듦), 통계·오류 보고 같은 통신을 하지 않습니다. 업데이트 확인도 단추를 눌렀을 때만 합니다.

14. 막지 못하는 것

울타리는 Cypher 도구에 세운 것입니다. 그 바깥은 Cypher가 막을 수 없습니다.

  • 파일 직접 접근: Claude Code는 자기 권한 설정 안에서 이 컴퓨터의 파일을 읽고 씁니다. 다른 워크스페이스의 메모가 저장된 파일도 파일로는 읽을 수 있습니다. 이것은 Claude Code의 권한 설정으로 다룹니다.
  • 프로세스 조작: 세션 안에서 통로에 직접 접속해 다른 세션의 번호를 적는 평범한 방법은 막지만, 같은 Windows 사용자 권한으로 다른 프로세스 자체를 조작하는 것(부모 프로세스 위조, 코드 주입)까지 막지는 못합니다.
  • 셸 세션에서 돌린 다른 프로그램: 셸 세션에도 통로의 주소와 확인값이 환경 변수로 들어가므로(4절), 그 셸에서 실행한 프로그램은 그 세션의 이름으로 통로에 접속해 그 워크스페이스의 Cypher 도구를 쓸 수 있습니다. 믿을 수 없는 프로그램을 돌린다면 claude_in_shell = false로 끕니다.
  • 같은 폴더를 보는 HTTP 항목: HTTP 규칙은 폴더 기준이라, 두 워크스페이스가 같은 폴더의 요청 파일을 보면 함께 다루게 됩니다.
  • 업데이트의 믿음: 확인값은 GitHub가 알려 주는 값입니다. 묶음이 올라온 뒤에 바뀌지 않았다는 것과 이 저장소의 릴리즈에서 받았다는 것은 확인하지만, 릴리즈를 올리는 계정 자체가 탈취된 경우까지 막지는 못합니다(업데이트는 실행 파일의 서명을 따로 확인하지 않습니다).
