Cypher 구현 방식

Cypher가 어떤 조각으로 이루어져 있고, Claude Code 세션과 어떻게 이야기하며, 그룹이라는 울타리를 어떻게 지키는지를 그림으로 설명합니다. 기준: 0.11.0 (2026-11-13).

1. 전체 구성

Cypher는 실행 파일 두 개입니다. 창을 띄우는 cypher.exe와, Claude Code가 불러 주는 작은 심부름꾼 cypher-bridge.exe입니다.

  • 화면은 빌드 단계 없는 자바스크립트입니다. 사이드바의 항목과 그룹을 알고 있는 것은 화면뿐입니다.
  • 본체는 화면이 못 하는 일(프로세스 띄우기, 파일, 네트워크)을 합니다. 그룹에 관한 판단이 필요하면 화면에 물어봅니다.
  • 웹 페이지를 보여 주는 사이트 항목의 웹뷰에는 앱 명령 권한을 주지 않습니다.

2. 사이드바: 항목과 묶음

사이드바에 놓이는 것을 항목이라 부릅니다. 터미널 세션(Claude, PowerShell)과 메모, HTTP, 사이트, 이미지, 마인드맵, 문서가 있습니다. 항목은 둘 중 한 가지 묶음에 들어갑니다.

새 종류의 항목은 이름·아이콘과 화면을 만드는 함수(create(item, host, saved, onChange), 제목·저장할 상태·정리 함수를 가진 화면 객체를 돌려줌)를 ui/main.js의 KINDS에 올리면 사이드바·분할·그룹·복원에 그대로 들어갑니다.

3. Claude 세션과 이야기하는 길

Cypher는 Claude 세션을 띄울 때 claude --settings <파일> --mcp-config <파일>로 설정을 끼워 넣습니다(도구 연결인 --mcp-config는 설정에서 [browser] enabled = false로 끄면 붙이지 않습니다). 사용자의 settings.json은 건드리지 않습니다. 그 설정이 전달 프로그램을 세 가지 자리에 걸어 둡니다.

  • 통로에 접속하면 첫 줄에 확인값(실행할 때마다 새로 만드는 값), 둘째 줄에 세션 번호를 적습니다.
  • 전달 프로그램은 신호를 보낸 뒤 본체가 처리를 마치고 연결을 닫을 때까지(길어야 1.5초) 기다립니다. 그래서 "쓰기 직전" 신호는 Claude가 실제로 파일을 쓰기 전에 처리됩니다(본체가 1.5초 안에 처리하는 보통의 경우).
  • 도구는 21개입니다: 브라우저 13개, HTTP 2개, 항목 목록·마인드맵·메모·이미지·문서·알림 6개.
  • 그룹을 알아야 하는 도구는 본체가 화면에 물어서(mcp-request 이벤트) 답을 받습니다(20초 안에).

4. 누가 보냈는지 확인하기

통로로 오는 신호에 적힌 세션 번호는 보낸 쪽이 스스로 적은 값입니다. 확인값은 모든 세션이 알고 있으니, 번호만 믿으면 한 세션이 다른 세션인 척할 수 있습니다. 그래서 Cypher는 번호를 믿지 않고 접속한 프로세스가 누구의 자손인지를 직접 봅니다.

  • 순서: 확인값이 맞는지 본다 → 접속한 프로세스를 찾는다 → 조상을 따라 올라간다 → 적힌 번호와 같은 세션인지 본다.
  • 부모가 이미 끝났거나 번호가 다른 프로세스에 다시 쓰인 경우는 "만든 시각"을 비교해 걸러 냅니다(부모는 자식보다 먼저 만들어졌어야 합니다).

5. 다룰 수 있는 범위

Claude 세션이 Cypher 도구로 다룰 수 있는 것은 자기와 같은 그룹에 있는 항목뿐입니다. 규칙은 한 줄짜리 판정(canControl)에 모여 있습니다: 둘이 같은 이름 붙인 그룹에 있고, 대상이 터미널 세션이 아닐 것.

상황결과
같은 그룹의 메모·마인드맵·사이트·HTTP·문서다룰 수 있음
다른 그룹의 항목, 그룹 없는 항목거절. 목록에도 나오지 않음
다른 세션(Claude든 PowerShell이든)거절. 다루는 도구 자체가 없음
그룹 없는 세션새 메모·이미지·문서·마인드맵 놓기와 알림만
항목이나 세션을 다른 그룹으로 옮김그 순간부터 옛 그룹은 거절, 새 그룹은 허용(판정을 매번 새로 함)
부른 세션을 알 수 없는 요청거절

HTTP 도구는 폴더 기준입니다: 같은 그룹 HTTP 항목의 요청 폴더와 그 세션을 시작한 폴더의 요청 파일(폴더 바로 아래, http, .cypher\http)에만 씁니다.

사용자가 직접 하는 일(변경 내용에서 고른 줄을 세션에 넣기, 이미지 경로를 세션에 넣기)은 이 제한과 무관합니다. 제한은 "Claude가 도구로 하는 일"에만 겁니다.

6. 그룹마다 다른 브라우저

조작할 수 있는 탭만 나누면 로그인 상태가 샙니다(A 그룹에서 로그인한 사이트에 B 그룹의 Claude가 자기 브라우저로 가면 로그인돼 있음). 그래서 브라우저 프로필(쿠키·저장소가 담기는 폴더)을 그룹마다 따로 씁니다.

  • 어느 그룹이 어느 프로필 번호를 쓰는지는 화면이 기억합니다(cypher.profiles). 그룹 이름을 바꿔도 번호는 그대로라 로그인 상태가 유지됩니다.
  • 이미 있는 그룹에 합치면 합쳐진 쪽 항목은 그 그룹의 프로필을 씁니다.
  • 그룹을 없앴다가 같은 이름으로 다시 만들면 예전 프로필을 다시 씁니다.
  • 프로필마다 브라우저 엔진 프로세스가 따로 뜹니다(사이트 항목을 실제로 띄운 그룹만).
  • 어느 항목이 어느 프로필을 써야 하는지는 화면이 정해 본체에 알립니다. Claude의 도구 호출이 그와 다른 프로필을 들고 오거나(도구가 도는 사이에 항목이 옮겨짐) 그사이 항목이 닫혔으면 본체는 웹뷰를 만들지 않고 거절합니다.
  • 그룹을 없애도 프로필 폴더는 지우지 않습니다. 지우려면 Cypher를 끄고 site-profiles(chrome 엔진은 chrome-profiles) 아래의 폴더를 지웁니다. 폴더 이름은 번호라 어느 그룹의 것인지 드러나지 않으니, 가리기 어렵다면 모두 지우고 그룹마다 다시 로그인합니다.

7. 만든 파일을 사이드바에 놓기

Claude가 Write 도구로 새 파일을 만들면 종류에 맞는 항목으로 그 세션의 묶음에 놓고 알림으로 알려 줍니다. 보던 화면은 바꾸지 않습니다. "새 파일인지"는 쓰기 직전에 그 파일이 없었는지로 가립니다.

  • 숨김 폴더·빌드 폴더(.git, node_modules, target 등)인지를 볼 때, 세션이 일하는 폴더 안의 파일은 그 폴더 아래 부분만 보고(프로젝트 자체가 D:\build 같은 곳에 있어도 놓임) 밖의 파일은 경로 전체를 봅니다. 요청 파일 자리인 .cypher\http는 예외로 놓습니다.
  • 임시 폴더와 Claude·Cypher의 설정·데이터 폴더에 만든 파일은 놓지 않습니다.
  • 그룹 없는 세션이 만든 .http는 그 세션의 시작 폴더가 보는 자리(폴더 바로 아래, http, .cypher\http)의 것만 HTTP 항목이 되고, 다른 폴더의 것은 문서 항목이 됩니다.

8. 어디에 무엇을 저장하나

곳담는 것
%APPDATA%\cypher사용자의 것: 설정(config.toml), 메모, 마인드맵, 이미지, 그룹 틀
%LOCALAPPDATA%\cypher내부 상태: 세션에 넘기는 설정 파일, 기록(cypher.log), 되돌리기 전 차이, 그룹별 브라우저 프로필(site-profiles, chrome-profiles)
%LOCALAPPDATA%\dev.cypher.terminal본창과 그룹 없는 사이트 항목의 브라우저 저장소(공용 프로필). 화면의 저장소도 이 안에 있음
화면의 저장소(localStorage)열린 항목과 분할 배치, 그룹 목록, 그룹 → 프로필 번호, 알림 기록, 닫은 항목, 모양

Cypher는 사용자의 설정 파일을 고치거나 덮어쓰지 않고, 업데이트 확인·통계·오류 보고 같은 통신을 스스로 하지 않습니다.

9. 막지 못하는 것

울타리는 Cypher 도구에 세운 것입니다. 그 바깥은 Cypher가 막을 수 없습니다.

  • 파일 직접 접근: Claude Code는 자기 권한 설정 안에서 이 컴퓨터의 파일을 읽고 씁니다. 다른 그룹의 메모가 저장된 파일도 파일로는 읽을 수 있습니다. 이것은 Claude Code의 권한 설정으로 다룹니다.
  • 프로세스 조작: 세션 안에서 통로에 직접 접속해 다른 세션의 번호를 적는 평범한 방법은 막지만, 같은 Windows 사용자 권한으로 다른 프로세스 자체를 조작하는 것(부모 프로세스 위조, 코드 주입)까지 막지는 못합니다.
  • 같은 폴더를 보는 HTTP 항목: HTTP 규칙은 폴더 기준이라, 두 그룹이 같은 폴더의 요청 파일을 보면 함께 다루게 됩니다.
