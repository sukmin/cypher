# Cypher (사이퍼)

Claude Code 세션 여러 개를 한 창에서 띄우고 전환·감시하는 Windows용 업무 도구입니다.
사이드바에는 터미널 세션뿐 아니라 메모, HTTP 요청 같은 여러 종류의 항목을 놓을 수 있고, 업무 하나를 워크스페이스 하나로 묶어 그 안에 필요한 것을 모아 둡니다.
화면에 나온 웹 주소와 파일 경로를 클릭하면 브라우저나 탐색기가 열립니다.

## 빌드와 실행

Rust(MSVC)만 있으면 됩니다. Node는 필요 없습니다.

```
cargo build --workspace --release
target\release\cypher.exe
```

창 제목에 버전이 표시됩니다(`Cargo.toml`의 `[workspace.package] version`).
`cypher.exe`와 `cypher-bridge.exe`는 같은 폴더에 있어야 합니다(모델 표시·완료 알림이 전달 프로그램을 거칩니다).
`CYPHER_AUTOSTART=claude` 환경 변수를 주고 실행하면 실행 위치 폴더에서 세션이 바로 열립니다.

## 기능

| 기능 | 설명 |
|---|---|
| 항목 모아보기 | 사이드바에 터미널 세션(Claude, PowerShell, SSH 등), 메모, HTTP, 사이트(브라우저), 이미지, 마인드맵, ERD, 문서, 할 일, 명령, 표, 코드, 헥사 항목을 놓음(**SSH는 워크스페이스마다 한 줄**이고, SSH 세션들은 그 줄이 여는 SSH 창의 탭임). **지금 화면(스테이지)에 보이는 항목**은 사이드바에서 굵은 왼쪽 띠와 옅은 바탕, 굵은 이름으로 보이고 이름 아랫줄에 표가 붙음: 입력이 가는 창의 항목은 강조색 테두리와 **[보는 중]**, 나란히 보이는 다른 창의 항목은 **[화면]**. 모든 세션과 항목은 이름 붙인 워크스페이스 안에 놓임(업무 하나가 워크스페이스 하나). 사이드바의 빈 곳을 누른 뒤 ↑/↓(Home/End)로 항목 사이를 오감. 항목을 다른 줄의 위·아래로 끌면 순서가 바뀌고(다른 워크스페이스의 줄이면 그 워크스페이스로 옮김), 이 순서는 다시 시작해도 유지되며 Ctrl+Tab도 이 순서를 따름. 워크스페이스도 머리를 끌어 다른 워크스페이스의 위·아래에 놓으면 순서가 바뀜(오른쪽 클릭 메뉴의 "위로·아래로 옮기기"로도 됨). **접어 둔 워크스페이스는 이름만 보이는 납작한 한 줄**임: 폴더 줄·할 일 진행·서브에이전트 수·+ 단추·항목 수는 펼쳤을 때만 보이고(메뉴는 접힌 채로도 오른쪽 클릭으로 엶), 그 안에 대기 중이거나 봐야 할 세션이 있으면 이름 뒤에 점 하나가 찍힘 |
| 빠른 이동 | Ctrl+Shift+K로 찾기 창을 열어 항목의 이름·별칭·워크스페이스·폴더나 앱의 명령(새 세션, 모양, 설정 …)을 글자로 찾아 Enter로 감. 초성으로도 찾음(`ㄱㅈ` → 결제). 아무것도 치지 않으면 최근에 본 순서라, 열자마자 Enter를 누르면 바로 전에 보던 항목으로 돌아감 |
| 워크스페이스 안에서만 만들기 | 세션과 항목은 워크스페이스 밖(루트)에 만들 수 없음. 사이드바 맨 위에는 [+ 워크스페이스]만 있고, 세션·항목은 워크스페이스 머리의 +(또는 워크스페이스 오른쪽 클릭 메뉴)로 그 워크스페이스 안에 만듦. 어느 워크스페이스에 생길지 눈에 보이는 곳에서만 만들게 해서, 엉뚱한 워크스페이스에 세션이 생기지 않게 한 것임. [+ 워크스페이스]는 이름을 묻고 이어서 그 워크스페이스의 세션이 시작될 폴더를 고르게 함(여기서 고른 폴더는 바꿀 수 없음. 취소하면 폴더 없이 만들어지고, 나중에 폴더 줄이나 워크스페이스 오른쪽 클릭 → "워크스페이스 폴더 정하기…"로 한 번 정할 수 있음). 단축키(Ctrl+Shift+T/D/O/H/M)와 빠른 이동의 "새 …" 명령은 지금 보고 있는 항목의 워크스페이스에 만들고(워크스페이스가 하나뿐이면 그 워크스페이스), 어느 워크스페이스인지 정할 수 없으면 만들지 않고 알려 줌. 끌어다 놓은 파일도 워크스페이스(놓은 워크스페이스, 또는 보고 있는 항목의 워크스페이스) 안에만 항목이 됨. 항목을 다른 워크스페이스로 옮길 수는 있지만 워크스페이스 밖으로 뺄 수는 없고, 세션·항목이 남아 있는 워크스페이스를 지우면("워크스페이스 삭제") 모두 닫고 지울지 물어본 뒤 한꺼번에 닫고 지움(닫기를 취소한 항목이 남으면 워크스페이스를 그대로 둠. 삭제한 워크스페이스의 기록은 3년 동안 보관함 — 아래 "삭제한 워크스페이스 기록"). **이전 버전에서 워크스페이스 없이 쓰던 세션·항목**(폴더별 묶음)은 다시 시작할 때 `root`라는 워크스페이스로 모이고, 그때 닫아 둔 워크스페이스 없는 항목을 다시 열어도 `root`에 들어감. `root`도 보통 워크스페이스라 이름을 바꾸거나 항목을 다른 워크스페이스로 옮길 수 있음. `CYPHER_AUTOSTART`로 바로 여는 세션도 `root` 워크스페이스에 열림 |
| 북마크 | 항목에 숫자(0~9)를 붙여 두고 Ctrl+숫자로 바로 감. Ctrl+Shift+숫자를 누르면 지금 보는 항목에 그 숫자가 붙고(같은 숫자를 다시 누르면 풂, 다른 항목이 쓰던 숫자면 옮겨 옴), 항목 오른쪽 클릭 메뉴의 숫자 줄로도 지정함. 붙인 숫자는 사이드바의 그 줄 이름 앞과 스테이지 표시줄·창 제목 줄에 색 배지로 보임. Ctrl+숫자는 그 항목을 화면에 띄우고(화면에 없으면 지금 창 자리에, 쉬는 세션이면 재개, 접힌 워크스페이스면 폄) 초점을 줌. 숫자 하나에 항목 하나이고 다시 시작해도 유지됨. 닫은 항목을 다시 열면 그 숫자가 비어 있을 때 되돌아옴. 그 숫자의 북마크가 없을 때의 Ctrl+숫자는 가로채지 않음(문서·ERD·마인드맵·메모의 Ctrl+0은 그대로 동작하고, 0번 북마크를 만들면 Ctrl+0은 북마크로 감). Windows가 Ctrl+Shift+0을 입력 언어 전환에 쓰고 있으면 그 키는 앱에 오지 않으므로, 0번은 오른쪽 클릭 메뉴로 지정함 |
| 닫은 항목 다시 열기 | 닫은 항목을 30일 동안 기억함. Ctrl+Shift+R은 가장 나중에 닫은 것을 같은 워크스페이스·폴더·별칭·색으로 바로 다시 열고, 도구 → "닫은 항목 다시 열기"는 목록에서 고름. Claude 세션은 하던 대화를 이어 열고(대화가 없던 세션·다른 터미널은 같은 폴더에서 새로 시작), 메모·마인드맵·ERD·할 일·이미지는 보관해 둔 내용으로, 사이트·HTTP·문서·표는 보던 주소·파일로, 명령은 적어 둔 명령으로 엶(실행하지는 않음). 종료된 세션은 오른쪽 클릭 → "다시 시작"으로 사이드바와 화면의 같은 자리에서 다시 띄움 |
| 삭제한 워크스페이스 기록 | **삭제한 워크스페이스는 그때의 모습을 3년 동안 보관함**(항목이 하나도 없던 워크스페이스는 남길 것이 없어 기록하지 않음. 도구 → "삭제한 워크스페이스 기록…", 사이드바 빈 곳 오른쪽 클릭, 빠른 이동). 기록 하나가 파일 하나임: `%APPDATA%\cypher\history\<삭제한 시각>-<번호>.json`(워크스페이스 이름·폴더·삭제한 때·보관 기한·항목 목록). **글로 보관할 수 있는 것은 내용째 담음**: 메모·할 일·마인드맵·ERD의 글, 명령 항목의 명령. 세션은 프로필·폴더·이어 갈 Claude 대화 번호(SSH는 서버 주소·포트·이름)만, **산출물(사이트·HTTP·문서·표·코드·헥사·이미지)은 이름과 가리키던 주소·경로만 담고 파일 내용은 보관하지 않음**. 기록 창에서 목록(최근에 삭제한 것이 앞)을 보고, 하나를 누르면 그때 있던 항목과 보관해 둔 글을 보고 [복사]할 수 있음. "워크스페이스로 되살리기…"는 이름을 묻고(있는 워크스페이스 이름이면 거기에 더함) 메모·할 일·마인드맵·ERD·명령을 보관해 둔 글로, 사이트·HTTP·문서 등은 그 주소·파일로 다시 만들고, 세션은 띄우지 않고 쉬는 세션으로 놓음(누르면 재개하고 Claude 세션은 그때 하던 대화를 이음). 되살려도 기록은 남고, 기록의 ×나 "이 기록 지우기…"로 지움. 3년이 지난 기록은 Cypher를 시작할 때 지움. 닫은 항목 목록(30일)과 따로 둠 |
| 별칭 | 항목을 두 번 누르거나 ✎ 단추, 오른쪽 클릭 메뉴로 사이드바의 그 줄에서 바로 별칭을 붙임. 세션에는 영향이 없고 사이드바·창 제목·알림에 보이는 이름만 바뀜. 원래 이름(종류·폴더)은 옆에 흐리게 남음 |
| 사이드바 너비 | 사이드바와 화면 사이의 경계를 끌어 너비 조절(두 번 누르면 기본 너비). 다시 시작해도 유지 |
| 프롬프트 편집기 | 화면에 세션 하나만 보일 때(분할하지 않았을 때) 세션 아래에 글 편집기가 놓임(SSH 세션에는 두지 않음: 터미널을 그만큼 넓게 씀). 긴 프롬프트를 여기서 쓰고 "프롬프트" 단추(Ctrl+Enter)를 누르면 그 세션의 입력창에 들어감. "바로 전송"(기본으로 켜져 있음)이 켜져 있으면 Enter까지 눌러 보내고, 끄면 입력창에 넣기만 함. 쓰던 글은 세션마다 기억하고, 높이 조절·접기 가능. 위쪽 테두리를 끌어 높이를 바꾸는 동안에는 세션 화면의 줄 수를 그대로 두고, 끌던 손이 멈추면(그리고 놓으면) 새 높이에 맞춘 뒤 Claude 세션의 화면을 다시 맞춤(Claude Code가 새 줄 수로 처음부터 다시 그려 내용이 잘리거나 아래가 비지 않고, 지난 출력에 겹친 줄은 지움). 접기·펴기와 두 번 눌러 기본 높이로 돌릴 때도 같음. 보낸 프롬프트는 50개까지 기억해 Alt+↑/↓로 넘겨 보거나 "기록" 단추에서 골라 다시 씀. 클립보드의 그림도 여기서 붙여넣을 수 있음(Ctrl+V): Claude 세션이면 그 세션의 입력창에 그림으로 붙고(`[Image #n]`), 그 밖의 세션이거나 Ctrl+Shift+V면 PNG로 저장한 경로가 편집기에 들어감 |
| 메모 | 글자 편집기 항목. 찾기·바꾸기(대/소문자, 단어 단위, 정규식과 `$1` 그룹 바꾸기), 줄로 이동, 시간/날짜, 자동 줄 바꿈, 확대/축소, 상태 표시줄(줄/열, 글자 수, 200자 원고지 매수, 줄 끝, 인코딩), JSON 정리, 보이지 않는 문자 찾기·정리. 파일 열기·저장은 인코딩(UTF-8, UTF-8 BOM, UTF-16, CP949)과 줄 끝을 유지. 쓰던 내용은 계속 임시 저장되어 다시 시작해도 돌아옴. 파일에 연결된 메모는 그 파일이 다른 곳(Claude 세션, 다른 편집기)에서 바뀌면, 고치지 않은 메모는 스스로 다시 읽고, 고치던 메모는 저장할 때 "다시 읽기 / 덮어쓰기"를 물음(다시 읽으면 고치던 글은 30일 보관). 같은 파일을 메모로 두 번 열면 이미 열린 메모로 감 |
| 사이트(브라우저) | "+ 사이트"를 누르면 주소를 묻지 않고 빈 페이지가 바로 스테이지에 뜨고, 위의 주소 칸에 주소(또는 검색어)를 쳐서 감. 설정 → "브라우저 시작 페이지…"에 주소를 적어 두면 새 사이트 항목이 빈 화면 대신 그 주소로 열림("chrome" 엔진의 브라우저도 처음 띄울 때 그 주소로 엶. 비우면 다시 빈 화면). 주소 칸 옆에 캡처, 즐겨찾기(☆), "Claude에게"(같은 이름 붙인 워크스페이스의 Claude 세션에 이 브라우저를 넘김. 세션이 여러 개면 고름. 워크스페이스에 넣지 않은 사이트 항목은 넘길 수 없음), "외부 브라우저"(지금 주소를 Windows 기본 브라우저로 엶) 단추. 뒤로·앞으로·새로 고침, 처음 간 주소로 돌아가기. 보던 주소와 제목을 기억하고 다시 시작하면 되살림. 로그인 상태는 같은 워크스페이스의 사이트 항목끼리만 함께 씀(워크스페이스마다 브라우저 프로필이 따로. 워크스페이스 없는 사이트 항목끼리는 공용 프로필). 메뉴·대화상자가 열려 있는 동안에는 페이지를 잠시 가림 |

| 할 일 | 업무(워크스페이스)의 체크 목록("+ 할 일"). 비어 있는 동안에는 빈 영역에 체크 목록이 든 Markdown·글자 파일을 끌어다 놓거나 [파일에서 가져오기…]로 골라 그 내용으로 채울 수 있음(원본 파일은 바뀌지 않음). 할 일은 창 맨 아래의 입력 칸에 적고 Enter로 더하고(비어 있는 동안에는 그 칸을 강조하고 바로 위에 안내 줄을 보여 주며, 빈 영역의 [할 일 적기 ↓]를 누르면 그 칸으로 감), 체크 칸이나 Space로 끝냄을 표시함. 두 번 누르기·Enter·F2로 그 자리에서 고치고(고친 뒤 Enter를 누르면 바로 아래에 이어 적음, 비우면 지워짐), Ctrl+Enter로 아래에 넣기, Tab/Shift+Tab으로 하위 일로·한 단계 위로, Alt+↑/↓로 순서 바꾸기(하위 일과 함께), Delete로 지우기, Ctrl+Z/Y로 되돌리기. [끝낸 일 숨기기], [정리](끝낸 일 지우기·모두 체크 풀기), [복사], [Claude에 넣기](남은 할 일을 세션 입력창에. 줄의 [→ Claude]는 그 할 일 하나). 사이드바의 그 줄 아래에 `3/7 완료`가, 워크스페이스 머리에는 그 워크스페이스의 할 일을 모두 합친 `☑ 3/7`이 보임(다 끝내면 녹색. 접어 둔 워크스페이스는 이름만 보임). 내용은 Markdown 체크 목록 글 그대로라(`# 제목`, `## 구역`, `- [ ] 할 일`, `- [x] 끝낸 일`, 두 칸 들여쓴 하위 일, 그 밖의 줄은 설명) [글로 편집](Ctrl+E)으로 글을 직접 고칠 수 있고 다른 곳에서도 그대로 읽힘. 자동 저장되고(`%APPDATA%\cypher\todos`), 같은 워크스페이스의 Claude 세션이 `todo_write`로 만들거나 더하고 `todo_check`로 체크함 |
| 명령 | 자주 돌리는 명령(시험·빌드·개발 서버)을 항목으로 두고 실행함. "+ 명령"은 묻지 않고 빈 항목을 만들고, 위 칸에 명령을 적고 Enter를 누르면 실행함. 빈 영역에 스크립트·실행 파일을 끌어다 놓거나 [실행할 파일 고르기…]로 고르면 그 파일을 실행하는 명령을 채워 줌(▶를 눌러야 돎). 명령 한 줄을 그 항목의 폴더에서 PowerShell로 돌리고(설정의 `powershell` 프로필이 pwsh이면 그것으로), 출력은 그 화면의 터미널에 보임. 끝나면 종료 코드로 성공·실패를 가려 화면과 사이드바의 그 줄에 `실행 중 · 14:02 시작` / `성공 · 12초` / `실패 · 종료 코드 101 · 8초` / `멈춤`으로 보이고(종류 기호의 색도 바뀜), 보고 있지 않을 때 실패했거나 10초 넘게 걸린 명령은 알림으로 알려 줌. [▶ 실행](명령 칸의 Enter, Ctrl+Enter) · [■ 멈춤](프로세스를 끝냄) · [▶ 다시 실행]. 실행 중에는 터미널에 입력할 수 있음(확인 질문에 답하기, Ctrl+C). [Claude에 넣기]는 명령·폴더·상태와 출력의 끝 60줄(고른 글이 있으면 그 글)을 Claude 세션 입력창에 넣고, [출력 복사]는 출력 전체를 복사함. 다시 시작한 뒤·닫은 항목을 다시 연 뒤·워크스페이스 틀을 펼친 뒤에는 명령만 되살리고 스스로 실행하지 않음. 같은 워크스페이스의 Claude 세션은 `run_output`으로 상태와 출력을 읽을 수 있고, 실행·멈춤은 사용자만 함 |
| 표 | CSV·TSV·JSON 파일을 표로 봄. "+ 표"는 묻지 않고 빈 항목을 만들고, 그 빈 영역에 파일을 끌어다 놓거나 [파일 고르기…]로 고르거나 경로를 적어 볼 파일을 정함(사이드바에 `.csv`·`.tsv` 파일을 끌어다 놓아도 표 항목이 됨). 열 이름을 누르면 정렬(오름 → 내림 → 원래 차례. 숫자 열은 크기로, 쉼표 자릿수·% 포함), 거르기 칸(Ctrl+F)에 낱말을 빈칸으로 나눠 적으면 모두 든 줄만 남김. 칸을 누르면 전체 값이 아래에 보이고 방향키로 옮기며 Ctrl+C로 복사, 오른쪽 클릭으로 줄 복사·이 값으로 거르기. [복사]는 보이는 줄을 탭으로 나눈 글(스프레드시트용)이나 Markdown 표로 복사. CSV의 구분자(쉼표·탭·쌍반점·세로줄)는 첫 줄에서 알아보고 큰따옴표로 감싼 값(구분자·줄 바꿈·`""`)을 읽으며, [첫 줄은 제목]으로 첫 줄을 열 이름으로 쓸지 고름. JSON은 객체의 배열(열 = 키)·배열의 배열·객체 안의 첫 배열을, `.jsonl`·`.ndjson`은 한 줄에 하나씩 읽음. 파일이 바뀌면 정렬·거르기·보던 자리를 지킨 채 스스로 다시 읽음. 8MB·10만 줄·200열까지. 고치지는 않음([메모로 편집]). 같은 워크스페이스의 Claude 세션이 `table_show`로 놓음 |
| 코드 보기 | 프로젝트의 코드를 읽는 항목("+ 코드…"). 만들 때 볼 폴더를 고르고, 그 폴더 아래의 파일을 한 번 읽어 색인(정의와 낱말)을 디스크에 만들어 둠(`%LOCALAPPDATA%\cypher\code-index`) — 정의로 가기·쓰는 곳 찾기·기호 찾기가 프로젝트를 다시 훑지 않고 답하고, 같은 폴더를 다시 열거나 앱을 다시 켜도 다시 만들지 않고(전에 만든 색인을 읽어 와 바뀐 파일만 다시 읽음), 큰 프로젝트에서도 메모리를 조금만 씀. Claude 세션이 고친 파일은 바로, 그 밖에 바뀐 파일은 조금 뒤 다시 읽어 맞춤. 색인이 어긋난 것 같으면 위쪽의 [재색인]으로 처음부터 다시 만듦. 정의로 가기는 이름만 보지 않고 받는 쪽의 자료형을 따라감: `orderMapper.insert(…)`면 `orderMapper`의 선언(지역 변수·인자·필드)에서 자료형을 읽어 그 자료형(과 상위 자료형)의 `insert`로, `a.b().c()`면 `b`의 반환형을 이어서, 자료형 이름은 import·use가 가리키는 파일의 것으로 감(Java·Rust 중심, Kotlin·TypeScript·Python·C 계열도 같은 방식). Lombok·record처럼 `getName()`의 정의가 없으면 필드로 가고, 라이브러리(`java.util`, `std`)의 것이면 엉뚱한 곳으로 가지 않고 "이 폴더 밖의 것"이라고 알림. 자료형을 알 수 없을 때만 이름이 같은 정의를 가까운 순서로 늘어놓아 고르게 함. 구현으로 가기(Ctrl+Alt+B): 인터페이스·트레이트(와 그 메서드)를 구현한 것으로, 인터페이스의 메서드 선언 위에서 정의로 가기를 해도 구현으로 감. MyBatis 매퍼는 인터페이스의 메서드와 XML의 구문(`<select id="…">`)을 서로 오감. 쓰는 곳 찾기는 자리마다 어느 클래스·메서드 안인지 함께 보여 줌. 나무에서 폴더 하나만 품은 폴더는 한 줄로 이어 보임(`java/com/example/shop`). 파일마다 항목이 생기지 않고 프로젝트 폴더 하나를 통째로 봄(고치지는 않음). 왼쪽에 프로젝트 나무와 이 파일의 구조, 오른쪽에 탭으로 연 코드. 나무와 탭의 파일 이름 앞에 종류(확장자)마다 색이 다른 표식(`J` 하늘, `R` 주황, `JS` 노랑, `TS` 파랑 등 — IntelliJ의 아이콘 색을 따름). 탭 오른쪽 클릭 메뉴: 탭 닫기, 다른 탭 모두 닫기, 왼쪽·오른쪽 탭 모두 닫기, 바뀌지 않은 파일의 탭 닫기, 모든 탭 닫기, 나무에서 보기, 경로 복사. 문법 강조(Java, Rust, JavaScript/TypeScript, Vue, HTML, CSS·SCSS, Kotlin, Go, Python, C 계열, C#, SQL, 셸, JSON·YAML·TOML, Markdown — 바깥 라이브러리 없이 직접 읽음), 줄 번호, 바뀐 줄 표시(git 기준: 더한 줄 녹색·고친 줄 파랑·지운 자리 빨강), 나무와 탭의 바뀐 파일 색, 나무와 [바뀐 파일] 목록의 파일 이름 옆에 종류 표(**수정·추가·삭제**), [바뀐 파일]로 바뀐 파일과 그 안의 **바뀐 곳**만 모아 보기: **고친 파일·추가한 파일·삭제한 파일**로 묶어 나눠 보이고(묶음마다 파일 수. 그 안에서는 Claude 세션이 방금 쓴 파일이 앞), 바뀐 곳마다 줄 범위·더한 줄·지운 줄 수가 보임. **차이 보기**: [바뀐 파일] 보기에서 파일이나 바뀐 곳을 누르면 그 파일이 **한 화면에서 차이(diff)로** 보임 — 지운 줄은 **빨강**(−), 더한 줄은 **초록**(+)이고 줄 번호 칸에 예전·지금 줄 번호가 함께 적힘. 바뀌지 않은 줄은 바뀐 곳의 앞뒤 3줄만 보이고 나머지는 접힘(누르면 펼침, [모두 펼치기]로 파일 전체). 추가한 파일은 전체가 초록, 삭제한 파일은 지우기 전 내용 전체가 빨강. 위쪽의 **[차이]** 단추나 F8로 차이 보기 ↔ 코드 그대로 보기를 오가고([바뀐 파일] 보기를 켜면 함께 켜짐), Ctrl+클릭은 그 줄을 코드에서 봄. 코드 그대로 보기에서는 바뀐 곳을 누르면 그 자리로 가며 지운 줄이 그 아래에 "이전 내용"으로 뜸. F7/Shift+F7로 다음·이전 바뀐 곳(파일을 넘어감), 줄 번호 옆의 색 표시를 눌러도 이전 내용이 뜸. 지워진 파일은 지우기 전의 내용을 보여 줌. **정의로 가기**(Ctrl+클릭, F12, Ctrl+B): 지역 변수·인자는 그 함수 안에서, 그 밖에는 프로젝트 전체에서 찾고, 같은 이름이 여럿이면 가까운 것(같은 파일, `자료형.이름`의 자료형이 감싼 것, 같은 폴더, 가져다 쓰는 파일)을 앞에 세워 고르게 함. 정의 위에서 누르면 쓰는 곳을 보여 줌. **쓰는 곳 찾기**(Alt+F7): 정의·쓰는 곳·주석과 문자열 안을 가려 파일별로 보여 주고 누르면 그 자리로. 뒤로·앞으로(Alt+←/→), 파일 찾기(Ctrl+P, `이름:줄번호`), 기호 찾기(Ctrl+T, 머리글자도 됨), 이 파일의 구조(Ctrl+F12), 줄로 가기(Ctrl+G), 이 파일에서 찾기(Ctrl+F), 프로젝트 전체에서 찾기(Ctrl+Shift+F, 대/소문자·단어·정규식), 누른 이름과 같은 이름 표시, 경로와 줄 번호(고른 코드)를 Claude 세션 입력창에 넣기. 위쪽의 글꼴 칸에서 코드의 글꼴과 글자 크기를 앱의 글꼴과 따로 정함(Ctrl+휠, Ctrl+더하기/빼기/0). 파일이 바뀌면 보던 자리를 지킨 채 스스로 다시 읽음. 정의와 쓰는 곳은 언어 서버 없이 글자의 모양으로 찾으므로, 자료형을 따져야 알 수 있는 것(같은 이름의 메서드 가운데 어느 것인지)은 가리지 못함 |
| SSH 세션 | 워크스페이스 머리의 + → "+ SSH 세션…". **SSH는 워크스페이스마다 하나**: 사이드바에는 워크스페이스마다 SSH 줄이 하나만 놓이고, 그 워크스페이스에서 여는 SSH 세션은 몇 개든 그 줄이 여는 SSH 창의 탭이 됨(이미 SSH가 있는 워크스페이스의 + 메뉴는 "서버에 더 접속… (이 워크스페이스 SSH의 새 탭으로)"로 바뀌고, SSH 줄의 +로도 탭을 더함). | 화면에서 찾기 | Ctrl+Shift+F. 치는 대로 찾고 찾은 개수와 지금 몇 번째인지(3/15)를 보여 줌. 대/소문자 구분(Alt+C)·정규식(Alt+X)을 켤 수 있고 다음에도 기억함 |
| 워크스페이스 폴더 | 워크스페이스마다 세션이 시작될 폴더를 정함. 사이드바의 워크스페이스 이름 바로 아래에 그 워크스페이스의 폴더 줄이 보임(접어 둔 워크스페이스는 이름만 보이고, 펼치면 폴더 줄이 나옴. 경로가 길면 끝부분이 보이고, 정하지 않았으면 "폴더를 정하지 않음"). [+ 워크스페이스]로 워크스페이스를 만들 때 고르고, **한 번 정한 폴더는 바꾸거나 풀 수 없음**(다른 폴더에서 일하려면 그 폴더로 새 워크스페이스를 만듦). 폴더 줄의 **[폴더]** 단추(또는 경로)를 누르면 그 폴더가 탐색기에서 열림(워크스페이스 머리 오른쪽 클릭 → "워크스페이스 폴더 열기 (탐색기)"도 같음). 만들 때 폴더를 고르지 않은 워크스페이스만 폴더 줄에서 한 번 정할 수 있음: ▾(또는 글을 누름)로 지금 항목의 폴더·최근 폴더에서 고르거나 "폴더…"로 다른 폴더를 고름. 정해 두면 그 워크스페이스에서 여는 세션이 그 폴더에서 시작하고, 워크스페이스 머리의 +로 더하는 다른 항목도 그 폴더를 따름. 정하지 않은 워크스페이스는 그 워크스페이스에 이미 있는 항목의 폴더를, 빈 워크스페이스면 기본 폴더(사용자 폴더)를 씀. 워크스페이스 이름을 바꾸면 따라가고, 워크스페이스를 없애면 함께 지워짐. 정해 둔 폴더가 없어졌으면(지워졌거나 옮겨짐) 기본 폴더에서 시작하고 알려 주며, 이때만 [폴더]를 누르면 다시 정할지 물어봄 |
| Claude 실행 명령 | 설정 → "Claude 실행 명령…"에 "+ Claude"로 여는 세션을 띄울 명령을 적음(예: `claude --dangerously-skip-permissions`, 감싼 스크립트나 다른 경로의 실행 파일. 빈칸이 든 경로나 인자는 큰따옴표로 감쌈. 작은따옴표와 `\"`는 묶음으로 보지 않음). Cypher는 이 명령 뒤에 자기 인자(`--settings`, `--mcp-config`, `--resume`)를 붙여 띄움. 비우면 기본 명령(`claude`). 이제부터 여는 세션에 적용. 프로그램은 PATH에서 찾고(실행 파일, 배치 파일 `.cmd`·`.bat`, PowerShell 스크립트 `.ps1` — 이름만 적어도, 확장자나 경로까지 적어도 됨), 파일로 찾지 못한 이름은 PowerShell의 명령으로 실행해 PowerShell 프로필에 만들어 둔 별칭·함수도 쓸 수 있음(PowerShell 스크립트는 사용자의 실행 정책대로 돎). 경로의 `%USERPROFILE%`·`~`를 풀고, 빈칸이 든 경로를 따옴표 없이 적어도 실제로 있는 파일까지를 프로그램으로 봄. 그 명령으로 띄우지 못하거나 뜨자마자 오류로 끝나면 세션 화면에 어디서 고치는지 알려 줌 |
| 그 밖에 | 출력 저장(지금까지 화면에 남은 것), 동시 입력(Ctrl+Shift+B: 나란히 보이는 모든 세션 · SSH 창 위쪽의 [≫ 동시 입력]: SSH 세션끼리만), 세션 오른쪽 클릭 메뉴의 "같은 폴더에 새 세션"·"폴더를 탐색기에서 열기"·"폴더 경로 복사" |

## 메뉴

사이드바 맨 위에는 [+ 워크스페이스] 단추만 있고, 세션과 항목(Claude, PowerShell, SSH, 메모, HTTP, 사이트, 이미지, 마인드맵, ERD, 문서, 할 일, 명령, 표, 코드, 헥사)은 워크스페이스 머리의 +로 그 워크스페이스 안에 만듭니다. 사이드바 아래에는 대기·알림·변경 내용 단추가 있습니다.
브라우저는 따로 뜨는 창이 아니라 사이드바의 사이트 항목입니다.
빠른 이동, 닫은 항목 다시 열기, 삭제한 워크스페이스 기록, 알림 기록, 타이머·알람, 워크스페이스 틀, 자주 쓰는 지시, 동시 입력, 기억 내보내기·가져오기는 창 상단의 도구 메뉴에, 단축키 보기와 Cypher 업데이트, Cypher 정보(지금 버전·GitHub 주소·라이선스·릴리즈 페이지)는 도움말 메뉴에 있습니다.
설정 메뉴에서는 모양(테마·글꼴·글자 크기), 브라우저 시작 페이지, Claude 실행 명령을 바꾸고, Cypher 설정 파일과 Claude Code의 사용자 공통 설정(`~/.claude/settings.json`)·공통 지침(`~/.claude/CLAUDE.md`)을 엽니다.

## 설정

`%APPDATA%\cypher\config.toml`(상단 메뉴의 설정 → Cypher 설정 파일 열기). 고친 뒤 다시 시작하면 적용됩니다.
터미널 기본 글꼴, 링크 클릭 방식, 편집기 명령(`code -g {file}:{line}:{col}`), 알림, 세션 복원, Claude가 만든 파일을 사이드바에 놓을지(`show_created`), 되살린 세션을 누른 것만 재개할지(`restore_on_click`), 지금 쓰는 도구를 사이드바에 보일지(`activity`), 셸 세션에서 직접 띄운 Claude에도 붙을지(`claude_in_shell`), 창 자석, 브라우저(엔진 포함), SSH(`[ssh] engine`: 내장 SSH·OpenSSH, `keepalive`: 연결 확인 간격), 프로필 추가를 정할 수 있습니다.

테마·글꼴·글자 크기는 설정 파일이 아니라 설정 → 모양에서 바꿉니다(바로 적용).
글자를 다루고 저장할 때의 인코딩은 UTF-8이 기본입니다: 새 메모·마인드맵·HTTP 요청 파일·출력 저장은 UTF-8로 쓰고, 다른 인코딩으로 된 파일은 읽을 때 알아보고 엽니다(메모는 그 파일의 인코딩을 지켜 저장). PowerShell·cmd 세션은 다른 프로그램과 주고받는 글자를 UTF-8로 맞춥니다(`[session] utf8 = false`로 끔). Claude 세션은 건드리지 않습니다.

메모의 쓰던 내용은 `%APPDATA%\cypher\memos`에 임시 저장됩니다. 닫은 메모는 바로 지우지 않고 `memos\closed`에 30일 동안 둡니다.

이 파일은 버전이 바뀌어도 그대로 쓰입니다. Cypher는 파일이 없을 때만 기본 파일을 만들고, 이미 있는 파일은 고치거나 덮어쓰지 않습니다.
모르는 항목은 무시하고 빠진 항목은 기본값을 씁니다. 새 버전에서 늘어난 항목은 같은 폴더의 `config.example.toml`에서 볼 수 있습니다(실행할 때마다 그 버전의 예시로 갱신).

사이드바 항목의 종류는 `ui/main.js`의 `KINDS`에 등록합니다. 새 종류는 화면을 만드는 함수 하나
(`create(item, host, saved, onChange)` → `{ ready, focus, title, state, close, dispose }`)를 올리면 사이드바·분할·워크스페이스·복원에 그대로 들어갑니다.

모델·effort·한도·완료 알림은 세션을 띄울 때 `claude --settings <파일>`로 상태줄과 훅을 주입해서 받습니다.
사용자의 `settings.json`은 건드리지 않습니다.

## 쓰던 상태줄(HUD)과 함께 쓰기

Cypher는 모델·effort 등을 받으려고 Claude Code의 상태줄 자리에 전달 프로그램을 넣습니다.
그 자리는 하나뿐이지만, 이미 쓰던 상태줄이 있으면 전달 프로그램이 정보를 Cypher로 넘긴 뒤 그 명령을 이어서 실행해 출력을 그대로 내보냅니다.
그래서 세션 화면에는 쓰던 상태줄이 그대로 보이고, Cypher의 표시도 함께 동작합니다.

- 원래 상태줄은 Claude Code의 우선순위대로 찾습니다: 폴더의 `.claude/settings.local.json` → 폴더의 `.claude/settings.json` → 사용자 공통 `~/.claude/settings.json`.
- 여백(`padding`)과 갱신 주기(`refreshInterval`)는 원래 설정을 따릅니다. Cypher는 따로 갱신 주기를 걸지 않습니다. 상태줄은 일이 생길 때마다(세션 시작, 새 답변, `/compact`, 권한 모드 변경 등) Claude Code가 돌리고, 쉬는 동안에는 원래 상태줄이 주기를 정해 두었을 때만 돕니다. 그래서 쉬는 동안 `/model`·`/effort`로 바꾼 것은 다음 답변이 올 때 사이드바에 보입니다.
- 원래 상태줄 명령은 10초 안에 끝나야 합니다. 넘기면 그 명령이 띄운 것까지 끝냅니다(멈춘 명령이 갱신마다 쌓이지 않게. Git Bash가 띄운 프로그램처럼 부모가 먼저 끝난 프로세스도 함께 끝냄).
- 원래 상태줄의 갱신 주기는 1초 이상의 수일 때만 따릅니다. 0이나 수가 아닌 값은 Claude Code처럼 "주기 없음"으로 읽습니다.
- 기존 훅, 플러그인, MCP 서버는 원래부터 그대로 함께 동작합니다.

## 보안 규칙

터미널 출력과 웹 페이지는 신뢰할 수 없는 입력으로 다룹니다.

- 링크는 `http`, `https`, `file`만 엽니다.
- 경로는 실제로 존재할 때만 링크가 됩니다.
- 실행 파일과 스크립트는 열지 않고 탐색기에서 보여 주기만 합니다.
- 네트워크 경로(`\\서버\…`)는 존재 확인도 하지 않습니다.
- 사이트 항목은 웹 주소(`http`, `https`)와 이 컴퓨터에 있는 HTML 파일(`.html`, `.htm`)만 엽니다. 다른 로컬 파일과 네트워크 경로의 파일은 열지 않고, 열 수 없는 파일 경로를 검색어로 넘기지도 않습니다.
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령(터미널 입력, 파일 열기 등)을 부를 수 없습니다. 권한은 본창의 화면에만 줍니다(`crates/cypher-app/build.rs`).
- 본창의 화면에는 보안 정책(CSP)이 걸려 있어 화면 코드가 바깥과 통신하거나 바깥의 글줄·그림을 불러올 수 없습니다.
- 전달 프로그램이 접속하는 통로는 이 컴퓨터 안(127.0.0.1)에서만 열리고, 실행마다 새로 만든 확인값이 맞아야 하며, 접속한 프로세스가 적어 보낸 세션 번호의 세션이 실제로 띄운 프로세스여야 받습니다(세션 안에서 다른 세션의 번호를 적어 접속하는 것을 막음. 같은 사용자 권한으로 다른 프로세스를 조작하는 것까지 막지는 못함).
- 셸 세션(PowerShell 등)에도 그 통로의 주소와 확인값이 환경 변수로 들어가고, PATH 맨 앞에 끼움 프로그램의 폴더(`%LOCALAPPDATA%\cypher\shim`)가 놓입니다(그 셸에서 직접 띄운 Claude에 Cypher를 붙이기 위해서입니다). 그래서 그 셸에서 실행한 다른 프로그램도 그 세션의 이름으로 통로에 접속해 그 세션이 속한 워크스페이스의 Cypher 도구(브라우저 조작 등)를 쓸 수 있습니다. 믿을 수 없는 프로그램을 그 셸에서 돌린다면 설정의 `[session] claude_in_shell = false`로 끄세요(끄면 "+ Claude"로 연 세션에만 값이 들어가고 PATH도 건드리지 않습니다).
- 문서 항목은 파일의 내용을 글자로만 다룹니다. 파일 안의 HTML·스크립트는 실행하지 않고 글자 그대로 보이며, 링크는 `http`·`https`와 이 컴퓨터의 파일만 엽니다(네트워크 경로와 `javascript:` 같은 것은 링크가 되지 않습니다). 그림은 불러오지 않습니다.
- 워크스페이스 틀 파일은 다른 사람에게서 받은 것일 수 있으므로, 펼칠 때 이 PC에 등록된 프로필과 항목 종류만 만들고 저장소 번호처럼 이 PC의 다른 항목을 가리키는 값은 받지 않습니다. 다만 틀에 든 사이트 주소와 파일 경로는 그대로 열리므로, 믿을 수 있는 틀만 펼치세요.
- Claude 세션이 도구로 다룰 수 있는 것은 그 세션과 같은 이름 붙인 워크스페이스의 항목뿐입니다. 워크스페이스 없는 것끼리와 세션끼리는 다룰 수 없습니다(아래 "Claude 세션이 다룰 수 있는 범위").
- 명령 항목의 명령은 사용자가 실행을 눌렀을 때만 돕니다(끌어다 놓거나 골라 채운 명령도 ▶를 눌러야 돕니다). 다시 시작한 뒤, 닫은 항목을 다시 연 뒤, 워크스페이스 틀을 펼친 뒤에는 명령을 되살려 두기만 합니다. Claude 세션의 도구로는 명령 항목을 만들거나 실행·멈출 수 없고, 같은 워크스페이스의 명령 항목의 출력을 읽는 것(`run_output`)만 됩니다. 받은 워크스페이스 틀에 든 명령은 실행하기 전에 내용을 확인하세요.
- Claude 세션이 도구로 메모를 통째로 바꿀 때는 바꾸기 전 글을 30일 동안 보관합니다. 이미지·문서로 놓을 수 있는 것은 이 컴퓨터의 파일뿐입니다(네트워크 경로는 받지 않음).
- 변경 내용의 되돌리기·커밋은 저장소 안의 상대 경로만 받고, 되돌리기는 화면이 본 상태가 아니라 그 순간의 git 상태를 다시 읽어 판단합니다.
- 내장 SSH는 서버의 키를 `~/.ssh/known_hosts`(와 `C:\ProgramData\ssh\ssh_known_hosts`)로 확인합니다. 기록된 키와 다르거나 `@revoked`이면 접속하지 않고, 처음 보는 서버는 지문을 보여 주고 사용자가 yes를 쳐야 접속하며 그 키를 `known_hosts`에 적습니다(`StrictHostKeyChecking yes`인 호스트는 묻지 않고 거절). 서버는 주소와 포트만 저장하고, 사용자 이름·비밀번호·키 암호·일회용 번호는 접속할 때마다 묻습니다. 비밀번호·키 암호·일회용 번호는 그 자리에서 쓰고 저장하지 않으며, 화면에 보이지 않습니다. 접속할 주소에 빈칸·옵션이 끼어들지 못하게 하고, ssh.exe로 띄울 때 물은 사용자 이름은 `-l`의 값으로만 넘깁니다(옵션으로 읽히지 않음).
- 연결 복제는 그 연결을 같은 앱 안에서만 나눠 씁니다. 복제가 아닌 새 세션은 같은 서버·같은 사용자로 인증한 연결만 같이 씁니다(다른 사용자로 인증한 연결에는 붙지 않음). 연결은 그것을 쓰는 마지막 세션이 닫히면 끊습니다.
- 헥사 에디터는 사용자가 저장을 눌렀을 때만 파일에 씁니다. 저장은 덮어쓰기만 하고(크기는 그대로), 작은 파일은 새 파일에 다 쓴 뒤 바꿔치기해 쓰다가 끊겨도 원래 파일이 남습니다(숨김 같은 속성, 권한, 인터넷에서 받은 파일 표시 같은 대체 스트림, 하드 링크는 그대로 둡니다). 연 뒤에 밖에서 바뀐 파일은 덮어쓰기 전에 묻습니다. 저장하지 않은 고침(64KB까지)은 앱을 닫거나 다시 시작해도 남아, 파일이 그대로면 다시 열 때 되살립니다(파일에는 쓰지 않은 채로).

### 바깥과의 통신

Cypher는 사용자가 시키지 않은 통신을 하지 않습니다. 스스로 하는 업데이트 확인, 사용 통계, 오류 보고가 없습니다. 통신이 일어나는 곳은 다음뿐입니다.

| 언제 | 어디로 |
|---|---|
| 사이트 항목에 주소를 치거나, 되살린 사이트 항목을 화면에 띄울 때, 시작 페이지를 정해 둔 채 새 사이트 항목을 만들 때, 같은 워크스페이스의 Claude 세션이 브라우저 도구를 쓸 때 | 그 웹 사이트 (주소가 아닌 글을 치면 Google 검색) |
| HTTP 항목에서 요청을 보내거나 Claude 세션이 `http_run`을 쓸 때 | 요청 파일에 적힌 주소 |
| SSH 세션을 열거나(복제는 이미 연 연결을 씀) 연결이 살아 있는지 확인할 때(`[ssh] keepalive`) | 접속 창에 적은 주소의 서버(`~/.ssh/config`의 HostName) |
| 웹 페이지의 그림을 사이드바로 끌어다 놓을 때 | 그 그림의 주소(그림을 받아 이미지 항목으로 만듦) |
| 링크를 누르거나 사이트 항목의 "외부 브라우저"를 누를 때 | Windows 기본 브라우저가 엶 |
| 도움말 → Cypher 업데이트에서 "업데이트 확인"이나 "내려받아 설치"를 누를 때 | `api.github.com`(최신 릴리즈 정보를 읽음), `github.com`(릴리즈 묶음을 받음). 로그인·토큰이 필요 없고 보내는 정보도 없음 |
| 도움말 → 브라우저 엔진 정보에서 "최신 버전 확인"을 누를 때 | `googlechromelabs.github.io`(Chrome 안정판 버전 번호를 읽음. 보내는 정보 없음) |

- Claude Code, PowerShell 등 세션 안에서 도는 프로그램의 통신은 그 프로그램의 것입니다.
- 웹뷰 엔진(WebView2)이 뒤에서 스스로 하는 통신(구성 요소 갱신, 안정성 보고, 동기화 등)은 실행 인자로 꺼 두었습니다. 다만 WebView2 런타임 본체가 시작할 때 Microsoft 365 쪽으로 짧게 접속하는 것이 관찰되며, 이것은 런타임(Windows 구성 요소)의 동작이라 앱에서 끌 수 없습니다. 막으려면 Windows 방화벽이나 조직의 WebView2 정책을 써야 합니다.
- 엔진을 `chrome`으로 바꾸면 띄운 Chrome·Edge가 스스로 하는 통신(업데이트 확인 등)이 더해집니다.

## 시험

```
cargo test --workspace
```

화면까지 자동으로 확인하려면 웹뷰 원격 디버깅을 켜고 실행한 뒤, 그 포트(CDP)로 JS를 실행합니다.
화면 코드가 `window.cypher`(세션 열기·입력·화면 글자 읽기)과 `window.cypherErrors`(화면 오류 목록)를 내놓습니다.

```
set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333
set WEBVIEW2_USER_DATA_FOLDER=<시험용 빈 폴더>
target\debug\cypher.exe
```

`WEBVIEW2_USER_DATA_FOLDER`가 있으면 웹뷰 엔진은 앱이 정한 데이터 폴더를 무시하고 그 폴더만 씁니다. 그대로 두면 워크스페이스별 브라우저 프로필이 한 폴더로 합쳐지므로, Cypher는 본창이 뜬 뒤 이 변수를 자기 프로세스에서 지우고 워크스페이스 없는 사이트 항목에만 그 폴더를 직접 지정합니다. 워크스페이스별 프로필은 `%LOCALAPPDATA%\cypher\site-profiles`에 생기므로, 사용자 데이터와 섞이지 않게 하려면 `LOCALAPPDATA`·`APPDATA`도 시험용 폴더로 돌려 실행합니다.

## 브라우저(사이트 항목)와 Claude 연동

브라우저는 사이드바의 사이트 항목입니다("+ 사이트" 또는 Ctrl+Shift+O). 로그인 상태는 다음 실행에도 유지됩니다.

### 워크스페이스마다 따로인 브라우저 프로필

로그인 상태(쿠키·저장소)는 **같은 워크스페이스의 사이트 항목끼리만** 함께 씁니다. 워크스페이스마다 브라우저 프로필(데이터 폴더)이 따로 있어서, 한 워크스페이스에서 로그인해 둔 계정을 다른 워크스페이스의 사이트 항목이나 그 워크스페이스의 Claude 세션이 쓸 수 없습니다.

- 프로필은 `%LOCALAPPDATA%\cypher\site-profiles\<프로필 번호>`에 둡니다. 어느 워크스페이스가 어느 번호를 쓰는지는 Cypher가 기억합니다.
- **워크스페이스 이름을 바꿔도** 프로필은 그대로라 로그인 상태가 유지됩니다(바꾼 이름으로 예전에 없앤 워크스페이스의 프로필이 남아 있어도 지금 워크스페이스의 것이 따라갑니다).
- **워크스페이스를 없애도 프로필은 지우지 않습니다.** 같은 이름으로 워크스페이스를 다시 만들면 예전 프로필(로그인 상태)을 다시 씁니다. 로그인 정보까지 없애려면 Cypher를 끈 뒤 `site-profiles`(chrome 엔진은 `chrome-profiles`) 아래의 폴더를 지웁니다. 폴더 이름은 프로필 번호라 어느 워크스페이스의 것인지 드러나지 않으므로, 가려 지우기 어렵다면 모두 지우고 워크스페이스마다 다시 로그인합니다.
- **사이트 항목을 다른 워크스페이스로 옮기면** 보던 주소는 그대로 두고 새 워크스페이스의 프로필로 다시 엽니다. 옛 워크스페이스의 로그인 상태는 따라가지 않습니다. 이미 있는 워크스페이스에 합칠 때도 같습니다. 옮기는 순간에 옛 워크스페이스의 Claude 세션이 그 브라우저를 조작하고 있었다면 그 조작은 "다른 워크스페이스로 옮겨졌다"는 오류로 끝납니다(옛 워크스페이스의 로그인 상태로 되살아나지 않습니다). 조작하던 사이트 항목을 닫았을 때도 그 조작은 오류로 끝나고, 닫은 항목이 보이지 않는 곳에서 다시 열리지 않습니다.
- **워크스페이스가 없는 사이트 항목**은 공용 프로필을 씁니다(이전 버전에서 쓰던 그 프로필). Claude 세션은 워크스페이스 없는 사이트 항목을 조작할 수 없습니다.
- 이전 버전에서 워크스페이스에 넣어 쓰던 사이트 항목은 이번 버전부터 그 워크스페이스의 새 프로필을 쓰므로 **한 번 다시 로그인해야 합니다**.
- 워크스페이스마다 브라우저 엔진 프로세스가 따로 뜨므로, 사이트 항목을 쓰는 워크스페이스가 많으면 메모리를 그만큼 더 씁니다(사이트 항목을 실제로 띄운 워크스페이스만).
Cypher가 띄운 Claude 세션에는 `cypher` 도구 묶음(MCP)이 자동으로 연결되고, 그 세션과 **같은 이름 붙인 워크스페이스**의 항목만 다룹니다.

### Claude 세션이 다룰 수 있는 범위

- **같은 워크스페이스 안에서만**: 도구는 그 세션과 같은 이름 붙인 워크스페이스에 있는 항목(메모, 마인드맵, 사이트, HTTP, 문서, 이미지)만 다룹니다. 다른 워크스페이스의 항목은 번호를 알아도 다룰 수 없고, 목록에도 나오지 않습니다.
- **워크스페이스 없는 것끼리는 다룰 수 없음**(이제 모든 세션과 항목이 워크스페이스 안에 있으므로 이 경우는 생기지 않습니다. 이전 버전에서 워크스페이스 없이 쓰던 것은 `root` 워크스페이스로 모이고, 그 뒤로는 `root` 워크스페이스 안의 것끼리 다른 워크스페이스와 같은 규칙으로 다룹니다): 워크스페이스 없이 폴더 묶음에 있는 세션과 항목은 같은 폴더에서 열었더라도 서로 다룰 수 없습니다. 워크스페이스 없는 Claude 세션은 브라우저 조작, 기존 항목 고치기, HTTP 도구를 쓸 수 없고, 자기 폴더 묶음에 새 항목을 놓는 것(메모·이미지·문서·마인드맵)과 알림만 할 수 있습니다(놓은 뒤에는 그것도 고칠 수 없습니다). 조작을 맡기려면 세션과 항목을 한 워크스페이스에 넣습니다(오른쪽 클릭 → 워크스페이스 지정, 또는 워크스페이스 머리로 끌기).
- **세션끼리는 다룰 수 없음**: Claude 세션이 다른 세션(다른 Claude 세션 포함)에 글을 넣거나 조작하는 도구는 없습니다. 같은 워크스페이스의 다른 세션은 목록에 이름과 상태만 보입니다.
- **다른 세션의 번호를 적어 보내도 받지 않음**: 도구 요청과 상태·완료 신호에는 "몇 번 세션이 보냈다"가 적혀 오지만, Cypher는 그 번호를 믿지 않고 접속한 프로세스가 실제로 그 세션이 띄운 프로세스인지(조상을 따라 올라가) 확인합니다. 다른 세션의 번호를 적어 보낸 요청, 번호가 없는 요청, 세션 밖의 프로세스가 보낸 요청은 받지 않습니다(확인값이 맞는 접속을 받지 않았을 때는 사유별로 한 번씩 `%LOCALAPPDATA%\cypher\cypher.log`에 남김). 평범한 방법(세션 안에서 통로에 직접 접속하기)은 막지만, 같은 Windows 사용자 권한으로 다른 프로세스 자체를 조작하는 것(부모 프로세스 위조, 코드 주입)까지 막지는 못합니다.
- **넘기기도 같은 워크스페이스 안에서만**: 사이트 항목의 "Claude에게"는 같은 워크스페이스의 Claude 세션에만 넘깁니다. 넘겨받은 뒤 어느 한쪽이 다른 워크스페이스로 옮겨지면 더는 조작하지 못합니다.
- **HTTP 도구**: `http_list`·`http_run`은 같은 워크스페이스에 있는 HTTP 항목의 요청 폴더와 그 세션을 시작한 폴더의 요청 파일(폴더 바로 아래, `http`, `.cypher\http`)에만 씁니다. 그 밖의 폴더(시작 폴더 아래의 다른 하위 폴더 포함)의 요청은 그 폴더를 보는 HTTP 항목을 같은 워크스페이스에 두어야 다룰 수 있습니다. 워크트리 세션(`claude --worktree`)은 시작 폴더가 저장소 뿌리라서, 워크트리 안의 요청을 다루려면 그 폴더의 HTTP 항목이 필요합니다. 폴더 기준 규칙이므로, 다른 워크스페이스의 HTTP 항목이 이 세션의 시작 폴더와 같은 폴더(또는 그 `http`·`.cypher\http`)를 보고 있다면 같은 요청 파일을 함께 다루게 됩니다.
- **"chrome" 엔진도 워크스페이스별**: 이 엔진에서는 워크스페이스마다 Chrome을 따로 띄우고 프로필도 따로 씁니다. Claude 세션은 자기 워크스페이스의 Chrome만 조작하고, 워크스페이스 없는 세션은 조작할 수 없습니다.
- 사용자가 직접 하는 일(변경 내용에서 고른 줄을 세션에 넣기, 이미지 경로를 세션에 넣기)은 이 제한과 무관합니다.

이 제한이 막지 못하는 것:

- **파일**: 제한은 Cypher 도구에 한한 것입니다. Claude Code는 자기 권한 설정 안에서 이 컴퓨터의 파일을 직접 읽고 쓸 수 있으므로, 다른 워크스페이스의 메모·마인드맵·이미지가 저장된 파일(`%APPDATA%\cypher`)이나 다른 세션의 폴더는 Cypher가 막지 못합니다. 그런 접근은 Claude Code의 권한 설정으로 다룹니다.

### Claude 세션이 만든 파일

Claude 세션이 Write 도구로 **새 파일**을 만들면 종류에 맞는 항목으로 그 세션의 워크스페이스(워크스페이스가 없으면 폴더 묶음)에 놓고 알림으로 알려 줍니다. 보던 화면은 바꾸지 않습니다.

| 만든 파일 | 놓이는 항목 |
|---|---|
| `.md`, `.markdown`, `.txt` | 문서 항목(파일이 바뀌면 스스로 다시 그림) |
| `.svg` 등 그림 | 이미지 항목(Write 도구는 글자만 쓰므로 사실상 SVG) |
| `.html`, `.htm` | 사이트 항목(그 파일을 브라우저로 엶. 웹뷰는 그 항목을 처음 볼 때 뜨고, 같은 워크스페이스의 Claude 세션이 그 파일을 고치면 스스로 새로 고침. 다른 길로 고친 것은 ⟳로 다시 읽음) |
| `.csv`, `.tsv` | 표 항목(파일이 바뀌면 스스로 다시 읽음). `.json`은 설정 파일인 경우가 많아 놓지 않음(`table_show`로 놓을 수 있음) |
| `.http` | HTTP 항목. 파일이 `<폴더>\http`나 `<폴더>\.cypher\http`에 있으면 그 `<폴더>`의 항목으로, 아니면 파일이 든 폴더의 항목으로 놓고, 그 폴더를 보는 HTTP 항목이 이미 있으면 새로 만들지 않고 그 항목의 파일 목록을 다시 읽음 |

- 새 파일인지는 쓰기 직전에 그 파일이 없었는지로 가립니다. 이미 있던 파일을 고쳐 쓴 것은 놓지 않습니다.
- 한 세션에서 같은 파일은 한 번만 놓고, 그 워크스페이스의 문서·표·메모·HTTP·사이트·이미지 항목이 이미 보여 주는 파일은 놓지 않습니다.
- 세션이 일하는 폴더 아래의 숨김 폴더(`.git`, `.claude` …)·`node_modules`·`target`·`dist`·`build` 안의 파일, Claude Code의 설정·기억 폴더와 Cypher 저장소·임시 폴더의 파일, 네트워크 경로의 파일은 놓지 않습니다(`.cypher\http`의 요청 파일은 놓습니다).
- 워크스페이스가 없는 세션이 만든 `.http`는 그 세션의 시작 폴더가 보는 요청 파일(폴더 바로 아래, `http`, `.cypher\http`)일 때만 HTTP 항목이 되고, 다른 폴더(시작 폴더의 다른 하위 폴더 포함)의 것은 다른 폴더 묶음에 끼어들지 않도록 자기 묶음의 문서 항목으로 보여 줍니다.
- 한 요청에서 8개까지만 놓고, 넘치면 한 번 알립니다.
- 명령(Bash 등)이나 스크립트로 만든 파일은 알 수 없어 놓지 않습니다(스킬이 스크립트로 만든 결과물도 그렇습니다). 그런 파일은 Claude가 `doc_show`·`image_add`·`table_show`로 놓을 수 있고, HTML 파일은 `browser_navigate`에 파일의 전체 경로를 주어 사이트 항목으로 엽니다. Claude 세션에 주는 안내에 이 방법이 적혀 있고, "문서 항목으로 보여 줘", "브라우저로 열어 줘"처럼 시켜도 됩니다. `browser_navigate`는 워크스페이스에 든 세션만 쓸 수 있고, 그 워크스페이스에 브라우저가 이미 있으면 그 브라우저가 그 파일로 옮겨 갑니다.
- 설정의 `[session] show_created`로 바꿉니다: `"known"`(기본), `"all"`(코드 같은 그 밖의 글자 파일도 문서 항목으로), `"off"`(놓지 않음, Write 도구의 훅도 걸지 않음).

Claude 세션이 **있던 파일을 고치면**(Edit·Write 도구) 새 항목을 놓지 않고, 그 세션과 같은 워크스페이스(워크스페이스가 없으면 같은 폴더 묶음)에서 그 파일을 보여 주는 항목이 바로 새 내용을 읽습니다. 다른 워크스페이스의 항목은 건드리지 않습니다.

| 그 파일을 보여 주는 항목 | 하는 일 |
|---|---|
| 문서, 표 | 보던 자리를 지킨 채 다시 읽음(가려져 있어도) |
| 사이트(HTML 파일을 연 것) | 페이지를 새로 고침. 웹뷰가 아직 뜨지 않았으면 처음 볼 때 새 내용으로 뜸 |
| 이미지(Claude가 만든 파일에서 가져온 그림) | 그 파일을 다시 가져와 그림을 바꿈. 옛 그림은 닫은 이미지처럼 30일 보관 |
| 파일에 연결된 메모, HTTP 항목 | 고치던 글이 없으면 다시 읽고, 있으면 덮어쓰지 않음(저장할 때 "다시 읽기 / 덮어쓰기"를 물음) |

- 명령(Bash 등)으로 고친 것은 알 수 없습니다. 문서·표는 화면에 보이는 동안 스스로 살피므로 그래도 반영되지만, 사이트는 ⟳로 다시 읽습니다.
- 도구 신호로 아는 것이라, 설정에서 `activity`와 `show_created`를 둘 다 꺼 두면(도구 훅을 걸지 않음) 이 동작도 하지 않습니다.

| 도구 | 하는 일 |
|---|---|
| `browser_read` | 지금 페이지의 주소·제목·글자와, 누르거나 입력할 수 있는 요소 목록(번호) |
| `browser_click` / `browser_type` / `browser_key` | 번호로 가리킨 요소 누르기, 글자 입력, 키 누르기 |
| `browser_screenshot` / `browser_click_at` | 화면을 그림으로 받아 보고, 그 그림의 좌표를 누르기 |
| `browser_navigate` / `browser_back` / `browser_scroll` / `browser_eval` | 이동(웹 주소, 또는 이 컴퓨터의 HTML 파일의 전체 경로), 뒤로, 스크롤, 페이지에서 스크립트 실행 |
| `browser_tabs` / `browser_select` | 같은 워크스페이스의 브라우저 목록 보기, 조작 대상 바꾸기 |
| `browser_dialog` | 페이지가 다음에 띄우는 확인 창(alert·confirm·prompt, 나가기 확인) 하나에 줄 답 정하기. 정하지 않으면 조작 중에 뜬 창은 Cypher가 바로 닫고(alert는 확인, confirm·prompt는 취소, 나가기 확인은 나가기) 그 사실을 도구의 답에 적음. 도구가 쓰고 있지 않을 때 뜬 창은 사용자가 답하도록 그대로 두고, 그 창이 떠 있는 채로 도구가 시작되면 닫고 시작함 |
| `cypher_items` | 같은 워크스페이스의 항목 목록: 다른 세션(이름·상태만), 메모·이미지·마인드맵·문서·할 일·표의 파일 경로, 브라우저 주소, HTTP 요청 폴더, 명령 항목의 명령과 상태. 워크스페이스가 없는 세션에는 목록 대신 그 사실을 알려 줌 |
| `mindmap_write` | 마인드맵 항목을 개요 글로 만들거나 고치기 |
| `erd_write` | ERD 항목을 `erDiagram` 표기의 글로 만들거나 고치기. 읽지 못한 줄이 있으면 줄 번호와 고치는 법을 답으로 돌려줌 |
| `todo_write` / `todo_check` | 할 일 항목을 Markdown 체크 목록으로 만들기·끝에 덧붙이기(`append`, 기본)·통째로 바꾸기(`replace`) / 할 일을 번호나 글로 가리켜 체크하거나 풀기. 답으로 할 일마다 번호를 붙인 지금의 목록과 진행을 돌려줌. 체크는 사이드바의 진행 표시로 바로 보이므로 따로 알림을 띄우지 않음 |
| `run_output` | 같은 워크스페이스의 명령 항목의 상태(실행 중·성공·실패와 종료 코드·멈춤)와 출력의 끝부분(기본 80줄, 400줄까지) 읽기. 읽기만 하고, 실행·멈춤은 사용자가 함 |
| `table_show` | 이 컴퓨터의 CSV·TSV·JSON 파일(절대 경로)을 같은 워크스페이스의 표 항목으로 놓기. 이미 그 파일을 보여 주는 표가 있으면 그것을 새로 읽음 |
| `memo_write` | 메모 항목 만들기. 번호(id)를 주면 그 메모의 끝에 덧붙이거나(`append`, 기본) 통째로 바꾸기(`replace`, 바꾸기 전 글은 30일 보관) |
| `image_add` | 이 컴퓨터의 그림 파일(절대 경로)을 같은 워크스페이스의 이미지 항목으로 넣기 |
| `doc_show` | 이 컴퓨터의 Markdown·글자 파일(절대 경로)을 같은 워크스페이스의 문서 항목으로 놓기. 이미 그 파일을 보여 주는 문서가 있으면 그것을 새로 읽음 |
| `notify_user` | 사용자에게 알림 띄우기(앱 안 알림, 창이 뒤에 있으면 Windows 알림, 알림 기록) |
| `http_list` / `http_run` | 폴더의 `.http` 요청 나열, 요청 실행(기록 포함) |

어느 브라우저를 조작하는지는 이렇게 정해집니다.

1. 사용자가 사이트 항목의 "Claude에게"로 넘겨준 브라우저. 같은 워크스페이스에 Claude 세션이 하나면 바로 넘어가고, 여러 개면 고르는 메뉴가 뜹니다(오른쪽 클릭: 고르기, 새 Claude 세션에 넘기기). 넘기면 그 세션 입력창에 머리말이 들어가고, 이어서 할 일을 적으면 됩니다. 넘겨받은 세션의 이름이 단추에 표시됩니다.
2. 넘겨받은 것이 없으면 같은 워크스페이스에서 마지막으로 본 사이트 항목.
3. 워크스페이스에 사이트 항목이 없는데 Claude가 주소로 이동하려 하면, 그 워크스페이스에 새 사이트 항목을 만들어 사이드바에 놓습니다(화면은 나누지 않습니다. 함께 보려면 사이드바에서 화면 가장자리로 끌어다 놓습니다).

- Claude가 놓거나 고친 항목(메모·이미지·문서)은 보던 화면을 바꾸지 않고 사이드바에만 놓이며, 알림으로 알려 줍니다(누르면 그 항목이 열림). 같은 항목에 같은 일을 잇달아 하면 알림은 처음 한 번만 뜹니다.
- 화면에 띄워 두지 않은 사이트 항목도 조작할 수 있습니다(조작하는 동안만 보이지 않는 자리에서 화면을 그립니다).
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령을 부를 수 없습니다(위 보안 규칙).
- 조작은 디버깅 포트를 열지 않고 WebView2의 개발자 도구 프로토콜을 앱 안에서 직접 부릅니다.
- 도구를 쓸 때의 승인 절차는 Claude Code의 권한 설정을 그대로 따릅니다.
- 설정의 `[browser] enabled = false`로 도구 연결을 끌 수 있습니다.

### 브라우저 엔진: 내장 웹뷰와 Chrome

기본 엔진(`webview`)은 사이드바의 사이트 항목이며 Windows의 WebView2로, Edge와 같은 Chromium이며 Windows가 알아서 최신으로 갱신합니다.
다만 WebView2는 Windows에만 있고, macOS의 웹뷰는 Chromium이 아니어서 같은 방법으로 조작할 수 없습니다.
그래서 다른 OS에서도 쓸 수 있는 두 번째 엔진을 두었습니다.

```toml
[browser]
engine = "chrome"      # 설치된 Chrome → Edge → Chromium → Brave 순으로 찾아 띄움
# chrome_path = ""     # 다른 실행 파일을 쓰려면 경로를 적음
```

- 설치된 브라우저를 Cypher 전용 프로필로 띄웁니다. 평소 쓰는 프로필과 로그인은 건드리지 않으며, 이 프로필의 로그인은 다음 실행에도 유지됩니다.
- **브라우저는 워크스페이스마다 따로 뜹니다.** 프로필도 워크스페이스마다 따로라(`%LOCALAPPDATA%\cypher\chrome-profiles\<프로필 번호>`) 로그인 상태가 워크스페이스끼리 섞이지 않습니다. 워크스페이스가 없는 항목을 보고 있을 때 연 Chrome은 `%LOCALAPPDATA%\cypher\chrome-profile`을 쓰며, Claude 세션은 그것을 조작할 수 없습니다.
- 브라우저가 스스로 갱신하므로 늘 최신 Chromium이고, Cypher 배포 파일은 커지지 않습니다.
- 디버깅 포트를 열지 않고 Cypher와 브라우저만 아는 파이프(`--remote-debugging-pipe`)로 통신합니다. Cypher를 끝내면 이 브라우저도 함께 끝납니다.
- Claude가 쓰는 도구(`browser_read` 등)는 두 엔진에서 똑같이 동작합니다. 이 엔진에서는 그 세션의 워크스페이스가 쓰는 Chrome 창에서 사용자가 보고 있는 탭을 조작합니다(워크스페이스 없는 세션은 조작할 수 없습니다).
- 이 엔진을 고르면 사이드바 아래에 "Chrome"(열기)·"넘기기"·"캡처" 단추가 생깁니다. 세 단추는 지금 보고 있는 항목의 워크스페이스가 쓰는 Chrome에 듣고, "넘기기"는 그 워크스페이스의 Claude 세션에 넘깁니다. 처음 여는 주소는 빈 페이지입니다(`[browser] home`으로 바꿈).
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)은 Tauri 3이 아직 알파 단계이고 배포 파일이 수백 MB 늘어 쓰지 않았습니다.
- 파이프를 넘기는 부분만 OS별로 다릅니다(`crates/cypher-app/src/chrome.rs`의 `spawn`). 지금은 Windows용만 구현돼 있습니다.

### Chromium 버전 올리기

Cypher는 Chromium을 실행 파일에 싣지 않습니다. 그래서 엔진 버전은 Cypher 버전과 무관하게, 바깥의 브라우저가 갱신될 때 함께 올라갑니다.
Cypher를 새로 빌드하거나 배포할 필요가 없습니다.

| 엔진 | 누가 갱신하나 | 직접 갱신하려면 |
|---|---|---|
| `webview` | WebView2 런타임. Edge와 함께 Windows가 자동으로 갱신 | Edge에서 `edge://settings/help`, 또는 Microsoft의 "WebView2 런타임(Evergreen)" 설치 프로그램 실행 후 Cypher 다시 시작 |
| `chrome` | 설치된 Chrome·Edge의 자동 업데이트 | 그 브라우저에서 `chrome://settings/help`(Edge는 `edge://settings/help`) 후 Cypher용 브라우저 창을 닫았다 다시 열기 |

갱신이 멈춰 있지 않은지는 직접 확인할 수 있습니다.

- 도움말 → "브라우저 엔진 정보·업데이트 확인" 창에서 지금 엔진의 Chromium 버전을 볼 수 있습니다. 그 창의 "최신 버전 확인"을 누르면 Chrome 최신 안정판과 비교해 몇 단계 뒤처졌는지와 갱신 방법을 알려 줍니다.
- Cypher가 스스로 버전을 확인하러 나가지는 않습니다. 단추를 눌렀을 때만 Google이 공개하는 Chrome for Testing 목록(`googlechromelabs.github.io`)에서 버전 번호를 읽고, 이때 보내는 정보는 없습니다.
- 회사 정책 등으로 자동 업데이트가 꺼진 PC라면, `chrome_path`에 직접 관리하는 Chromium 실행 파일을 지정해 그 파일만 교체하는 방법도 있습니다.

Cypher 쪽에서 따로 챙길 것은 두 가지입니다.

- 조작에 쓰는 개발자 도구 프로토콜(CDP) 명령은 오래 유지돼 온 안정된 것만 씁니다(`Runtime.evaluate`, `Page.navigate`, `Page.captureScreenshot`, `Input.*`, `Target.*`). Chromium이 올라가 동작이 달라졌는지는 `cargo test -p cypher chrome -- --ignored`(설치된 브라우저를 실제로 띄워 파이프로 조작해 보는 시험)로 확인합니다.
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)으로 바꾸면 그때부터는 Chromium 버전이 Cypher 빌드에 고정되므로, 보안 갱신을 따라가려면 약 4주마다 Cypher를 다시 빌드·배포해야 합니다. 지금 구조를 택한 까닭 중 하나입니다.

## HTTP 요청 파일

사이드바의 "+ HTTP"(Ctrl+Shift+H)나 워크스페이스 머리의 +로 HTTP 항목을 만듭니다. 항목은 만들 때 보고 있던 항목의 폴더를 따릅니다.
그 폴더의 `.cypher\http\`, `http\`, 또는 폴더 바로 아래의 `*.http`를 읽습니다.

```
@host = https://api.example.com

### 로그인
POST {{host}}/login
Content-Type: application/json

{"id": "kim"}
```

실행하면 요청 파일 옆 `history.http`에 요청과 응답이 덧붙습니다(인증 헤더 값과 환경 변수에서 읽은 값은 `***`로 가림).
기록 파일은 저장소에 올라가지 않게 해 둡니다: git 저장소 안이면 그 저장소의 `info/exclude`(이 컴퓨터에만 있는 무시 목록)에 올리고 `.gitignore`는 건드리지 않습니다. 저장소가 아닌 폴더면 `.gitignore`가 없을 때만 만들어 둡니다.

- 요청 줄은 `http://`·`https://` 주소나 `{{변수}}`로 시작해야 합니다. 요청 줄 왼쪽의 ▶나 Ctrl+Enter는 커서가 있는 그 요청만 보냅니다.
  주소를 채우지 못했거나(변수 오타 등) 요청이 아닌 줄에서는 다른 요청을 대신 보내지 않고 까닭을 알려 줍니다.
  파일 머리말(첫 `###` 앞의 빈 줄·주석·변수)에서 실행하면 바로 아래의 첫 요청을 보내고, 마지막 요청 아래의 빈 줄에서는 그 마지막 요청을 보냅니다. 보내는 중인 요청을 다시 눌러도 두 번 보내지 않습니다.
- 고친 내용은 고치는 동안에도 1.5초 안쪽 간격으로 자동 저장됩니다(파일의 줄 끝 형식은 그대로 둡니다). 저장하지 못하면 항목을 닫거나 다른 파일로 옮기기 전에 알려 줍니다.
- 파일이 다른 곳(Claude 세션, 다른 HTTP 항목, 외부 편집기)에서 바뀌면, 편집기에 고친 내용이 없을 때 다시 읽습니다. 고치던 중이었다면 저장하지 않고 "다시 읽기 / 덮어쓰기"를 묻습니다(말없이 덮어쓰지 않습니다).
- 읽지 못한 파일(다른 프로그램이 잠근 파일 등)은 편집기를 잠가 덮어쓰지 않습니다. 열어 둔 파일이 바깥에서 지워졌으면 저장할 때 다시 만듭니다. BOM이 붙은 요청 파일도 읽습니다.
- 리다이렉트를 따라갔으면 응답과 기록에 `→ 최종 주소`를 적습니다. 같은 이름의 응답 헤더(`Set-Cookie` 등)는 값마다 한 줄씩 보여 줍니다. 5MB를 넘는 응답은 앞부분만 받고 잘렸다고 알리며, 화면에 다 보이지 않는 긴 요청·응답에는 생략한 줄 수를 적습니다.
- 다른 도구의 틀 문법(`{{ $labels.instance }}`, `{{$json.name}}`처럼 점·괄호가 든 것)은 건드리지 않고 그대로 보냅니다.
- 파일 보내기: 본문에서 `< 경로`로 시작하는 줄은 그 파일의 내용으로 바뀌어 나갑니다(IntelliJ 형식). 경로는 요청 파일이 있는 폴더 기준이고, 거기 없으면 항목의 폴더(요청 파일이 `<폴더>\.cypher\http`나 `<폴더>\http`에 있을 때의 그 `<폴더>`)에서 찾습니다. 전체 경로도 됩니다(공백이 든 경로는 그대로 적거나 큰따옴표로 감쌈). 그림 같은 이진 파일도 되고, 합쳐서 100MB까지입니다. 본문에 그 한 줄만 두면 파일이 통째로 본문이 되고, `multipart/form-data` 본문의 한 부분에 두면 파일 올리기가 됩니다. `Content-Type`이 `multipart/…`인 본문은 줄 끝을 규격대로 CRLF로 보냅니다(파일 안의 줄 끝은 그대로). 화면의 요청 원문과 `history.http`에는 파일 내용이 아니라 `< 경로` 줄이 남고, `{{$body}}`(서명에 쓰는 본문)도 적힌 글 기준입니다. 없는 파일이면 보내지 않고 알려 줍니다.
- 새 요청 파일의 예시는 모두 `httpbin.org`(받은 요청을 그대로 돌려주는 시험용 서버)로 보내므로 바로 눌러 볼 수 있습니다. 필요 없는 예시는 지우면 됩니다. 이미 있는 요청 파일은 바뀌지 않습니다.

### 내장 값과 서명(HMAC)

새 요청 파일의 기본 예시 맨 아래에 바로 보내 볼 수 있는 "서명(HMAC) 예시"가, 그 위에 Basic 인증(`{{$base64 …}}`)과 요청마다 달라지는 값(`{{$uuid}}`, `{{$isoTimestamp}}`)의 예시가 들어 있습니다.

`{{이름}}`은 변수, `{{$이름 인자…}}`는 내장 값입니다. 인자는 변수 이름, `$내장값`, 또는 "따옴표 글"로 적습니다
(따옴표 안에서는 `{{…}}`를 다시 쓸 수 있습니다). 글자 그대로 쓰려면 반드시 따옴표로 감쌉니다. 따옴표 없는 이름은 변수로 보며, 그런 변수가 없으면 보내지 않고 알려 줍니다(변수 이름 오타가 그대로 키나 메시지로 쓰이지 않게).
값은 주소 → 본문 → 헤더 순으로 채워지므로 헤더의 서명에 주소와 본문을 쓸 수 있습니다.
`$host`·`$path`·`$query`·`$pathQuery`·`$url`은 실제로 전송되는 모양 그대로입니다(한글·공백은 퍼센트 인코딩, 기본 포트 생략).

| 적는 법 | 값 |
|---|---|
| `{{$timestamp}}` / `{{$timestampMs}}` | 지금 시각(Unix 초 / 밀리초). 한 요청 안에서는 같은 값 |
| `{{$isoTimestamp}}` / `{{$httpDate}}` | `2026-11-12T08:00:00Z` / `Thu, 12 Nov 2026 08:00:00 GMT` |
| `{{$uuid}}` / `{{$randomInt}}` | 무작위 UUID / 0~999. 같은 값을 여러 번 쓰려면 변수에 담습니다(변수는 요청마다 한 번만 계산) |
| `{{$method}}` `{{$url}}` `{{$host}}` `{{$path}}` `{{$query}}` `{{$pathQuery}}` `{{$body}}` | 이 요청의 부분들 |
| `{{$env 이름}}` | 환경 변수(비밀키를 파일에 적지 않으려 할 때) |
| `{{$base64 값}}` / `{{$base64url 값}}` | Base64로 바꾼 글 |
| `{{$hash 알고리즘 표기 값}}` | 해시 |
| `{{$hmac 알고리즘 표기 키 메시지}}` | HMAC 서명. 키가 16진수나 Base64 글이면 끝에 `key=hex` 또는 `key=base64` |

알고리즘은 `sha256`, `sha1`, `sha384`, `sha512`, `md5`, 표기는 `hex`, `hexupper`, `base64`, `base64url` 중 하나입니다.

```
@host = https://api.example.com
@secret = {{$env MY_API_SECRET}}
@nonce = {{$uuid}}
@message = {{$timestamp}}{{$method}}{{$pathQuery}}{{$body}}

### 주문 넣기
POST {{host}}/v1/orders?side=buy
Content-Type: application/json
X-Timestamp: {{$timestamp}}
X-Nonce: {{nonce}}
X-Body-SHA256: {{$hash sha256 hex $body}}
X-Signature: {{$hmac sha256 hex secret message}}

{"qty": 1}
```

값을 계산하지 못하면(모르는 알고리즘, 없는 환경 변수 등) 요청을 보내지 않고 까닭을 알려 줍니다.
보낸 요청 원문(서명이 채워진 헤더 포함)은 응답과 함께 화면에 나옵니다.
