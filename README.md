# Cypher (사이퍼)

Claude Code 세션 여러 개를 한 창에서 띄우고 전환·감시하는 Windows용 업무 도구입니다.
사이드바에는 터미널 세션뿐 아니라 메모, HTTP 요청 같은 여러 종류의 항목을 놓을 수 있고, 업무 하나를 그룹 하나로 묶어 그 안에 필요한 것을 모아 둡니다.
화면에 나온 웹 주소와 파일 경로를 클릭하면 브라우저나 탐색기가 열립니다.

## 빌드와 실행

Rust(MSVC)만 있으면 됩니다. Node는 필요 없습니다.

```
cargo build --workspace --release
target\release\cypher.exe
```

창 제목에 버전이 표시됩니다(`Cargo.toml`의 `[workspace.package] version`).
`cypher.exe`와 `cypher-bridge.exe`는 같은 폴더에 있어야 합니다(모델 표시·완료 알림이 전달 프로그램을 거칩니다).
`CYPHER_AUTOSTART=claude` 환경 변수를 주고 실행하면 실행 위치 폴더에서 세션이 바로 열립니다.

## 기능

| 기능 | 설명 |
|---|---|
| 항목 모아보기 | 사이드바에 터미널 세션(Claude, PowerShell 등), 메모, HTTP, 사이트(브라우저), 이미지, 브레인스토밍 항목을 놓음. 폴더별로 묶이고, 이름 붙인 그룹으로 한 업무의 항목을 모을 수 있음. 사이드바의 빈 곳을 누른 뒤 ↑/↓(Home/End)로 항목 사이를 오감. 항목을 다른 줄의 위·아래로 끌면 순서가 바뀌고(다른 그룹의 줄이면 그 그룹으로 옮김), 이 순서는 다시 시작해도 유지되며 Ctrl+Tab도 이 순서를 따름 |
| 빠른 이동 | Ctrl+Shift+K로 찾기 창을 열어 항목의 이름·별칭·그룹·폴더나 앱의 명령(새 세션, 모양, 설정 …)을 글자로 찾아 Enter로 감. 초성으로도 찾음(`ㄱㅈ` → 결제). 아무것도 치지 않으면 최근에 본 순서라, 열자마자 Enter를 누르면 바로 전에 보던 항목으로 돌아감 |
| 닫은 항목 다시 열기 | 닫은 항목을 30일 동안 기억함. Ctrl+Shift+R은 가장 나중에 닫은 것을 같은 그룹·폴더·별칭·색으로 바로 다시 열고, 도구 → "닫은 항목 다시 열기"는 목록에서 고름. Claude 세션은 하던 대화를 이어 열고(대화가 없던 세션·다른 터미널은 같은 폴더에서 새로 시작), 메모·브레인스토밍·이미지는 보관해 둔 내용으로, 사이트·HTTP는 보던 주소·파일로 엶. 종료된 세션은 오른쪽 클릭 → "다시 시작"으로 사이드바와 화면의 같은 자리에서 다시 띄움 |
| 별칭 | 항목을 두 번 누르거나 ✎ 단추, 오른쪽 클릭 메뉴로 사이드바의 그 줄에서 바로 별칭을 붙임. 세션에는 영향이 없고 사이드바·창 제목·알림에 보이는 이름만 바뀜. 원래 이름(종류·폴더)은 옆에 흐리게 남음 |
| 사이드바 너비 | 사이드바와 화면 사이의 경계를 끌어 너비 조절(두 번 누르면 기본 너비). 다시 시작해도 유지 |
| 프롬프트 편집기 | 화면에 세션 하나만 보일 때(분할하지 않았을 때) 세션 아래에 글 편집기가 놓임. 긴 프롬프트를 여기서 쓰고 "프롬프트" 단추(Ctrl+Enter)를 누르면 그 세션의 입력창에 들어감. "바로 전송"을 켜면 Enter까지 눌러 보냄. 쓰던 글은 세션마다 기억하고, 높이 조절·접기 가능. 보낸 프롬프트는 50개까지 기억해 Alt+↑/↓로 넘겨 보거나 "기록" 단추에서 골라 다시 씀 |
| 메모 | 글자 편집기 항목. 찾기·바꾸기(대/소문자, 단어 단위, 정규식과 `$1` 그룹 바꾸기), 줄로 이동, 시간/날짜, 자동 줄 바꿈, 확대/축소, 상태 표시줄(줄/열, 글자 수, 200자 원고지 매수, 줄 끝, 인코딩), JSON 정리, 보이지 않는 문자 찾기·정리. 파일 열기·저장은 인코딩(UTF-8, UTF-8 BOM, UTF-16, CP949)과 줄 끝을 유지. 쓰던 내용은 계속 임시 저장되어 다시 시작해도 돌아옴 |
| 사이트(브라우저) | "+ 사이트"를 누르면 주소를 묻지 않고 빈 페이지가 바로 작업 화면에 뜨고, 위의 주소 칸에 주소(또는 검색어)를 쳐서 감. 주소 칸 옆에 캡처, 즐겨찾기(☆), "Claude에게"(같은 그룹의 Claude 세션에 이 브라우저를 넘김. 세션이 여러 개면 고름), "외부 브라우저"(지금 주소를 Windows 기본 브라우저로 엶) 단추. 뒤로·앞으로·새로 고침, 처음 간 주소로 돌아가기. 보던 주소와 제목을 기억하고 다시 시작하면 되살림. 로그인 상태는 사이트 항목끼리 함께 씀. 메뉴·대화상자가 열려 있는 동안에는 페이지를 잠시 가림 |
| 이미지 | 그림을 항목으로 두고 봄. 만드는 방법: "+ 이미지"로 파일 고르기·붙여넣기(Ctrl+V), 이미지 파일이나 브라우저의 그림을 끌어다 놓기, 브라우저·사이트 화면 캡처. 형식은 웹에서 쓰는 것(PNG, JPEG, GIF, WebP, BMP, SVG, AVIF, ICO). 창에 맞춤(F)·실제 크기(1)·확대/축소(+/-, Alt 또는 Ctrl+휠은 커서 기준)·끌어서 이동, 휠과 ←/→로 같은 묶음의 이전·다음 이미지, 정보 표시(I), 복사(Ctrl+C)·다른 곳에 저장(Ctrl+S), 그림 경로를 Claude 세션 입력창에 넣기. 그림은 `%APPDATA%pherimages`에 복사해 두므로 원본을 옮기거나 지워도 남고, 닫은 이미지는 30일 동안 보관 |
| 화면 캡처 | 사이트 항목 주소 칸 옆의 "캡처" 단추로 보이는 화면을 찍어 그 항목과 같은 묶음의 이미지 항목으로 넣음(Shift+클릭은 페이지 전체). 찍은 페이지의 제목이 이름, 주소가 출처로 남음 |
| 끌어다 놓기 | 파일·글자·링크·그림을 창에 끌어다 놓으면 알맞게 처리. 사이드바(묶음 머리나 그 안의 줄에 놓으면 그 묶음)·빈 화면·메모나 터미널이 아닌 창에 놓으면 항목이 됨: 이미지 → 이미지 항목, 글자 파일·끌어 온 글자 → 메모, `.http` → HTTP, 링크·인터넷 바로 가기(`.url`) → 사이트. 터미널과 프롬프트 편집기에 놓으면 파일은 경로를, 글자는 그대로 입력. 메모 창에 놓은 글자 파일은 그 메모로 엶. 보던 화면은 바꾸지 않고 사이드바에만 놓으며(화면이 비어 있으면 바로 보여 줌), 새 항목은 표시가 켜짐 |
| 화면 분할 | 사이드바의 세션을 화면으로 끌어다 놓으면 놓은 위치대로 나뉨(창의 왼쪽·오른쪽 가장자리는 좌우 분할, 위·아래 가장자리는 상하 분할, 가운데는 그 자리에 열기). 창 사이 경계선을 끌어 크기 조절(두 번 누르면 반반). 창 제목 줄의 "이 창만"(분할 풀기)·"숨기기" 단추와 세션 우클릭 메뉴, 사이드바 세션 줄의 ◉/○ 단추로 한 창만 남기거나 창을 숨기고 다시 보임(세션은 사이드바에 남아 계속 실행). 최대 8개, 분할 모양과 비율은 다시 시작해도 유지 |
| 링크 클릭 | 웹 주소는 브라우저, 폴더는 탐색기, 파일은 탐색기에서 선택. Ctrl+클릭은 파일 열기 |
| 이미지 붙여넣기 | Ctrl+V 하나로 글자·파일·이미지를 구분. 붙여넣은 이미지는 터미널 아래에 미리보기 |
| 모델·effort 표시 | 세션마다 모델, effort, 컨텍스트 사용률, 비용. 컨텍스트 80% 이상이면 색 경고 |
| 서브에이전트 표시 | 돌고 있는 서브에이전트 수를 세션 줄에 도는 고리와 숫자로, 그 아래 줄에 종류별 개수("서브에이전트 2개 실행 중 · Explore 2")로 표시. 묶음 머리에는 합계가 보여 접어 두어도 알 수 있음. 서브에이전트가 도는 동안의 중간 멈춤은 완료로 알리지 않고, 모두 끝난 뒤의 완료만 알림 |
| 사용 한도·사용량 | 창 아래에 5시간·주간 한도. 세션별 CPU·메모리는 사이드바에 표시 |
| 완료 알림 | 응답이 끝나거나 승인을 기다리면 앱 안 알림, 창이 뒤에 있으면 Windows 알림. 컨텍스트가 90%를 넘으면 한 번 알림 |
| 작업 시간 | Claude 세션이 요청을 처리하는 동안 사이드바의 그 줄에 경과 시간(3:24)을 보여 주고, 끝나면 걸린 시간을 줄과 완료 알림에 남김("완료 · 5분 12초 걸림") |
| 대기 모아보기 | 대기 중인 세션만 보기, Ctrl+Shift+N으로 다음 대기 세션 이동 |
| 변경 내용 | 세션 폴더의 바뀐 파일 목록과 차이를 옆 창에 표시(git) |
| 워크트리 | 새 git 워크트리에서 Claude 시작(`claude --worktree`) |
| 자주 쓰는 지시 | 문장을 저장해 두고 클릭 한 번으로 입력 |
| 기억 내보내기·가져오기 | Claude Code의 폴더별 기억 파일을 다른 폴더로 복사하거나 들여옴(가져올 때 기존 기억은 백업, 색인은 병합) |
| 브레인스토밍 | 마인드맵 항목. 그림으로 만들기: 가지를 고르고 Tab(하위)·Enter(형제), 글자를 치거나 F2로 고치기, Delete로 지우기, 끌어서 다른 가지로 옮기기, Alt+↑/↓로 순서 바꾸기, 접기(Ctrl+/), 색, 되돌리기(Ctrl+Z/Y), 가지 복사·붙여넣기. 글 없이 Enter를 누르면 빈 가지로 남음(만들지 않으려면 Esc). 표식: 가지를 오른쪽 클릭해(또는 [표식] 단추) 깃발·별·순위(색 7가지씩)·진행(0~100%)·이모지 21가지를 붙이고, 붙은 표식을 다시 누르면 뗌. 코드로 만들기: [그림 \| 코드] 단추(Ctrl+E)로 같은 내용을 코드(개요 글)로 바꿔 보고 고침 — `# 중심 주제` / `- 가지` / 두 칸 들여쓴 `- 하위 가지`, 줄 끝에 `{#3b9fe6 fold}`(색·접힘)·`{flag-red p1 ✅}`(표식). 코드에 잘못된 줄이 있으면 줄 번호와 고치는 법을 알려 주고, 고치기 전에는 그림으로 바뀌지 않음(저장·내보내기도 막음). 양쪽으로 펼치기·오른쪽으로만 펼치기. 내용은 자동 저장되고(`%APPDATA%\cypher\mindmaps`), 개요 파일(.md, UTF-8)로 저장·열기, PNG·PDF·SVG로 내보내기, 사이드바의 이미지 항목으로 넣기 |
| 테마·글꼴 | 설정 → 모양에서 테마(어두운 테마(기본), 밝은 테마, Windows 고전(Win32)), 화면 글꼴·글자 크기, 터미널 글꼴·글자 크기를 고름. 고치는 즉시 적용되고 기억됨 |
| 작업 화면 표시줄 | 작업 화면 맨 위에 지금 보고 있는 항목을 표시: 그룹(또는 폴더 묶음) › 별칭·이름 · 원래 이름 · 폴더 |
| Claude 연동 | 같은 그룹의 Claude 세션이 그 그룹의 브라우저(사이트 항목)를 읽고 조작(클릭·입력·이동, 화면을 그림으로 보고 좌표 클릭)하고, 그룹의 항목 목록(메모·이미지·브레인스토밍 파일 경로, 브라우저 주소)을 보고, 브레인스토밍을 개요 글로 만들거나 고침. 설정에서 엔진을 `chrome`으로 바꾸면 사이트 항목 대신 설치된 Chrome·Edge를 전용 프로필로 띄워 조작 |
| HTTP 요청 | IntelliJ `.http` 형식의 요청을 HTTP 항목의 편집기에서 바로 쓰고 보냄(파일이 없으면 예시로 시작, 요청 줄 왼쪽의 녹색 ▶ 또는 Ctrl+Enter로 보내기, Ctrl+S 저장). 시각·UUID·요청 본문 같은 내장 값과 해시·HMAC 서명 지원. 실행마다 `history.http`에 요청·응답 기록. Claude 세션도 같은 파일을 도구로 실행 |
| 세션 복원 | 다시 시작하면 이전 세션과 배치를 되살리고 Claude 대화를 이어감 |
| 창 자석 | 창을 끌 때 화면 가장자리와 다른 Cypher 창에 달라붙음. 조금만 더 끌면 바로 떨어지고, Ctrl을 누른 채 끌면 붙지 않음 |
| 화면에서 찾기 | Ctrl+Shift+F. 치는 대로 찾고 찾은 개수와 지금 몇 번째인지(3/15)를 보여 줌. 대/소문자 구분(Alt+C)·정규식(Alt+X)을 켤 수 있고 다음에도 기억함 |
| 최근 폴더 | 폴더 줄의 ▾ 단추로 지금 항목의 폴더나 최근에 세션을 시작한 폴더(8개)에서 골라 새 세션 폴더를 바꿈 |
| 그 밖에 | 출력 저장, 동시 입력, 세션 오른쪽 클릭 메뉴의 "같은 폴더에 새 세션"·"폴더를 탐색기에서 열기"·"폴더 경로 복사" |

## 단축키

| 키 | 동작 |
|---|---|
| Ctrl+Shift+T / D | 새 세션 / 나란히 새 세션 |
| Ctrl+Shift+W / X | 세션 닫기 / 나란히 보기에서 빼기 |
| Ctrl+Tab | 다음 항목 (Shift: 이전). 사이드바에 보이는 순서대로 |
| Ctrl+Shift+←/→ | 나란히 보이는 창 사이 이동 |
| Ctrl+Shift+N | 다음 대기 세션 |
| Ctrl+Shift+K | 빠른 이동(항목·명령 찾기) |
| Ctrl+Shift+R | 가장 나중에 닫은 항목 다시 열기 |
| Ctrl+Shift+F / G / P / B | 찾기 / 변경 내용 / 자주 쓰는 지시 / 동시 입력 |

## 메뉴

사이드바 위에는 새 항목 단추(+ Claude, + PowerShell, + 워크트리, + 메모, + HTTP, + 사이트, + 이미지, + 브레인스토밍, + 그룹)가, 아래에는 대기·변경 내용 단추가 있습니다.
브라우저는 따로 뜨는 창이 아니라 사이드바의 사이트 항목입니다.
빠른 이동, 닫은 항목 다시 열기, 자주 쓰는 지시, 동시 입력, 기억 내보내기·가져오기는 창 상단의 도구 메뉴에, 단축키 보기는 도움말 메뉴에 있습니다.
설정 메뉴에서는 모양(테마·글꼴·글자 크기)을 바꾸고, Cypher 설정 파일과 Claude Code의 사용자 공통 설정(`~/.claude/settings.json`)·공통 지침(`~/.claude/CLAUDE.md`)을 엽니다.

## 설정

`%APPDATA%\cypher\config.toml`(상단 메뉴의 설정 → Cypher 설정 파일 열기). 고친 뒤 다시 시작하면 적용됩니다.
터미널 기본 글꼴, 링크 클릭 방식, 편집기 명령(`code -g {file}:{line}:{col}`), 알림, 세션 복원, 창 자석, 브라우저(엔진 포함), 프로필 추가를 정할 수 있습니다.

테마·글꼴·글자 크기는 설정 파일이 아니라 설정 → 모양에서 바꿉니다(바로 적용).
글자를 다루고 저장할 때의 인코딩은 UTF-8이 기본입니다: 새 메모·브레인스토밍·HTTP 요청 파일·출력 저장은 UTF-8로 쓰고, 다른 인코딩으로 된 파일은 읽을 때 알아보고 엽니다(메모는 그 파일의 인코딩을 지켜 저장). PowerShell·cmd 세션은 다른 프로그램과 주고받는 글자를 UTF-8로 맞춥니다(`[session] utf8 = false`로 끔). Claude 세션은 건드리지 않습니다.

메모의 쓰던 내용은 `%APPDATA%\cypher\memos`에 임시 저장됩니다. 닫은 메모는 바로 지우지 않고 `memos\closed`에 30일 동안 둡니다.

이 파일은 버전이 바뀌어도 그대로 쓰입니다. Cypher는 파일이 없을 때만 기본 파일을 만들고, 이미 있는 파일은 고치거나 덮어쓰지 않습니다.
모르는 항목은 무시하고 빠진 항목은 기본값을 씁니다. 새 버전에서 늘어난 항목은 같은 폴더의 `config.example.toml`에서 볼 수 있습니다(실행할 때마다 그 버전의 예시로 갱신).

사이드바 항목의 종류는 `ui/main.js`의 `KINDS`에 등록합니다. 새 종류는 화면을 만드는 함수 하나
(`create(item, host, saved, onChange)` → `{ ready, focus, title, state, close, dispose }`)를 올리면 사이드바·분할·그룹·복원에 그대로 들어갑니다.

모델·effort·한도·완료 알림은 세션을 띄울 때 `claude --settings <파일>`로 상태줄과 훅을 주입해서 받습니다.
사용자의 `settings.json`은 건드리지 않습니다.

## 쓰던 상태줄(HUD)과 함께 쓰기

Cypher는 모델·effort 등을 받으려고 Claude Code의 상태줄 자리에 전달 프로그램을 넣습니다.
그 자리는 하나뿐이지만, 이미 쓰던 상태줄이 있으면 전달 프로그램이 정보를 Cypher로 넘긴 뒤 그 명령을 이어서 실행해 출력을 그대로 내보냅니다.
그래서 세션 화면에는 쓰던 상태줄이 그대로 보이고, Cypher의 표시도 함께 동작합니다.

- 원래 상태줄은 Claude Code의 우선순위대로 찾습니다: 폴더의 `.claude/settings.local.json` → 폴더의 `.claude/settings.json` → 사용자 공통 `~/.claude/settings.json`.
- 여백(`padding`)은 원래 설정을 따르고, 갱신 주기는 둘 중 짧은 쪽(최대 5초)에 맞춥니다.
- 기존 훅, 플러그인, MCP 서버는 원래부터 그대로 함께 동작합니다.

## 보안 규칙

터미널 출력과 웹 페이지는 신뢰할 수 없는 입력으로 다룹니다.

- 링크는 `http`, `https`, `file`만 엽니다.
- 경로는 실제로 존재할 때만 링크가 됩니다.
- 실행 파일과 스크립트는 열지 않고 탐색기에서 보여 주기만 합니다.
- 네트워크 경로(`\\서버\…`)는 존재 확인도 하지 않습니다.
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령(터미널 입력, 파일 열기 등)을 부를 수 없습니다. 권한은 본창의 화면에만 줍니다(`crates/cypher-app/build.rs`).
- 본창의 화면에는 보안 정책(CSP)이 걸려 있어 화면 코드가 바깥과 통신하거나 바깥의 글줄·그림을 불러올 수 없습니다.
- 전달 프로그램이 접속하는 통로는 이 컴퓨터 안(127.0.0.1)에서만 열리고, 실행마다 새로 만든 확인값이 맞아야 받습니다.

### 바깥과의 통신

Cypher는 사용자가 시키지 않은 통신을 하지 않습니다. 업데이트 확인, 사용 통계, 오류 보고를 보내지 않습니다. 통신이 일어나는 곳은 다음뿐입니다.

| 언제 | 어디로 |
|---|---|
| 사이트 항목에 주소를 치거나, 되살린 사이트 항목을 화면에 띄울 때, 같은 그룹의 Claude 세션이 브라우저 도구를 쓸 때 | 그 웹 사이트 (주소가 아닌 글을 치면 Google 검색) |
| HTTP 항목에서 요청을 보내거나 Claude 세션이 `http_run`을 쓸 때 | 요청 파일에 적힌 주소 |
| 웹 페이지의 그림을 사이드바로 끌어다 놓을 때 | 그 그림의 주소(그림을 받아 이미지 항목으로 만듦) |
| 링크를 누르거나 사이트 항목의 "외부 브라우저"를 누를 때 | Windows 기본 브라우저가 엶 |
| 도움말 → 브라우저 엔진 정보에서 "최신 버전 확인"을 누를 때 | `googlechromelabs.github.io`(Chrome 안정판 버전 번호를 읽음. 보내는 정보 없음) |

- Claude Code, PowerShell 등 세션 안에서 도는 프로그램의 통신은 그 프로그램의 것입니다.
- 웹뷰 엔진(WebView2)이 뒤에서 스스로 하는 통신(구성 요소 갱신, 안정성 보고, 동기화 등)은 실행 인자로 꺼 두었습니다. 다만 WebView2 런타임 본체가 시작할 때 Microsoft 365 쪽으로 짧게 접속하는 것이 관찰되며, 이것은 런타임(Windows 구성 요소)의 동작이라 앱에서 끌 수 없습니다. 막으려면 Windows 방화벽이나 조직의 WebView2 정책을 써야 합니다.
- 엔진을 `chrome`으로 바꾸면 띄운 Chrome·Edge가 스스로 하는 통신(업데이트 확인 등)이 더해집니다.

## 시험

```
cargo test --workspace
```

화면까지 자동으로 확인하려면 웹뷰 원격 디버깅을 켜고 실행한 뒤, 그 포트(CDP)로 JS를 실행합니다.
화면 코드가 `window.cypher`(세션 열기·입력·화면 글자 읽기)과 `window.cypherErrors`(화면 오류 목록)를 내놓습니다.

```
target\debug\cypher.exe
```

## 브라우저(사이트 항목)와 Claude 연동

브라우저는 사이드바의 사이트 항목입니다("+ 사이트" 또는 Ctrl+Shift+O). 로그인 상태는 다음 실행에도 유지됩니다.
Cypher가 띄운 Claude 세션에는 `cypher` 도구 묶음(MCP)이 자동으로 연결되고, 그 세션과 **같은 그룹**(이름 붙인 그룹이 없으면 같은 폴더 묶음)의 항목을 다룹니다.

| 도구 | 하는 일 |
|---|---|
| `browser_read` | 지금 페이지의 주소·제목·글자와, 누르거나 입력할 수 있는 요소 목록(번호) |
| `browser_click` / `browser_type` / `browser_key` | 번호로 가리킨 요소 누르기, 글자 입력, 키 누르기 |
| `browser_screenshot` / `browser_click_at` | 화면을 그림으로 받아 보고, 그 그림의 좌표를 누르기 |
| `browser_navigate` / `browser_back` / `browser_scroll` / `browser_eval` | 이동, 뒤로, 스크롤, 페이지에서 스크립트 실행 |
| `browser_tabs` / `browser_select` | 같은 그룹의 브라우저 목록 보기, 조작 대상 바꾸기 |
| `cypher_items` | 같은 그룹의 항목 목록: 다른 세션, 메모·이미지·브레인스토밍의 파일 경로, 브라우저 주소, HTTP 요청 폴더 |
| `mindmap_write` | 브레인스토밍 항목을 개요 글로 만들거나 고치기 |
| `http_list` / `http_run` | 폴더의 `.http` 요청 나열, 요청 실행(기록 포함) |

어느 브라우저를 조작하는지는 이렇게 정해집니다.

1. 사용자가 사이트 항목의 "Claude에게"로 넘겨준 브라우저. 같은 그룹에 Claude 세션이 하나면 바로 넘어가고, 여러 개면 고르는 메뉴가 뜹니다(오른쪽 클릭: 고르기, 새 Claude 세션에 넘기기). 넘기면 그 세션 입력창에 머리말이 들어가고, 이어서 할 일을 적으면 됩니다. 넘겨받은 세션의 이름이 단추에 표시됩니다.
2. 넘겨받은 것이 없으면 같은 그룹에서 마지막으로 본 사이트 항목.
3. 그룹에 사이트 항목이 없는데 Claude가 주소로 이동하려 하면, 그 그룹에 새 사이트 항목을 만들어 세션 옆에 나란히 놓습니다.

- 화면에 띄워 두지 않은 사이트 항목도 조작할 수 있습니다(조작하는 동안만 보이지 않는 자리에서 화면을 그립니다).
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령을 부를 수 없습니다(위 보안 규칙).
- 조작은 디버깅 포트를 열지 않고 WebView2의 개발자 도구 프로토콜을 앱 안에서 직접 부릅니다.
- 도구를 쓸 때의 승인 절차는 Claude Code의 권한 설정을 그대로 따릅니다.
- 설정의 `[browser] enabled = false`로 도구 연결을 끌 수 있습니다.

### 브라우저 엔진: 내장 웹뷰와 Chrome

기본 엔진(`webview`)은 사이드바의 사이트 항목이며 Windows의 WebView2로, Edge와 같은 Chromium이며 Windows가 알아서 최신으로 갱신합니다.
다만 WebView2는 Windows에만 있고, macOS의 웹뷰는 Chromium이 아니어서 같은 방법으로 조작할 수 없습니다.
그래서 다른 OS에서도 쓸 수 있는 두 번째 엔진을 두었습니다.

```toml
[browser]
engine = "chrome"      # 설치된 Chrome → Edge → Chromium → Brave 순으로 찾아 띄움
# chrome_path = ""     # 다른 실행 파일을 쓰려면 경로를 적음
```

- 설치된 브라우저를 Cypher 전용 프로필(`%LOCALAPPDATA%\cypher\chrome-profile`)로 띄웁니다. 평소 쓰는 프로필과 로그인은 건드리지 않으며, 이 프로필의 로그인은 다음 실행에도 유지됩니다.
- 브라우저가 스스로 갱신하므로 늘 최신 Chromium이고, Cypher 배포 파일은 커지지 않습니다.
- 디버깅 포트를 열지 않고 Cypher와 브라우저만 아는 파이프(`--remote-debugging-pipe`)로 통신합니다. Cypher를 끝내면 이 브라우저도 함께 끝납니다.
- Claude가 쓰는 도구(`browser_read` 등)는 두 엔진에서 똑같이 동작합니다. 이 엔진에서는 그룹과 무관하게 그 Chrome 창에서 사용자가 보고 있는 탭을 조작합니다.
- 이 엔진을 고르면 사이드바 아래에 "Chrome"(열기)·"넘기기"·"캡처" 단추가 생깁니다. 처음 여는 주소는 빈 페이지입니다(`[browser] home`으로 바꿈).
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)은 Tauri 3이 아직 알파 단계이고 배포 파일이 수백 MB 늘어 쓰지 않았습니다.
- 파이프를 넘기는 부분만 OS별로 다릅니다(`crates/cypher-app/src/chrome.rs`의 `spawn`). 지금은 Windows용만 구현돼 있습니다.

### Chromium 버전 올리기

Cypher는 Chromium을 실행 파일에 싣지 않습니다. 그래서 엔진 버전은 Cypher 버전과 무관하게, 바깥의 브라우저가 갱신될 때 함께 올라갑니다.
Cypher를 새로 빌드하거나 배포할 필요가 없습니다.

| 엔진 | 누가 갱신하나 | 직접 갱신하려면 |
|---|---|---|
| `webview` | WebView2 런타임. Edge와 함께 Windows가 자동으로 갱신 | Edge에서 `edge://settings/help`, 또는 Microsoft의 "WebView2 런타임(Evergreen)" 설치 프로그램 실행 후 Cypher 다시 시작 |
| `chrome` | 설치된 Chrome·Edge의 자동 업데이트 | 그 브라우저에서 `chrome://settings/help`(Edge는 `edge://settings/help`) 후 Cypher용 브라우저 창을 닫았다 다시 열기 |

갱신이 멈춰 있지 않은지는 직접 확인할 수 있습니다.

- 도움말 → "브라우저 엔진 정보·업데이트 확인" 창에서 지금 엔진의 Chromium 버전을 볼 수 있습니다. 그 창의 "최신 버전 확인"을 누르면 Chrome 최신 안정판과 비교해 몇 단계 뒤처졌는지와 갱신 방법을 알려 줍니다.
- Cypher가 스스로 버전을 확인하러 나가지는 않습니다. 단추를 눌렀을 때만 Google이 공개하는 Chrome for Testing 목록(`googlechromelabs.github.io`)에서 버전 번호를 읽고, 이때 보내는 정보는 없습니다.
- 회사 정책 등으로 자동 업데이트가 꺼진 PC라면, `chrome_path`에 직접 관리하는 Chromium 실행 파일을 지정해 그 파일만 교체하는 방법도 있습니다.

Cypher 쪽에서 따로 챙길 것은 두 가지입니다.

- 조작에 쓰는 개발자 도구 프로토콜(CDP) 명령은 오래 유지돼 온 안정된 것만 씁니다(`Runtime.evaluate`, `Page.navigate`, `Page.captureScreenshot`, `Input.*`, `Target.*`). Chromium이 올라가 동작이 달라졌는지는 `cargo test -p cypher chrome -- --ignored`(설치된 브라우저를 실제로 띄워 파이프로 조작해 보는 시험)로 확인합니다.
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)으로 바꾸면 그때부터는 Chromium 버전이 Cypher 빌드에 고정되므로, 보안 갱신을 따라가려면 약 4주마다 Cypher를 다시 빌드·배포해야 합니다. 지금 구조를 택한 까닭 중 하나입니다.

## HTTP 요청 파일

사이드바의 "+ HTTP"(Ctrl+Shift+H)나 묶음 머리의 +로 HTTP 항목을 만듭니다. 항목은 만들 때 보고 있던 항목의 폴더를 따릅니다.
그 폴더의 `.cypher\http\`, `http\`, 또는 폴더 바로 아래의 `*.http`를 읽습니다.

```
@host = https://api.example.com

### 로그인
POST {{host}}/login
Content-Type: application/json

{"id": "kim"}
```

실행하면 요청 파일 옆 `history.http`에 요청과 응답이 덧붙습니다(인증 헤더 값과 환경 변수에서 읽은 값은 `***`로 가림).
기록 파일은 `.gitignore`에 자동으로 올라갑니다.

- 요청 줄은 `http://`·`https://` 주소나 `{{변수}}`로 시작해야 합니다. 요청 줄 왼쪽의 ▶나 Ctrl+Enter는 커서가 있는 그 요청만 보냅니다.
  주소를 채우지 못했거나(변수 오타 등) 요청이 아닌 줄에서는 다른 요청을 대신 보내지 않고 까닭을 알려 줍니다.
- 고친 내용은 입력이 멈추면 자동으로 저장됩니다(파일의 줄 끝 형식은 그대로 둡니다). 저장하지 못하면 항목을 닫거나 다른 파일로 옮기기 전에 알려 줍니다.
- 파일이 다른 곳(Claude 세션, 다른 HTTP 항목, 외부 편집기)에서 바뀌면, 편집기에 고친 내용이 없을 때 다시 읽습니다.
- 다른 도구의 틀 문법(`{{ $labels.instance }}`, `{{$json.name}}`처럼 점·괄호가 든 것)은 건드리지 않고 그대로 보냅니다.

### 내장 값과 서명(HMAC)

새 요청 파일의 기본 예시 맨 아래에 바로 보내 볼 수 있는 "서명(HMAC) 예시"가 들어 있습니다.

`{{이름}}`은 변수, `{{$이름 인자…}}`는 내장 값입니다. 인자는 변수 이름, `$내장값`, 또는 "따옴표 글"로 적습니다
(따옴표 안에서는 `{{…}}`를 다시 쓸 수 있습니다). 글자 그대로 쓰려면 반드시 따옴표로 감쌉니다. 따옴표 없는 이름은 변수로 보며, 그런 변수가 없으면 보내지 않고 알려 줍니다(변수 이름 오타가 그대로 키나 메시지로 쓰이지 않게).
값은 주소 → 본문 → 헤더 순으로 채워지므로 헤더의 서명에 주소와 본문을 쓸 수 있습니다.
`$host`·`$path`·`$query`·`$pathQuery`·`$url`은 실제로 전송되는 모양 그대로입니다(한글·공백은 퍼센트 인코딩, 기본 포트 생략).

| 적는 법 | 값 |
|---|---|
| `{{$timestamp}}` / `{{$timestampMs}}` | 지금 시각(Unix 초 / 밀리초). 한 요청 안에서는 같은 값 |
| `{{$isoTimestamp}}` / `{{$httpDate}}` | `2026-11-12T08:00:00Z` / `Thu, 12 Nov 2026 08:00:00 GMT` |
| `{{$uuid}}` / `{{$randomInt}}` | 무작위 UUID / 0~999. 같은 값을 여러 번 쓰려면 변수에 담습니다(변수는 요청마다 한 번만 계산) |
| `{{$method}}` `{{$url}}` `{{$host}}` `{{$path}}` `{{$query}}` `{{$pathQuery}}` `{{$body}}` | 이 요청의 부분들 |
| `{{$env 이름}}` | 환경 변수(비밀키를 파일에 적지 않으려 할 때) |
| `{{$base64 값}}` / `{{$base64url 값}}` | Base64로 바꾼 글 |
| `{{$hash 알고리즘 표기 값}}` | 해시 |
| `{{$hmac 알고리즘 표기 키 메시지}}` | HMAC 서명. 키가 16진수나 Base64 글이면 끝에 `key=hex` 또는 `key=base64` |

알고리즘은 `sha256`, `sha1`, `sha384`, `sha512`, `md5`, 표기는 `hex`, `hexupper`, `base64`, `base64url` 중 하나입니다.

```
@host = https://api.example.com
@secret = {{$env MY_API_SECRET}}
@nonce = {{$uuid}}
@message = {{$timestamp}}{{$method}}{{$pathQuery}}{{$body}}

### 주문 넣기
POST {{host}}/v1/orders?side=buy
Content-Type: application/json
X-Timestamp: {{$timestamp}}
X-Nonce: {{nonce}}
X-Body-SHA256: {{$hash sha256 hex $body}}
X-Signature: {{$hmac sha256 hex secret message}}

{"qty": 1}
```

값을 계산하지 못하면(모르는 알고리즘, 없는 환경 변수 등) 요청을 보내지 않고 까닭을 알려 줍니다.
보낸 요청 원문(서명이 채워진 헤더 포함)은 응답과 함께 화면에 나옵니다.
