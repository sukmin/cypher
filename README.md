# Cypher (사이퍼)

Claude Code 세션 여러 개를 한 창에서 띄우고 전환·감시하는 Windows용 업무 도구입니다.
사이드바에는 터미널 세션뿐 아니라 메모, HTTP 요청 같은 여러 종류의 항목을 놓을 수 있고, 업무 하나를 그룹 하나로 묶어 그 안에 필요한 것을 모아 둡니다.
화면에 나온 웹 주소와 파일 경로를 클릭하면 브라우저나 탐색기가 열립니다.

## 빌드와 실행

Rust(MSVC)만 있으면 됩니다. Node는 필요 없습니다.

```
cargo build --workspace --release
target\release\cypher.exe
```

창 제목에 버전이 표시됩니다(`Cargo.toml`의 `[workspace.package] version`).
`cypher.exe`와 `cypher-bridge.exe`는 같은 폴더에 있어야 합니다(모델 표시·완료 알림이 전달 프로그램을 거칩니다).
`CYPHER_AUTOSTART=claude` 환경 변수를 주고 실행하면 실행 위치 폴더에서 세션이 바로 열립니다.

## 기능

| 기능 | 설명 |
|---|---|
| 항목 모아보기 | 사이드바에 터미널 세션(Claude, PowerShell 등), 메모, HTTP, 사이트(브라우저), 이미지, 브레인스토밍, 문서 항목을 놓음. 폴더별로 묶이고, 이름 붙인 그룹으로 한 업무의 항목을 모을 수 있음. 사이드바의 빈 곳을 누른 뒤 ↑/↓(Home/End)로 항목 사이를 오감. 항목을 다른 줄의 위·아래로 끌면 순서가 바뀌고(다른 그룹의 줄이면 그 그룹으로 옮김), 이 순서는 다시 시작해도 유지되며 Ctrl+Tab도 이 순서를 따름 |
| 빠른 이동 | Ctrl+Shift+K로 찾기 창을 열어 항목의 이름·별칭·그룹·폴더나 앱의 명령(새 세션, 모양, 설정 …)을 글자로 찾아 Enter로 감. 초성으로도 찾음(`ㄱㅈ` → 결제). 아무것도 치지 않으면 최근에 본 순서라, 열자마자 Enter를 누르면 바로 전에 보던 항목으로 돌아감 |
| 닫은 항목 다시 열기 | 닫은 항목을 30일 동안 기억함. Ctrl+Shift+R은 가장 나중에 닫은 것을 같은 그룹·폴더·별칭·색으로 바로 다시 열고, 도구 → "닫은 항목 다시 열기"는 목록에서 고름. Claude 세션은 하던 대화를 이어 열고(대화가 없던 세션·다른 터미널은 같은 폴더에서 새로 시작), 메모·브레인스토밍·이미지는 보관해 둔 내용으로, 사이트·HTTP는 보던 주소·파일로 엶. 종료된 세션은 오른쪽 클릭 → "다시 시작"으로 사이드바와 화면의 같은 자리에서 다시 띄움 |
| 별칭 | 항목을 두 번 누르거나 ✎ 단추, 오른쪽 클릭 메뉴로 사이드바의 그 줄에서 바로 별칭을 붙임. 세션에는 영향이 없고 사이드바·창 제목·알림에 보이는 이름만 바뀜. 원래 이름(종류·폴더)은 옆에 흐리게 남음 |
| 사이드바 너비 | 사이드바와 화면 사이의 경계를 끌어 너비 조절(두 번 누르면 기본 너비). 다시 시작해도 유지 |
| 프롬프트 편집기 | 화면에 세션 하나만 보일 때(분할하지 않았을 때) 세션 아래에 글 편집기가 놓임. 긴 프롬프트를 여기서 쓰고 "프롬프트" 단추(Ctrl+Enter)를 누르면 그 세션의 입력창에 들어감. "바로 전송"을 켜면 Enter까지 눌러 보냄. 쓰던 글은 세션마다 기억하고, 높이 조절·접기 가능. 보낸 프롬프트는 50개까지 기억해 Alt+↑/↓로 넘겨 보거나 "기록" 단추에서 골라 다시 씀 |
| 메모 | 글자 편집기 항목. 찾기·바꾸기(대/소문자, 단어 단위, 정규식과 `$1` 그룹 바꾸기), 줄로 이동, 시간/날짜, 자동 줄 바꿈, 확대/축소, 상태 표시줄(줄/열, 글자 수, 200자 원고지 매수, 줄 끝, 인코딩), JSON 정리, 보이지 않는 문자 찾기·정리. 파일 열기·저장은 인코딩(UTF-8, UTF-8 BOM, UTF-16, CP949)과 줄 끝을 유지. 쓰던 내용은 계속 임시 저장되어 다시 시작해도 돌아옴. 파일에 연결된 메모는 그 파일이 다른 곳(Claude 세션, 다른 편집기)에서 바뀌면, 고치지 않은 메모는 스스로 다시 읽고, 고치던 메모는 저장할 때 "다시 읽기 / 덮어쓰기"를 물음(다시 읽으면 고치던 글은 30일 보관). 같은 파일을 메모로 두 번 열면 이미 열린 메모로 감 |
| 사이트(브라우저) | "+ 사이트"를 누르면 주소를 묻지 않고 빈 페이지가 바로 작업 화면에 뜨고, 위의 주소 칸에 주소(또는 검색어)를 쳐서 감. 설정 → "브라우저 시작 페이지…"에 주소를 적어 두면 새 사이트 항목이 빈 화면 대신 그 주소로 열림("chrome" 엔진의 브라우저도 처음 띄울 때 그 주소로 엶. 비우면 다시 빈 화면). 주소 칸 옆에 캡처, 즐겨찾기(☆), "Claude에게"(같은 이름 붙인 그룹의 Claude 세션에 이 브라우저를 넘김. 세션이 여러 개면 고름. 그룹에 넣지 않은 사이트 항목은 넘길 수 없음), "외부 브라우저"(지금 주소를 Windows 기본 브라우저로 엶) 단추. 뒤로·앞으로·새로 고침, 처음 간 주소로 돌아가기. 보던 주소와 제목을 기억하고 다시 시작하면 되살림. 로그인 상태는 같은 그룹의 사이트 항목끼리만 함께 씀(그룹마다 브라우저 프로필이 따로. 그룹 없는 사이트 항목끼리는 공용 프로필). 메뉴·대화상자가 열려 있는 동안에는 페이지를 잠시 가림 |
| 이미지 | 그림을 항목으로 두고 봄. 만드는 방법: "+ 이미지"로 파일 고르기·붙여넣기(Ctrl+V), 이미지 파일이나 브라우저의 그림을 끌어다 놓기, 브라우저·사이트 화면 캡처. 형식은 웹에서 쓰는 것(PNG, JPEG, GIF, WebP, BMP, SVG, AVIF, ICO). 창에 맞춤(F)·실제 크기(1)·확대/축소(+/-, Alt 또는 Ctrl+휠은 커서 기준)·끌어서 이동, 휠과 ←/→로 같은 묶음의 이전·다음 이미지, 정보 표시(I), 복사(Ctrl+C)·다른 곳에 저장(Ctrl+S), 그림 경로를 Claude 세션 입력창에 넣기. 그림은 `%APPDATA%\cypher\images`에 복사해 두므로 원본을 옮기거나 지워도 남고, 닫은 이미지는 30일 동안 보관 |
| 화면 캡처 | 사이트 항목 주소 칸 옆의 "캡처" 단추로 보이는 화면을 찍어 그 항목과 같은 묶음의 이미지 항목으로 넣음(Shift+클릭은 페이지 전체). 찍은 페이지의 제목이 이름, 주소가 출처로 남음 |
| 끌어다 놓기 | 파일·글자·링크·그림을 창에 끌어다 놓으면 알맞게 처리. 사이드바(묶음 머리나 그 안의 줄에 놓으면 그 묶음)·빈 화면·메모나 터미널이 아닌 창에 놓으면 항목이 됨: 이미지 → 이미지 항목, 글자 파일·끌어 온 글자 → 메모, `.http` → HTTP, 링크·인터넷 바로 가기(`.url`) → 사이트. 터미널과 프롬프트 편집기에 놓으면 파일은 경로를, 글자는 그대로 입력. 메모 창에 놓은 글자 파일은 그 메모로 엶. 보던 화면은 바꾸지 않고 사이드바에만 놓으며(화면이 비어 있으면 바로 보여 줌), 새 항목은 표시가 켜짐 |
| 화면 분할 | 사이드바의 세션을 화면으로 끌어다 놓으면 놓은 위치대로 나뉨(창의 왼쪽·오른쪽 가장자리는 좌우 분할, 위·아래 가장자리는 상하 분할, 가운데는 그 자리에 열기). 창 사이 경계선을 끌어 크기 조절(두 번 누르면 반반). 창 제목 줄의 "이 창만"(분할 풀기)·"숨기기" 단추와 세션 우클릭 메뉴, 사이드바 세션 줄의 ◉/○ 단추로 한 창만 남기거나 창을 숨기고 다시 보임(세션은 사이드바에 남아 계속 실행). 최대 8개, 분할 모양과 비율은 다시 시작해도 유지 |
| 링크 클릭 | 웹 주소는 브라우저, 폴더는 탐색기, 파일은 탐색기에서 선택. Ctrl+클릭은 파일 열기. 경로나 주소 뒤에 조사가 붙어 있어도(`src/main.rs를`, `https://example.com/docs에서`) 조사를 뺀 부분을 링크로 잡음 |
| 이미지 붙여넣기 | Ctrl+V 하나로 글자·파일·이미지를 구분. 붙여넣은 이미지는 터미널 아래에 미리보기 |
| 모델·effort 표시 | 세션마다 모델, effort, 컨텍스트 사용률, 비용. 컨텍스트 80% 이상이면 색 경고 |
| 서브에이전트 표시 | 돌고 있는 서브에이전트 수를 세션 줄에 도는 고리와 숫자로, 그 아래 줄에 종류별 개수("서브에이전트 2개 실행 중 · Explore 2")로 표시. 묶음 머리에는 합계가 보여 접어 두어도 알 수 있음. 서브에이전트가 도는 동안의 중간 멈춤은 완료로 알리지 않고, 모두 끝난 뒤의 완료만 알림 |
| 사용 한도·사용량 | 창 아래에 5시간·주간 한도. 세션별 CPU·메모리는 사이드바에 표시 |
| 완료 알림 | 응답이 끝나거나 승인을 기다리면 앱 안 알림, 창이 뒤에 있으면 Windows 알림. 컨텍스트가 90%를 넘으면 한 번 알림 |
| 작업 시간 | Claude 세션이 요청을 처리하는 동안 사이드바의 그 줄에 경과 시간(3:24)을 보여 주고, 끝나면 걸린 시간을 줄과 완료 알림에 남김("완료 · 5분 12초 걸림"). Esc로 중단한 요청에는 Claude Code가 완료 신호를 보내지 않으므로, Esc·Ctrl+C를 누른 뒤 몇 초 조용하면(또는 30초 동안 아무 출력이 없으면) 경과 시간을 멈춤 |
| 대기 모아보기 | 대기 중인 세션만 보기, Ctrl+Shift+N으로 다음 대기 세션 이동 |
| 변경 내용 | 세션 폴더의 바뀐 파일 목록과 차이를 옆 창에 표시(git). 차이에는 옛·새 파일의 줄 번호가 붙음. **줄을 골라 지시하기**: 줄을 누르거나 끌어 고르고(Shift+클릭: 범위, 다시 누르면 풂) 아래 칸에 한마디를 적어 Enter를 누르면 "파일·줄 번호 + 고른 차이 + 한마디"가 Claude 세션의 입력창에 들어감(보내지는 않음). 보고 있던 항목이 Claude 세션이면 그 세션에, 아니면 같은 묶음의 Claude 세션에 넣고(여럿이면 고름), 셸에는 넣지 않음. **되돌리기**: 파일을 오른쪽 클릭 → "이 파일의 변경 되돌리기"는 고쳤거나 지운 파일을 마지막 커밋의 내용으로 돌리고, 되돌리기 전의 차이를 `%LOCALAPPDATA%\cypher\reverted`에 `.patch`로 30일 동안 보관(`git apply`로 되살림). 새 파일은 지우지 않고, 이름 변경·충돌 상태는 거절. **커밋**: [커밋…]에서 파일을 고르고 메시지를 적어 고른 파일만 커밋(푸시는 하지 않음, 훅·서명은 저장소 설정대로). 실패하면 git의 말을 창 안에 보여 줌 |
| 문서 | "+ 문서"로 Markdown·글자 파일을 골라 서식 있는 모습으로 읽음(제목, 굵게·기울임·취소선, 코드, 중첩·체크 목록, 인용, 표, 링크). 파일이 바뀌면 보던 자리를 지킨 채 스스로 다시 그리므로, Claude가 고치는 계획서·보고서를 옆에 띄워 두고 볼 수 있음. 목차, 찾기(Ctrl+F), 글자 크기(Ctrl+휠), 다른 `.md`로 가는 링크는 그 자리에서 열고 [뒤로](Alt+←), [메모로 편집], [Claude에 넣기](경로를 세션 입력창에), 코드 블록 복사. 파일 안의 HTML은 실행하지 않고 글자로 보이며, 그림은 불러오지 않음. `.md`가 아닌 글자 파일은 고정폭 글 그대로 |
| 만든 파일 놓기 | Claude 세션이 Write 도구로 새로 만든 문서(.md, .txt)·SVG 그림·요청 파일(.http)을 종류에 맞는 항목(문서·이미지·HTTP)으로 그 세션의 묶음에 자동으로 놓고 알림으로 알려 줌. 보던 화면은 바꾸지 않음. 한 요청에 8개까지, 설정의 `show_created`로 끄거나 넓힘 |
| 알림 기록 | 떴다가 사라지는 알림(완료와 걸린 시간, 승인·입력 대기, 컨텍스트 경고, Claude가 보낸 알림, Claude가 놓은 항목, 오류)을 7일 동안 200개까지 모아 둠. 사이드바 아래 [알림 N]의 숫자는 아직 보지 않은 알림. Ctrl+Shift+A로 목록을 열어 누르면 그 항목으로 감. 그 항목을 열거나 목록을 열면 읽은 것으로 침 |
| 그룹 틀 | 묶음 하나의 구성을 파일로 저장해 두고 같은 종류의 업무를 시작할 때 한 번에 펼침. 묶음 머리 오른쪽 클릭 → "틀로 저장", 펼치기는 도구 → 그룹 틀. 담기는 것: 세션(프로필·폴더 — 대화는 담지 않고 새로 시작), 메모(글 또는 연결된 파일), 브레인스토밍(개요 글), 사이트(주소), HTTP(요청 폴더·파일), 문서(파일 경로), 별칭·색. 이미지는 담지 않음. 저장해 둔 폴더가 없어졌으면 지금의 새 세션 폴더에서 열고, "이 폴더에서"는 모든 항목을 지금의 새 세션 폴더에서 엶. 틀은 `%APPDATA%\cypher\templates\<이름>.json`(복사해 다른 PC로 옮길 수 있음) |
| 자주 쓰는 지시 | 문장을 저장해 두고 클릭 한 번으로 입력 |

## 메뉴

사이드바 위에는 새 항목 단추(+ Claude, + PowerShell, + 메모, + HTTP, + 사이트, + 이미지, + 브레인스토밍, + 문서, + 그룹)가, 아래에는 대기·알림·변경 내용 단추가 있습니다.
브라우저는 따로 뜨는 창이 아니라 사이드바의 사이트 항목입니다.
빠른 이동, 닫은 항목 다시 열기, 알림 기록, 그룹 틀, 자주 쓰는 지시, 동시 입력, 기억 내보내기·가져오기는 창 상단의 도구 메뉴에, 단축키 보기는 도움말 메뉴에 있습니다.
설정 메뉴에서는 모양(테마·글꼴·글자 크기)과 브라우저 시작 페이지를 바꾸고, Cypher 설정 파일과 Claude Code의 사용자 공통 설정(`~/.claude/settings.json`)·공통 지침(`~/.claude/CLAUDE.md`)을 엽니다.

## 설정

`%APPDATA%\cypher\config.toml`(상단 메뉴의 설정 → Cypher 설정 파일 열기). 고친 뒤 다시 시작하면 적용됩니다.
터미널 기본 글꼴, 링크 클릭 방식, 편집기 명령(`code -g {file}:{line}:{col}`), 알림, 세션 복원, Claude가 만든 파일을 사이드바에 놓을지(`show_created`), 창 자석, 브라우저(엔진 포함), 프로필 추가를 정할 수 있습니다.

테마·글꼴·글자 크기는 설정 파일이 아니라 설정 → 모양에서 바꿉니다(바로 적용).
글자를 다루고 저장할 때의 인코딩은 UTF-8이 기본입니다: 새 메모·브레인스토밍·HTTP 요청 파일·출력 저장은 UTF-8로 쓰고, 다른 인코딩으로 된 파일은 읽을 때 알아보고 엽니다(메모는 그 파일의 인코딩을 지켜 저장). PowerShell·cmd 세션은 다른 프로그램과 주고받는 글자를 UTF-8로 맞춥니다(`[session] utf8 = false`로 끔). Claude 세션은 건드리지 않습니다.

메모의 쓰던 내용은 `%APPDATA%\cypher\memos`에 임시 저장됩니다. 닫은 메모는 바로 지우지 않고 `memos\closed`에 30일 동안 둡니다.

이 파일은 버전이 바뀌어도 그대로 쓰입니다. Cypher는 파일이 없을 때만 기본 파일을 만들고, 이미 있는 파일은 고치거나 덮어쓰지 않습니다.
모르는 항목은 무시하고 빠진 항목은 기본값을 씁니다. 새 버전에서 늘어난 항목은 같은 폴더의 `config.example.toml`에서 볼 수 있습니다(실행할 때마다 그 버전의 예시로 갱신).

## 쓰던 상태줄(HUD)과 함께 쓰기

Cypher는 모델·effort 등을 받으려고 Claude Code의 상태줄 자리에 전달 프로그램을 넣습니다.
그 자리는 하나뿐이지만, 이미 쓰던 상태줄이 있으면 전달 프로그램이 정보를 Cypher로 넘긴 뒤 그 명령을 이어서 실행해 출력을 그대로 내보냅니다.
그래서 세션 화면에는 쓰던 상태줄이 그대로 보이고, Cypher의 표시도 함께 동작합니다.

- 원래 상태줄은 Claude Code의 우선순위대로 찾습니다: 폴더의 `.claude/settings.local.json` → 폴더의 `.claude/settings.json` → 사용자 공통 `~/.claude/settings.json`.
- 여백(`padding`)은 원래 설정을 따르고, 갱신 주기는 둘 중 짧은 쪽(최대 5초)에 맞춥니다.
- 기존 훅, 플러그인, MCP 서버는 원래부터 그대로 함께 동작합니다.

## 보안 규칙

터미널 출력과 웹 페이지는 신뢰할 수 없는 입력으로 다룹니다.

- 링크는 `http`, `https`, `file`만 엽니다.
- 경로는 실제로 존재할 때만 링크가 됩니다.
- 실행 파일과 스크립트는 열지 않고 탐색기에서 보여 주기만 합니다.
- 네트워크 경로(`\\서버\…`)는 존재 확인도 하지 않습니다.
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령(터미널 입력, 파일 열기 등)을 부를 수 없습니다. 권한은 본창의 화면에만 줍니다(`crates/cypher-app/build.rs`).
- 본창의 화면에는 보안 정책(CSP)이 걸려 있어 화면 코드가 바깥과 통신하거나 바깥의 글줄·그림을 불러올 수 없습니다.
- 전달 프로그램이 접속하는 통로는 이 컴퓨터 안(127.0.0.1)에서만 열리고, 실행마다 새로 만든 확인값이 맞아야 하며, 접속한 프로세스가 적어 보낸 세션 번호의 세션이 실제로 띄운 프로세스여야 받습니다(세션 안에서 다른 세션의 번호를 적어 접속하는 것을 막음. 같은 사용자 권한으로 다른 프로세스를 조작하는 것까지 막지는 못함).
- 문서 항목은 파일의 내용을 글자로만 다룹니다. 파일 안의 HTML·스크립트는 실행하지 않고 글자 그대로 보이며, 링크는 `http`·`https`와 이 컴퓨터의 파일만 엽니다(네트워크 경로와 `javascript:` 같은 것은 링크가 되지 않습니다). 그림은 불러오지 않습니다.
- 그룹 틀 파일은 다른 사람에게서 받은 것일 수 있으므로, 펼칠 때 이 PC에 등록된 프로필과 항목 종류만 만들고 저장소 번호처럼 이 PC의 다른 항목을 가리키는 값은 받지 않습니다. 다만 틀에 든 사이트 주소와 파일 경로는 그대로 열리므로, 믿을 수 있는 틀만 펼치세요.
- Claude 세션이 도구로 다룰 수 있는 것은 그 세션과 같은 이름 붙인 그룹의 항목뿐입니다. 그룹 없는 것끼리와 세션끼리는 다룰 수 없습니다(아래 "Claude 세션이 다룰 수 있는 범위").
- Claude 세션이 도구로 메모를 통째로 바꿀 때는 바꾸기 전 글을 30일 동안 보관합니다. 이미지·문서로 놓을 수 있는 것은 이 컴퓨터의 파일뿐입니다(네트워크 경로는 받지 않음).
- 변경 내용의 되돌리기·커밋은 저장소 안의 상대 경로만 받고, 되돌리기는 화면이 본 상태가 아니라 그 순간의 git 상태를 다시 읽어 판단합니다.

### 바깥과의 통신

Cypher는 사용자가 시키지 않은 통신을 하지 않습니다. 업데이트 확인, 사용 통계, 오류 보고를 보내지 않습니다. 통신이 일어나는 곳은 다음뿐입니다.

| 언제 | 어디로 |
|---|---|
| 사이트 항목에 주소를 치거나, 되살린 사이트 항목을 화면에 띄울 때, 시작 페이지를 정해 둔 채 새 사이트 항목을 만들 때, 같은 그룹의 Claude 세션이 브라우저 도구를 쓸 때 | 그 웹 사이트 (주소가 아닌 글을 치면 Google 검색) |
| HTTP 항목에서 요청을 보내거나 Claude 세션이 `http_run`을 쓸 때 | 요청 파일에 적힌 주소 |
| 웹 페이지의 그림을 사이드바로 끌어다 놓을 때 | 그 그림의 주소(그림을 받아 이미지 항목으로 만듦) |
| 링크를 누르거나 사이트 항목의 "외부 브라우저"를 누를 때 | Windows 기본 브라우저가 엶 |
| 도움말 → 브라우저 엔진 정보에서 "최신 버전 확인"을 누를 때 | `googlechromelabs.github.io`(Chrome 안정판 버전 번호를 읽음. 보내는 정보 없음) |

- Claude Code, PowerShell 등 세션 안에서 도는 프로그램의 통신은 그 프로그램의 것입니다.
- 웹뷰 엔진(WebView2)이 뒤에서 스스로 하는 통신(구성 요소 갱신, 안정성 보고, 동기화 등)은 실행 인자로 꺼 두었습니다. 다만 WebView2 런타임 본체가 시작할 때 Microsoft 365 쪽으로 짧게 접속하는 것이 관찰되며, 이것은 런타임(Windows 구성 요소)의 동작이라 앱에서 끌 수 없습니다. 막으려면 Windows 방화벽이나 조직의 WebView2 정책을 써야 합니다.
- 엔진을 `chrome`으로 바꾸면 띄운 Chrome·Edge가 스스로 하는 통신(업데이트 확인 등)이 더해집니다.

## 시험

```
cargo test --workspace
```

화면까지 자동으로 확인하려면 웹뷰 원격 디버깅을 켜고 실행한 뒤, 그 포트(CDP)로 JS를 실행합니다.
화면 코드가 `window.cypher`(세션 열기·입력·화면 글자 읽기)과 `window.cypherErrors`(화면 오류 목록)를 내놓습니다.

```
set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333
set WEBVIEW2_USER_DATA_FOLDER=<시험용 빈 폴더>
target\debug\cypher.exe
```

`WEBVIEW2_USER_DATA_FOLDER`가 있으면 웹뷰 엔진은 앱이 정한 데이터 폴더를 무시하고 그 폴더만 씁니다. 그대로 두면 그룹별 브라우저 프로필이 한 폴더로 합쳐지므로, Cypher는 본창이 뜬 뒤 이 변수를 자기 프로세스에서 지우고 그룹 없는 사이트 항목에만 그 폴더를 직접 지정합니다. 그룹별 프로필은 `%LOCALAPPDATA%\cypher\site-profiles`에 생기므로, 사용자 데이터와 섞이지 않게 하려면 `LOCALAPPDATA`·`APPDATA`도 시험용 폴더로 돌려 실행합니다.

## 브라우저(사이트 항목)와 Claude 연동

브라우저는 사이드바의 사이트 항목입니다("+ 사이트" 또는 Ctrl+Shift+O). 로그인 상태는 다음 실행에도 유지됩니다.

### 그룹마다 따로인 브라우저 프로필

로그인 상태(쿠키·저장소)는 **같은 그룹의 사이트 항목끼리만** 함께 씁니다. 그룹마다 브라우저 프로필(데이터 폴더)이 따로 있어서, 한 그룹에서 로그인해 둔 계정을 다른 그룹의 사이트 항목이나 그 그룹의 Claude 세션이 쓸 수 없습니다.

- 프로필은 `%LOCALAPPDATA%\cypher\site-profiles\<프로필 번호>`에 둡니다. 어느 그룹이 어느 번호를 쓰는지는 Cypher가 기억합니다.
- **그룹 이름을 바꿔도** 프로필은 그대로라 로그인 상태가 유지됩니다(바꾼 이름으로 예전에 없앤 그룹의 프로필이 남아 있어도 지금 그룹의 것이 따라갑니다).
- **그룹을 없애도 프로필은 지우지 않습니다.** 같은 이름으로 그룹을 다시 만들면 예전 프로필(로그인 상태)을 다시 씁니다. 로그인 정보까지 없애려면 Cypher를 끈 뒤 `site-profiles`(chrome 엔진은 `chrome-profiles`) 아래의 폴더를 지웁니다. 폴더 이름은 프로필 번호라 어느 그룹의 것인지 드러나지 않으므로, 가려 지우기 어렵다면 모두 지우고 그룹마다 다시 로그인합니다.
- **사이트 항목을 다른 그룹으로 옮기면** 보던 주소는 그대로 두고 새 그룹의 프로필로 다시 엽니다. 옛 그룹의 로그인 상태는 따라가지 않습니다. 이미 있는 그룹에 합칠 때도 같습니다. 옮기는 순간에 옛 그룹의 Claude 세션이 그 브라우저를 조작하고 있었다면 그 조작은 "다른 그룹으로 옮겨졌다"는 오류로 끝납니다(옛 그룹의 로그인 상태로 되살아나지 않습니다). 조작하던 사이트 항목을 닫았을 때도 그 조작은 오류로 끝나고, 닫은 항목이 보이지 않는 곳에서 다시 열리지 않습니다.
- **그룹이 없는 사이트 항목**은 공용 프로필을 씁니다(이전 버전에서 쓰던 그 프로필). Claude 세션은 그룹 없는 사이트 항목을 조작할 수 없습니다.
- 이전 버전에서 그룹에 넣어 쓰던 사이트 항목은 이번 버전부터 그 그룹의 새 프로필을 쓰므로 **한 번 다시 로그인해야 합니다**.
- 그룹마다 브라우저 엔진 프로세스가 따로 뜨므로, 사이트 항목을 쓰는 그룹이 많으면 메모리를 그만큼 더 씁니다(사이트 항목을 실제로 띄운 그룹만).
Cypher가 띄운 Claude 세션에는 `cypher` 도구 묶음(MCP)이 자동으로 연결되고, 그 세션과 **같은 이름 붙인 그룹**의 항목만 다룹니다.

### Claude 세션이 다룰 수 있는 범위

- **같은 그룹 안에서만**: 도구는 그 세션과 같은 이름 붙인 그룹에 있는 항목(메모, 브레인스토밍, 사이트, HTTP, 문서, 이미지)만 다룹니다. 다른 그룹의 항목은 번호를 알아도 다룰 수 없고, 목록에도 나오지 않습니다.
- **그룹 없는 것끼리는 다룰 수 없음**: 그룹 없이 폴더 묶음에 있는 세션과 항목은 같은 폴더에서 열었더라도 서로 다룰 수 없습니다. 그룹 없는 Claude 세션은 브라우저 조작, 기존 항목 고치기, HTTP 도구를 쓸 수 없고, 자기 폴더 묶음에 새 항목을 놓는 것(메모·이미지·문서·브레인스토밍)과 알림만 할 수 있습니다(놓은 뒤에는 그것도 고칠 수 없습니다). 조작을 맡기려면 세션과 항목을 한 그룹에 넣습니다(오른쪽 클릭 → 그룹 지정, 또는 묶음 머리로 끌기).
- **세션끼리는 다룰 수 없음**: Claude 세션이 다른 세션(다른 Claude 세션 포함)에 글을 넣거나 조작하는 도구는 없습니다. 같은 그룹의 다른 세션은 목록에 이름과 상태만 보입니다.
- **다른 세션의 번호를 적어 보내도 받지 않음**: 도구 요청과 상태·완료 신호에는 "몇 번 세션이 보냈다"가 적혀 오지만, Cypher는 그 번호를 믿지 않고 접속한 프로세스가 실제로 그 세션이 띄운 프로세스인지(조상을 따라 올라가) 확인합니다. 다른 세션의 번호를 적어 보낸 요청, 번호가 없는 요청, 세션 밖의 프로세스가 보낸 요청은 받지 않습니다(확인값이 맞는 접속을 받지 않았을 때는 사유별로 한 번씩 `%LOCALAPPDATA%\cypher\cypher.log`에 남김). 평범한 방법(세션 안에서 통로에 직접 접속하기)은 막지만, 같은 Windows 사용자 권한으로 다른 프로세스 자체를 조작하는 것(부모 프로세스 위조, 코드 주입)까지 막지는 못합니다.
- **넘기기도 같은 그룹 안에서만**: 사이트 항목의 "Claude에게"는 같은 그룹의 Claude 세션에만 넘깁니다. 넘겨받은 뒤 어느 한쪽이 다른 그룹으로 옮겨지면 더는 조작하지 못합니다.
- **HTTP 도구**: `http_list`·`http_run`은 같은 그룹에 있는 HTTP 항목의 요청 폴더와 그 세션을 시작한 폴더의 요청 파일(폴더 바로 아래, `http`, `.cypher\http`)에만 씁니다. 그 밖의 폴더(시작 폴더 아래의 다른 하위 폴더 포함)의 요청은 그 폴더를 보는 HTTP 항목을 같은 그룹에 두어야 다룰 수 있습니다. 워크트리 세션(`claude --worktree`)은 시작 폴더가 저장소 뿌리라서, 워크트리 안의 요청을 다루려면 그 폴더의 HTTP 항목이 필요합니다. 폴더 기준 규칙이므로, 다른 그룹의 HTTP 항목이 이 세션의 시작 폴더와 같은 폴더(또는 그 `http`·`.cypher\http`)를 보고 있다면 같은 요청 파일을 함께 다루게 됩니다.
- **"chrome" 엔진도 그룹별**: 이 엔진에서는 그룹마다 Chrome을 따로 띄우고 프로필도 따로 씁니다. Claude 세션은 자기 그룹의 Chrome만 조작하고, 그룹 없는 세션은 조작할 수 없습니다.
- 사용자가 직접 하는 일(변경 내용에서 고른 줄을 세션에 넣기, 이미지 경로를 세션에 넣기)은 이 제한과 무관합니다.

이 제한이 막지 못하는 것:

- **파일**: 제한은 Cypher 도구에 한한 것입니다. Claude Code는 자기 권한 설정 안에서 이 컴퓨터의 파일을 직접 읽고 쓸 수 있으므로, 다른 그룹의 메모·브레인스토밍·이미지가 저장된 파일(`%APPDATA%\cypher`)이나 다른 세션의 폴더는 Cypher가 막지 못합니다. 그런 접근은 Claude Code의 권한 설정으로 다룹니다.

### Claude 세션이 만든 파일

Claude 세션이 Write 도구로 **새 파일**을 만들면 종류에 맞는 항목으로 그 세션의 묶음(그룹, 그룹이 없으면 폴더 묶음)에 놓고 알림으로 알려 줍니다. 보던 화면은 바꾸지 않습니다.

| 만든 파일 | 놓이는 항목 |
|---|---|
| `.md`, `.markdown`, `.txt` | 문서 항목(파일이 바뀌면 스스로 다시 그림) |
| `.svg` 등 그림 | 이미지 항목(Write 도구는 글자만 쓰므로 사실상 SVG) |
| `.http` | HTTP 항목. 파일이 `<폴더>\http`나 `<폴더>\.cypher\http`에 있으면 그 `<폴더>`의 항목으로, 아니면 파일이 든 폴더의 항목으로 놓고, 그 폴더를 보는 HTTP 항목이 이미 있으면 새로 만들지 않고 그 항목의 파일 목록을 다시 읽음 |

- 새 파일인지는 쓰기 직전에 그 파일이 없었는지로 가립니다. 이미 있던 파일을 고쳐 쓴 것은 놓지 않습니다.
- 한 세션에서 같은 파일은 한 번만 놓고, 그 묶음의 문서·메모·HTTP 항목이 이미 보여 주는 파일은 놓지 않습니다.
- 세션이 일하는 폴더 아래의 숨김 폴더(`.git`, `.claude` …)·`node_modules`·`target`·`dist`·`build` 안의 파일, Claude Code의 설정·기억 폴더와 Cypher 저장소·임시 폴더의 파일, 네트워크 경로의 파일은 놓지 않습니다(`.cypher\http`의 요청 파일은 놓습니다).
- 그룹이 없는 세션이 만든 `.http`는 그 세션의 시작 폴더가 보는 요청 파일(폴더 바로 아래, `http`, `.cypher\http`)일 때만 HTTP 항목이 되고, 다른 폴더(시작 폴더의 다른 하위 폴더 포함)의 것은 다른 폴더 묶음에 끼어들지 않도록 자기 묶음의 문서 항목으로 보여 줍니다.
- 한 요청에서 8개까지만 놓고, 넘치면 한 번 알립니다.
- 명령(Bash 등)으로 만든 파일은 알 수 없어 놓지 않습니다. 그런 파일은 Claude가 `doc_show`·`image_add`로 놓을 수 있습니다.
- 설정의 `[session] show_created`로 바꿉니다: `"known"`(기본), `"all"`(코드 같은 그 밖의 글자 파일도 문서 항목으로), `"off"`(놓지 않음, Write 도구의 훅도 걸지 않음).

| 도구 | 하는 일 |
|---|---|
| `browser_read` | 지금 페이지의 주소·제목·글자와, 누르거나 입력할 수 있는 요소 목록(번호) |
| `browser_click` / `browser_type` / `browser_key` | 번호로 가리킨 요소 누르기, 글자 입력, 키 누르기 |
| `browser_screenshot` / `browser_click_at` | 화면을 그림으로 받아 보고, 그 그림의 좌표를 누르기 |
| `browser_navigate` / `browser_back` / `browser_scroll` / `browser_eval` | 이동, 뒤로, 스크롤, 페이지에서 스크립트 실행 |
| `browser_tabs` / `browser_select` | 같은 그룹의 브라우저 목록 보기, 조작 대상 바꾸기 |
| `browser_dialog` | 페이지가 다음에 띄우는 확인 창(alert·confirm·prompt, 나가기 확인) 하나에 줄 답 정하기. 정하지 않으면 조작 중에 뜬 창은 Cypher가 바로 닫고(alert는 확인, confirm·prompt는 취소, 나가기 확인은 나가기) 그 사실을 도구의 답에 적음. 도구가 쓰고 있지 않을 때 뜬 창은 사용자가 답하도록 그대로 두고, 그 창이 떠 있는 채로 도구가 시작되면 닫고 시작함 |
| `cypher_items` | 같은 그룹의 항목 목록: 다른 세션(이름·상태만), 메모·이미지·브레인스토밍·문서의 파일 경로, 브라우저 주소, HTTP 요청 폴더. 그룹이 없는 세션에는 목록 대신 그 사실을 알려 줌 |
| `mindmap_write` | 브레인스토밍 항목을 개요 글로 만들거나 고치기 |
| `memo_write` | 메모 항목 만들기. 번호(id)를 주면 그 메모의 끝에 덧붙이거나(`append`, 기본) 통째로 바꾸기(`replace`, 바꾸기 전 글은 30일 보관) |
| `image_add` | 이 컴퓨터의 그림 파일(절대 경로)을 같은 그룹의 이미지 항목으로 넣기 |
| `doc_show` | 이 컴퓨터의 Markdown·글자 파일(절대 경로)을 같은 그룹의 문서 항목으로 놓기. 이미 그 파일을 보여 주는 문서가 있으면 그것을 새로 읽음 |
| `notify_user` | 사용자에게 알림 띄우기(앱 안 알림, 창이 뒤에 있으면 Windows 알림, 알림 기록) |
| `http_list` / `http_run` | 폴더의 `.http` 요청 나열, 요청 실행(기록 포함) |

어느 브라우저를 조작하는지는 이렇게 정해집니다.

1. 사용자가 사이트 항목의 "Claude에게"로 넘겨준 브라우저. 같은 그룹에 Claude 세션이 하나면 바로 넘어가고, 여러 개면 고르는 메뉴가 뜹니다(오른쪽 클릭: 고르기, 새 Claude 세션에 넘기기). 넘기면 그 세션 입력창에 머리말이 들어가고, 이어서 할 일을 적으면 됩니다. 넘겨받은 세션의 이름이 단추에 표시됩니다.
2. 넘겨받은 것이 없으면 같은 그룹에서 마지막으로 본 사이트 항목.
3. 그룹에 사이트 항목이 없는데 Claude가 주소로 이동하려 하면, 그 그룹에 새 사이트 항목을 만들어 세션 옆에 나란히 놓습니다.

- Claude가 놓거나 고친 항목(메모·이미지·문서)은 보던 화면을 바꾸지 않고 사이드바에만 놓이며, 알림으로 알려 줍니다(누르면 그 항목이 열림). 같은 항목에 같은 일을 잇달아 하면 알림은 처음 한 번만 뜹니다.
- 화면에 띄워 두지 않은 사이트 항목도 조작할 수 있습니다(조작하는 동안만 보이지 않는 자리에서 화면을 그립니다).
- 사이트 항목이 여는 웹 페이지는 Cypher의 내부 명령을 부를 수 없습니다(위 보안 규칙).
- 조작은 디버깅 포트를 열지 않고 WebView2의 개발자 도구 프로토콜을 앱 안에서 직접 부릅니다.
- 도구를 쓸 때의 승인 절차는 Claude Code의 권한 설정을 그대로 따릅니다.
- 설정의 `[browser] enabled = false`로 도구 연결을 끌 수 있습니다.

### 브라우저 엔진: 내장 웹뷰와 Chrome

기본 엔진(`webview`)은 사이드바의 사이트 항목이며 Windows의 WebView2로, Edge와 같은 Chromium이며 Windows가 알아서 최신으로 갱신합니다.
다만 WebView2는 Windows에만 있고, macOS의 웹뷰는 Chromium이 아니어서 같은 방법으로 조작할 수 없습니다.
그래서 다른 OS에서도 쓸 수 있는 두 번째 엔진을 두었습니다.

```toml
[browser]
engine = "chrome"      # 설치된 Chrome → Edge → Chromium → Brave 순으로 찾아 띄움
# chrome_path = ""     # 다른 실행 파일을 쓰려면 경로를 적음
```

- 설치된 브라우저를 Cypher 전용 프로필로 띄웁니다. 평소 쓰는 프로필과 로그인은 건드리지 않으며, 이 프로필의 로그인은 다음 실행에도 유지됩니다.
- **브라우저는 그룹마다 따로 뜹니다.** 프로필도 그룹마다 따로라(`%LOCALAPPDATA%\cypher\chrome-profiles\<프로필 번호>`) 로그인 상태가 그룹끼리 섞이지 않습니다. 그룹이 없는 항목을 보고 있을 때 연 Chrome은 `%LOCALAPPDATA%\cypher\chrome-profile`을 쓰며, Claude 세션은 그것을 조작할 수 없습니다.
- 브라우저가 스스로 갱신하므로 늘 최신 Chromium이고, Cypher 배포 파일은 커지지 않습니다.
- 디버깅 포트를 열지 않고 Cypher와 브라우저만 아는 파이프(`--remote-debugging-pipe`)로 통신합니다. Cypher를 끝내면 이 브라우저도 함께 끝납니다.
- Claude가 쓰는 도구(`browser_read` 등)는 두 엔진에서 똑같이 동작합니다. 이 엔진에서는 그 세션의 그룹이 쓰는 Chrome 창에서 사용자가 보고 있는 탭을 조작합니다(그룹 없는 세션은 조작할 수 없습니다).
- 이 엔진을 고르면 사이드바 아래에 "Chrome"(열기)·"넘기기"·"캡처" 단추가 생깁니다. 세 단추는 지금 보고 있는 항목의 그룹이 쓰는 Chrome에 듣고, "넘기기"는 그 그룹의 Claude 세션에 넘깁니다. 처음 여는 주소는 빈 페이지입니다(`[browser] home`으로 바꿈).
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)은 Tauri 3이 아직 알파 단계이고 배포 파일이 수백 MB 늘어 쓰지 않았습니다.
- 파이프를 넘기는 부분만 OS별로 다릅니다(`crates/cypher-app/src/chrome.rs`의 `spawn`). 지금은 Windows용만 구현돼 있습니다.

### Chromium 버전 올리기

Cypher는 Chromium을 실행 파일에 싣지 않습니다. 그래서 엔진 버전은 Cypher 버전과 무관하게, 바깥의 브라우저가 갱신될 때 함께 올라갑니다.
Cypher를 새로 빌드하거나 배포할 필요가 없습니다.

| 엔진 | 누가 갱신하나 | 직접 갱신하려면 |
|---|---|---|
| `webview` | WebView2 런타임. Edge와 함께 Windows가 자동으로 갱신 | Edge에서 `edge://settings/help`, 또는 Microsoft의 "WebView2 런타임(Evergreen)" 설치 프로그램 실행 후 Cypher 다시 시작 |
| `chrome` | 설치된 Chrome·Edge의 자동 업데이트 | 그 브라우저에서 `chrome://settings/help`(Edge는 `edge://settings/help`) 후 Cypher용 브라우저 창을 닫았다 다시 열기 |

갱신이 멈춰 있지 않은지는 직접 확인할 수 있습니다.

- 도움말 → "브라우저 엔진 정보·업데이트 확인" 창에서 지금 엔진의 Chromium 버전을 볼 수 있습니다. 그 창의 "최신 버전 확인"을 누르면 Chrome 최신 안정판과 비교해 몇 단계 뒤처졌는지와 갱신 방법을 알려 줍니다.
- Cypher가 스스로 버전을 확인하러 나가지는 않습니다. 단추를 눌렀을 때만 Google이 공개하는 Chrome for Testing 목록(`googlechromelabs.github.io`)에서 버전 번호를 읽고, 이때 보내는 정보는 없습니다.
- 회사 정책 등으로 자동 업데이트가 꺼진 PC라면, `chrome_path`에 직접 관리하는 Chromium 실행 파일을 지정해 그 파일만 교체하는 방법도 있습니다.

Cypher 쪽에서 따로 챙길 것은 두 가지입니다.

- 조작에 쓰는 개발자 도구 프로토콜(CDP) 명령은 오래 유지돼 온 안정된 것만 씁니다(`Runtime.evaluate`, `Page.navigate`, `Page.captureScreenshot`, `Input.*`, `Target.*`). Chromium이 올라가 동작이 달라졌는지는 `cargo test -p cypher chrome -- --ignored`(설치된 브라우저를 실제로 띄워 파이프로 조작해 보는 시험)로 확인합니다.
- 앱 창 안에 Chromium을 통째로 넣는 방식(CEF)으로 바꾸면 그때부터는 Chromium 버전이 Cypher 빌드에 고정되므로, 보안 갱신을 따라가려면 약 4주마다 Cypher를 다시 빌드·배포해야 합니다. 지금 구조를 택한 까닭 중 하나입니다.

## HTTP 요청 파일

사이드바의 "+ HTTP"(Ctrl+Shift+H)나 묶음 머리의 +로 HTTP 항목을 만듭니다. 항목은 만들 때 보고 있던 항목의 폴더를 따릅니다.
그 폴더의 `.cypher\http\`, `http\`, 또는 폴더 바로 아래의 `*.http`를 읽습니다.

```
@host = https://api.example.com

### 로그인
POST {{host}}/login
Content-Type: application/json

{"id": "kim"}
```

실행하면 요청 파일 옆 `history.http`에 요청과 응답이 덧붙습니다(인증 헤더 값과 환경 변수에서 읽은 값은 `***`로 가림).
기록 파일은 저장소에 올라가지 않게 해 둡니다: git 저장소 안이면 그 저장소의 `info/exclude`(이 컴퓨터에만 있는 무시 목록)에 올리고 `.gitignore`는 건드리지 않습니다. 저장소가 아닌 폴더면 `.gitignore`가 없을 때만 만들어 둡니다.

- 요청 줄은 `http://`·`https://` 주소나 `{{변수}}`로 시작해야 합니다. 요청 줄 왼쪽의 ▶나 Ctrl+Enter는 커서가 있는 그 요청만 보냅니다.
  주소를 채우지 못했거나(변수 오타 등) 요청이 아닌 줄에서는 다른 요청을 대신 보내지 않고 까닭을 알려 줍니다.
  파일 머리말(첫 `###` 앞의 빈 줄·주석·변수)에서 실행하면 바로 아래의 첫 요청을 보내고, 마지막 요청 아래의 빈 줄에서는 그 마지막 요청을 보냅니다. 보내는 중인 요청을 다시 눌러도 두 번 보내지 않습니다.
- 고친 내용은 고치는 동안에도 1.5초 안쪽 간격으로 자동 저장됩니다(파일의 줄 끝 형식은 그대로 둡니다). 저장하지 못하면 항목을 닫거나 다른 파일로 옮기기 전에 알려 줍니다.
- 파일이 다른 곳(Claude 세션, 다른 HTTP 항목, 외부 편집기)에서 바뀌면, 편집기에 고친 내용이 없을 때 다시 읽습니다. 고치던 중이었다면 저장하지 않고 "다시 읽기 / 덮어쓰기"를 묻습니다(말없이 덮어쓰지 않습니다).
- 읽지 못한 파일(다른 프로그램이 잠근 파일 등)은 편집기를 잠가 덮어쓰지 않습니다. 열어 둔 파일이 바깥에서 지워졌으면 저장할 때 다시 만듭니다. BOM이 붙은 요청 파일도 읽습니다.
- 리다이렉트를 따라갔으면 응답과 기록에 `→ 최종 주소`를 적습니다. 같은 이름의 응답 헤더(`Set-Cookie` 등)는 값마다 한 줄씩 보여 줍니다. 5MB를 넘는 응답은 앞부분만 받고 잘렸다고 알리며, 화면에 다 보이지 않는 긴 요청·응답에는 생략한 줄 수를 적습니다.
- 다른 도구의 틀 문법(`{{ $labels.instance }}`, `{{$json.name}}`처럼 점·괄호가 든 것)은 건드리지 않고 그대로 보냅니다.

### 내장 값과 서명(HMAC)

새 요청 파일의 기본 예시 맨 아래에 바로 보내 볼 수 있는 "서명(HMAC) 예시"가 들어 있습니다.

`{{이름}}`은 변수, `{{$이름 인자…}}`는 내장 값입니다. 인자는 변수 이름, `$내장값`, 또는 "따옴표 글"로 적습니다
(따옴표 안에서는 `{{…}}`를 다시 쓸 수 있습니다). 글자 그대로 쓰려면 반드시 따옴표로 감쌉니다. 따옴표 없는 이름은 변수로 보며, 그런 변수가 없으면 보내지 않고 알려 줍니다(변수 이름 오타가 그대로 키나 메시지로 쓰이지 않게).
값은 주소 → 본문 → 헤더 순으로 채워지므로 헤더의 서명에 주소와 본문을 쓸 수 있습니다.
`$host`·`$path`·`$query`·`$pathQuery`·`$url`은 실제로 전송되는 모양 그대로입니다(한글·공백은 퍼센트 인코딩, 기본 포트 생략).

| 적는 법 | 값 |
|---|---|
| `{{$timestamp}}` / `{{$timestampMs}}` | 지금 시각(Unix 초 / 밀리초). 한 요청 안에서는 같은 값 |
| `{{$isoTimestamp}}` / `{{$httpDate}}` | `2026-11-12T08:00:00Z` / `Thu, 12 Nov 2026 08:00:00 GMT` |
| `{{$uuid}}` / `{{$randomInt}}` | 무작위 UUID / 0~999. 같은 값을 여러 번 쓰려면 변수에 담습니다(변수는 요청마다 한 번만 계산) |
| `{{$method}}` `{{$url}}` `{{$host}}` `{{$path}}` `{{$query}}` `{{$pathQuery}}` `{{$body}}` | 이 요청의 부분들 |
| `{{$env 이름}}` | 환경 변수(비밀키를 파일에 적지 않으려 할 때) |
| `{{$base64 값}}` / `{{$base64url 값}}` | Base64로 바꾼 글 |
| `{{$hash 알고리즘 표기 값}}` | 해시 |
| `{{$hmac 알고리즘 표기 키 메시지}}` | HMAC 서명. 키가 16진수나 Base64 글이면 끝에 `key=hex` 또는 `key=base64` |

알고리즘은 `sha256`, `sha1`, `sha384`, `sha512`, `md5`, 표기는 `hex`, `hexupper`, `base64`, `base64url` 중 하나입니다.

```
@host = https://api.example.com
@secret = {{$env MY_API_SECRET}}
@nonce = {{$uuid}}
@message = {{$timestamp}}{{$method}}{{$pathQuery}}{{$body}}

### 주문 넣기
POST {{host}}/v1/orders?side=buy
Content-Type: application/json
X-Timestamp: {{$timestamp}}
X-Nonce: {{nonce}}
X-Body-SHA256: {{$hash sha256 hex $body}}
X-Signature: {{$hmac sha256 hex secret message}}

{"qty": 1}
```

값을 계산하지 못하면(모르는 알고리즘, 없는 환경 변수 등) 요청을 보내지 않고 까닭을 알려 줍니다.
보낸 요청 원문(서명이 채워진 헤더 포함)은 응답과 함께 화면에 나옵니다.
